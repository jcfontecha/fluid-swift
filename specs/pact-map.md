# pact-map (3.11.0)

## Role

Per-key proposal/acceptance consensus across the quorum present at proposal sequencing. Reads expose the last accepted value while a new proposal is pending. `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:104-155`, `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:214-267`.

## Wire and persisted formats

Ops in literal construction order:

```json
{"type":"set","key":"a","value":7,"refSeq":10}
{"type":"set","key":"a","refSeq":20}
{"type":"accept","key":"a"}
```

Type and key required strings; set.refSeq required number, captured lastSequenceNumber; set.value arbitrary T or undefined (undefined omitted, used for deletion). Accept has no proposal ID or refSeq; sender comes from envelope. No local metadata is generated by producer. `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:75-97`, `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:176-183`, `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:262-266`.

One `header` blob, plain JSON.stringify([...values.entries()]), no serializer or split. Each array pair [key,Pact], insertion order. Pact fields accepted then pending; undefined members omitted. Accepted fields value then sequenceNumber; pending fields value then expectedSignoffs (ordered string[]). Examples:

```json
[["a",{"pending":{"value":7,"expectedSignoffs":["c1","c2"]}}]]
[["a",{"accepted":{"value":6,"sequenceNumber":9},"pending":{"value":7,"expectedSignoffs":["c2"]}}]]
[["a",{"accepted":{"value":7,"sequenceNumber":12}}]]
[["a",{"accepted":{"sequenceNumber":21}}]]
```

Final example is accepted deletion; key remains in Map. Empty header `[]`. Load readAndParse then copies pairs into Map without handle decode, quorum filtering, automatic acceptance, or events. Summary uses plain JSON for user T, despite op handling passing through SharedObject's serializer; do not insert a handle-aware summary pass TS doesn't perform. `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:33-70`, `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:237-255`, `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:292-295`, `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:329-338`.

## Behavior

1. Set returns immediately if a sequenced pending proposal exists. Detached schedules queueMicrotask(handleIncomingSet(key,value,0,0)), no immediate mutation/event. Multiple synchronous detached sets can queue before any pending state exists; microtasks evaluate validity when run. Attached captures refSeq, submits, no optimistic mutation. Delete no-ops for absent key, pending proposal, or accepted undefined; otherwise set(key,undefined). `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:158-211`.
2. On sequenced set (local and remote identical), valid iff key absent OR no pending and accepted.sequenceNumber ≤ original refSeq. Invalid proposal silently ignored with no event/accept. Thus first concurrent proposal sequenced wins; later proposal created before accepted sequence remains stale even after prior acceptance. `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:214-229`, `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:371-388`.
3. Preserve previous accepted; obtain expectedSignoffs as current quorum keys in order if attached, [] otherwise. Store {accepted,pending:{value,expectedSignoffs}}, emit pending(key). If list empty immediately replace with {accepted:{value,sequenceNumber:setSequenceNumber},pending:undefined}, emit accepted(key). Otherwise if own clientId defined and in list, submit accept op **after** pending event. `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:209-267`.
4. On accept: absent pending → ignore. Otherwise assert sender in expectedSignoffs, filter sender out; if now empty replace accepted using pending value and **accept envelope sequenceNumber**, clear pending, emit accepted. An accepted value's sequence is final signoff, not proposal sequence. `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:270-298`, `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:392-398`.
5. removeMember traverses Map insertion order; for each pending filter departing ID; if empty accept at deltaManager.lastSequenceNumber (leave-processing sequence) and emit accepted(key). New members aren't added to existing expectedSignoffs. Disconnect no-op. `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:300-322`, `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:343`.
6. ReSubmit set is dropped when existing key has pending, or original refSeq < accepted?.sequenceNumber. Otherwise exact original op/metadata forwarded. Accept always forwarded, no new signoff generation on reconnect. Stash throws `not implemented`. No custom rollback: inherited unsupported rollback throws, not an acceptance inverse. Unknown applied operation throws Unknown operation; non-op envelope ignored. `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:345-410`, `reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/sharedObject.ts:669-670`.

## Invariants and asserts

`0x2f9`: accept sender must still be in expectedSignoffs when pending exists; duplicate accept while other signoffs remain throws rather than being idempotent. Accept after proposal already accepted is ignored. `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:275-296`.

## JS-semantics hazards

Detached microtasks are essential (no synchronous event shortcut). Missing value represents accepted deletion, not absent Pact. Summary plain JSON does not share op handle decode semantics; Map tuple representation safely retains `__proto__` keys. Expected-signoff array and Map order determine persisted bytes and acceptance-event order. Public event reentrancy occurs before subsequent automatic signoff submission. `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:158-183`, `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:237-267`, `reference/fluidframework-3.11.0/packages/dds/pact-map/src/pactMap.ts:300-338`.
