# Container-loader: serialized pending state

## 1. Role

SerializedStateManager records a base snapshot and all subsequently processed ops so a later container can restore runtime pending work at the original reference points. PendingLocalStateStore is an in-memory Map-like deduplicating collection of serialized attached states, not a second persistence format. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:170-183`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/pendingLocalStateStore.ts:44-50`.)

## 2. Surface used by other packages

`fetchSnapshot(specifiedVersion,pendingLocalState)`, `addProcessedOp`, `setInitialSnapshot`, `getPendingLocalState(clientId,runtime,resolvedUrl)`, dispose. Container delegates pending state only while open, attached and resolved to a Fluid URL; requires 0x0d1/0x0d2. Store exposes set/get/has/delete/clear/size/entries/keys/iteration. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:247-271`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:407-427`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:1187-1206`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/pendingLocalStateStore.ts:55-173`.)

## 3. Wire and persisted formats

### Attached state, exact producer order

SerializedStateManager JSON.stringify emits properties in this insertion order (undefined properties omitted):

| Field | Type / presence |
|---|---|
| attached | literal true, required |
| pendingRuntimeState | opaque runtime return; omitted when undefined, preserved when null |
| baseSnapshot | required ISnapshotTree |
| snapshotBlobs | required object mapping storage blob ID → UTF-8 decoded string (not base64) |
| loadedGroupIdSnapshots | optional object mapping group ID → `{baseSnapshot,snapshotBlobs,snapshotSequenceNumber}`; omitted if no groups |
| savedOps | required array of full sequenced envelopes, in processing order; proposal contents may already be object |
| url | required resolvedUrl.url string |
| clientId | optional string, last accepted container identity (retained on disconnect) |

No version field, no wrapper, and no pending-local-op list at loader level: local work lives inside pendingRuntimeState. IPendingContainerState additionally accepts `blobContentsMode?:"reference"` and `attachmentBlobContents?:{[storageId:string]:base64String}` from full-state capture, but the live manager does not emit them. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:73-122`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:447-482`.)

ISnapshotTree is `{id?:string,blobs:{[path:string]:storageId:string},trees:{[path:string]:ISnapshotTree},unreferenced?:true,groupId?:string}`; preserve original object's property order for restored trees. A newly converted summary tree creates properties `blobs,trees,id,unreferenced,groupId` in that order, with undefined last fields omitted; IDs are generated UUIDs. Traverse summary entries in property order, recursively produce child trees; blobs receive generated UUID IDs and string contents UTF-8 bytes (Uint8Array copied as bytes); attachment entries directly use their id; summary handles throw LoggingError `No handles should be there in summary in detached container!!`. (`reference/fluidframework-3.11.0/packages/common/driver-definitions/src/protocol/storage.ts:133-149`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/utils.ts:149-198`.)

Concrete emitted attached example: fixture snapshot has root `{blobs:{},trees:{".protocol":{blobs:{attributes:"a",quorumMembers:"m",quorumProposals:"p",quorumValues:"v"},trees:{}}}}`, runtime returns `{pendingStates:[]}`, no processed ops/groups, resolved URL `fluid://host/tenant/doc`, undefined clientId. Exact JSON string content is:

```json
{"attached":true,"pendingRuntimeState":{"pendingStates":[]},"baseSnapshot":{"blobs":{},"trees":{".protocol":{"blobs":{"attributes":"a","quorumMembers":"m","quorumProposals":"p","quorumValues":"v"},"trees":{}}}},"snapshotBlobs":{"a":"{\"minimumSequenceNumber\":0,\"sequenceNumber\":0}","m":"[]","p":"[]","v":"[]"},"savedOps":[],"url":"fluid://host/tenant/doc"}
```

The runtime object here is an opaque fixture return, not a new loader-defined runtime schema. Base tree/blob map are direct fixture inputs to the producer; the producer inserts the outer fields in the order shown. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:463-482`.)

Full capture producer order differs: `attached,baseSnapshot,snapshotBlobs,blobContentsMode,attachmentBlobContents,loadedGroupIdSnapshots,pendingRuntimeState,savedOps,url`. Undefined groups/runtime always omitted; empty attachment map omitted; reference marker omitted for inline capture. Example reference-state outer content with empty tree fixture: `{"attached":true,"baseSnapshot":{"blobs":{},"trees":{}},"snapshotBlobs":{},"blobContentsMode":"reference","savedOps":[],"url":"fluid://host/tenant/doc"}`. It requires online driver wiring; offline frozen load explicitly rejects reference-only state. Inline attachment example field `"attachmentBlobContents":{"binary-id":"AP8="}` represents bytes 00 ff, not UTF-8 text. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/createAndLoadContainerUtils.ts:738-750`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/createAndLoadContainerUtils.ts:424-433`.)

### Detached state and legacy reads

`serialize()` rejects Attached or closed containers with UsageError `Container must not be attached or closed.`. If already Attaching, reuse attachingData.summary rather than regenerating it; otherwise call runtime.createSummary() first and captureProtocolSummary second, then combine. Convert the combined summary to snapshot before requesting pending runtime state. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:1219-1237`.)

Container.serialize emits `attached:false,baseSnapshot,snapshotBlobs,pendingRuntimeState?,hasAttachmentBlobs:boolean,attachmentBlobs?:string` in this order. Only attaching state requests runtime.getPendingLocalState; it must be synchronous (0x8e3). Detached state omits pendingRuntimeState. hasAttachmentBlobs reflects detachedBlobStorage exists and size>0. attachmentBlobs is itself a **JSON string encoding an array of UTF-8 decoded blob strings**, not base64. For bytes of `hello`, field is `"attachmentBlobs":"[\"hello\"]"`. The legacy detached memory format is text-based even though the newer attached attachmentBlobContents format is binary-safe. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:1219-1247`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/memoryBlobStorage.ts:56-74`.)

Detached parser accepts current shape if attached/baseSnapshot/snapshotBlobs/hasAttachmentBlobs are non-undefined (does not validate attached===false). Also accepts legacy combined summary `{type:1,tree:{".protocol":protocolSummary,".app":appSummary,".hasAttachmentBlobs"?:marker}}`; converts it to snapshot, sets attached=false and hasAttachmentBlobs by presence of `.hasAttachmentBlobs` tree entry. Otherwise UsageError `Cannot rehydrate detached container. Incorrect format`. Attached parser is only JSON.parse (undefined input→undefined), without shape validation or a version migration. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/utils.ts:333-345`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/utils.ts:367-405`.)

## 4. Behavior

### Fetch/restore order

fetchSnapshot, setInitialSnapshot and getPendingLocalState call verifyNotDisposed first; these methods after dispose throw `SerializedStateManager used after dispose.`. Without pending: getSnapshot API path if supported else getSnapshotTree path; assert snapshot exists 0x8e4; get tree; read attributes; if offline enabled start refresh timer, record snapshot and attributes SN (no fetched time on this initial network path); return snapshot/version/attributes. New API calls getSnapshot({versionId:specifiedVersion}) and derives `{id,treeId}` from snapshotTree.id when present. Old API calls getVersions(specifiedVersion??null,1), chooses first (possibly undefined), calls getSnapshotTree(version). Missing requested versions produce telemetry; undefined snapshot ultimately asserts. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:229-233`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:264-289`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:563-650`.)

With pending: decode snapshotBlobs values UTF-8 into ordered blob map; decode attachmentBlobContents base64 **afterwards**, overwriting colliding structural IDs; cache blobs; read attributes from baseSnapshot. Construct internal snapshot in order `{sequenceNumber:attributes.SN,snapshotTree:baseSnapshot,blobContents,latestSequenceNumber:undefined,ops:[],snapshotFormatV:1}`. If offline enabled set lastSavedOpSequenceNumber to final savedOps SN if nonempty, record snapshotInfo, trigger refresh without waiting. Return version undefined. Group snapshots are supplied to storage adapter by container constructor, separately from base blob cache. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:291-335`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:990-1008`.)

### Snapshot promotion and saving

addProcessedOp when offline disabled does nothing; enabled pushes the exact message object, then attempts snapshot promotion. Constructor listens to pending-op `saved` event for the same promotion attempt, not aggregate dirty-state saved. A refreshed candidate becomes latestSnapshot then invokes promotion. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:194-219`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:247-250`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:343-345`.)

Promotion returns -1 if disposed OR no candidate SN OR processedOps empty OR final processed SN<lastSavedOpSequenceNumber OR hasPendingOps. Otherwise: if candidateSN<firstProcessedSN, log old snapshot, discard candidate, clear refresher's candidate and restart timer. Else if candidateSN<=lastProcessedSN, remove exactly candidateSN-firstProcessedSN+1 leading ops, replace snapshotInfo, discard candidate, clear refresher candidate, restart timer, log SnapshotRefreshed. Else retain candidate for future processed ops. Both evaluated branches and the future-candidate branch return candidate SN; only guard returns -1. Pending operation safety, not aggregate dirty, controls promotion. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:351-398`.)

setInitialSnapshot checks not disposed; offline enabled records snapshot, sequenceNumber??0 and snapshotFetchedTime=Date.now(), then starts refresh timer. getPendingLocalState checks not disposed and offline enabled else UsageError `Can't get pending local state unless offline load is enabled`; asserts snapshotInfo 0x8e5; awaits runtime.getPendingLocalState({notifyImminentClosure:false,snapshotSequenceNumber:baseSN,sessionExpiryTimerStarted:snapshotFetchedTime}); converts each loaded group to text blob snapshot info; converts base snapshot map or recursively reads tree blobs; constructs state in exact order above; JSON.stringify. No automatic close, disconnect, or imminent-closure notification occurs. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:407-482`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/utils.ts:209-222`.)

Refresh scheduling is separately gated: `offlineLoadEnabled && (Fluid.Container.enableOfflineSnapshotRefresh ?? false)`; default refresh is **off**, even though default interactive offline serialization is on. Timeout is constructor argument ?? 86400000ms. tryRefreshSnapshot starts only if enabled, not disposed, no in-flight refresh, no retained candidate. After fetching latest base snapshot and checking disposal, if getSnapshot API is enabled and loaded group IDs are nonempty, require getSnapshot (0x972), await getSnapshot({versionId:undefined,scenarioName:"getLatestSnapshotInfo",cacheSnapshot:false,loadingGroupIds:Object.keys(loadedGroupIdSnapshots),fetchSource:FetchSource.noCache}), require result (0x973); adapter updates group cache. Notify manager only when base candidate exists, then restart timer. Disposing clears the timer but does not cancel already executing I/O. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/snapshotRefresher.ts:79-160`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/snapshotRefresher.ts:196-198`.)

### PendingLocalStateStore

set parses attached state, normalizes comparison URLs by removing **one** final slash, initializes firstUrl using ??=, rejects differing normalized URL with UsageError `PendingLocalStateStore can only be used with a single container.`. In order: replace savedOps entries with first-seen object by sequenceNumber; replace snapshotBlobs values with first-seen string by ID; same for optional attachmentBlobContents in a **separate** cache; then for each loaded group, if no cache OR incoming.snapshotSequenceNumber<cached.snapshotSequenceNumber, assign incoming to cache and state. Equal/newer incoming group is left as its own object (not replaced by cached earlier object). Finally Map.set(key,state). No content-equality checks for same op sequence/blob ID; first-seen payload wins. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/pendingLocalStateStore.ts:95-131`.)

get returns JSON.stringify(Map.get(key)); missing returns undefined. Iterators yield states stringified at iteration time, in Map order; replacing an existing key retains position. delete/clear remove only stored states; **do not** reset first URL, op cache, either blob cache, or group cache. A clear store cannot switch documents. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/pendingLocalStateStore.ts:44-76`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/pendingLocalStateStore.ts:137-173`.)

### Snapshot byte conversion and historical reads

For ISnapshot input, snapshotBlobs is built by iterating blobContents Map and UTF-8 decoding every value, including unreferenced entries not reachable from the tree. For tree-only input, start recursive child-tree reads in Object.entries order; root `.blobs` is special: fetch **only** its `.redirectTable` blob (missing ID asserts 0x9ce), not attachments or descendants. Then await own blob reads sequentially in Object.values order before awaiting Promise.all(child reads). Non-root trees named `.blobs` are ordinary recursion. Insertion into the shared snapshotBlobs object follows read-completion order across child branches; integer-index IDs still serialize before other keys. Outer persisted object order remains baseSnapshot then snapshotBlobs. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/containerStorageAdapter.ts:328-383`.) Group conversion requires snapshot.sequenceNumber defined (0x93a) and produces `{baseSnapshot,snapshotBlobs,snapshotSequenceNumber}`. This is not a summary tree and has no `type` fields. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/utils.ts:209-222`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/utils.ts:351-359`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:488-496`.)

A concrete detached producer example, given a converted snapshot fixture `{blobs:{},trees:{},id:"tree-1"}`, no pending runtime state and detached storage containing UTF-8 `hello`, is:

```json
{"attached":false,"baseSnapshot":{"blobs":{},"trees":{},"id":"tree-1"},"snapshotBlobs":{},"hasAttachmentBlobs":true,"attachmentBlobs":"[\"hello\"]"}
```

The tree ID is a fixed fixture stand-in for convertSummaryToISnapshot's UUID. `hasAttachmentBlobs` is not inferred during parse; on rehydrate a true flag requires nonempty storage after optional initialization. Array position determines decimal attachment ID (`"0"` here), so sorting blob contents would change handles. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:1219-1247`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:1829-1850`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/memoryBlobStorage.ts:37-74`.)

Latest refresh fetch explicitly requests getVersions(null,1,"getLatestSnapshotInfo",FetchSource.noCache), fetches that first version's ID using the same new/old snapshot API selection, takes ISnapshot.sequenceNumber if non-nullish or reads attributes otherwise, and returns `{snapshot,snapshotSequenceNumber,snapshotFetchedTime:Date.now()}`. Any exception is logged/cancels the performance event and returns undefined rather than closing the container. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:507-550`.)

## 6. JS-semantics hazards

Do not use Codable defaults to turn absent pendingRuntimeState into null or flatten double-encoded attachmentBlobs. snapshotBlobs is lossy for arbitrary invalid UTF-8; binary-safe attachmentBlobContents intentionally uses base64 and wins ID collisions. Store intern caches are ordinary `{}` objects, not Maps or null-prototype dictionaries: `cache[id] ??= value` includes inherited properties. For example an ID `"constructor"` finds the inherited non-null function instead of storing the supplied blob string, and JSON.stringify then omits that function-valued blob property. A Swift dictionary silently changes this edge behavior. Store numeric sequence keys are JS object integer keys, while savedOps is an ordered array; do not serialize the intern cache instead. Awaiting runtime state happens before reading/converting snapshotInfo later, so serial executor must preserve JS async boundaries rather than freezing an earlier independent copy. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:94-105`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:291-307`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/serializedStateManager.ts:447-480`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/pendingLocalStateStore.ts:108-127`.)
