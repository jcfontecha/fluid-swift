# Container-loader: connections

## 1. Role

Transport connected is not container Connected. ConnectionManager owns socket/retry/permissions and outbound delivery; ConnectionStateHandler holds the new client ID until membership and previous-client safety gates pass; ConnectionStateCatchup additionally holds the externally visible Connected transition until known ops are applied. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:140-199`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:245-329`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:332-359`.)

## 2. Surface used by other packages

State raw values are Disconnected=0, CatchingUp=1, Connected=2, EstablishingConnection=3, **not ordinal progression**. pendingClientId is socket identity, cleared after disconnect callback; clientId is last accepted identity, retained across disconnect. Manager exposes connected, mode, details, readonly info, pending ops and dirty write desire. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionState.ts:10-33`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:76-103`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:210-256`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:274-339`.)

## 3. Wire and persisted formats

New socket request calls connectToDeltaStream({...client,mode:requestedMode}), overriding original client's mode at its existing property position. Successful connection supplies claims.scopes, mode, clientId, initialMessages, initialClients?, initialSignals?, checkpointSequenceNumber?, serviceConfiguration and version. Initial messages are sequenced envelopes; initialClients are ISignalClient records, converted to JSON clear/join signals as specified in protocol chapter. No state-machine enum is sent to the service. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:581-586`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:832-983`.)

Nack handler uses only `messages[0].content`; consumed fields: `type:string,message:string,code:number,retryAfter?:number` (seconds). Message is `Nack (TYPE): MESSAGE`; retry allowed iff code!=403; retryAfter becomes milliseconds by *1000. retryable+retryAfter defined creates ThrottlingError (`errorType="throttlingError",canRetry=true,retryAfterSeconds=retryAfter`); otherwise GenericNetworkError (`errorType="genericNetworkError",canRetry=code!==403`). Both include statusCode=code and driverVersion=undefined. E.g. content `{"code":429,"type":"ThrottlingError","message":"busy","retryAfter":2}` yields retryable ThrottlingError and a 2000ms reconnect wait. Permission-readonly nack bypasses conversion and closes with createWriteError("writeOnReadOnlyDocument"), a NonRetryableError with `errorType="writeError",canRetry=false`. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:80-91`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:1230-1247`, `reference/fluidframework-3.11.0/packages/loader/driver-utils/src/network.ts:209-249`.)

## 4. Behavior

### Transport state machine

Represent transport state as no connection/no attempt; pending attempt; connected; disposed. ReconnectMode is Enabled/Disabled/Never. Constructor stores defaultReconnectionMode=client.mode and sets Enabled if reconnectAllowed else Never. Outbound queue initially paused. shouldJoinWrite = outstandingOps OR aggregate containerDirty; hasPendingOps = outstandingOps OR containerOpDirty; outstandingOps = observedCSN < generatedCSN-localOpsToIgnore. Aggregate dirty non-op work does not require waiting for the old client. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:274-306`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:370-385`.)

**connectCore execution:**

1. Assert not disposed 0x26a; requestedMode=argument??default. If shouldJoinWrite force write. If a connection/attempt exists, log mismatched modes if needed and return (do not replace it).
2. Require doc service 0x2a7; invoke establishConnectionHandler. storageOnly policy creates FrozenDeltaStream and sets up read directly; assert no pending attempt 0x2b3.
3. Set delay=500ms, attempt count=0, abort controller and pendingConnection{abort,connectionMode}. Until a live connection: disposed throws; aborted returns; increment attempt; assign client.mode; await stream connection. A returned disposed connection is dropped and loop retries.
4. Catch: deltaStreamConnectionForbidden → FrozenDeltaStream with storageOnlyReason and readonly reason, requestedMode=read, break. outOfStorageError → FrozenDeltaStream with readonly reason, requestedMode=read, break. Nonretryable (`canRetry!==true`) → normalize with fatal-connect props, closeHandler, throw. If maxInitialConnectionAttempts reached, same close/throw. If reconnect not Enabled, return. Else compute wait as below, emit reconnectionDelayHandler only for explicit retry delay, sleep, wait for online if strongly offline, retry.
5. After success, aborted/disposed disposes new connection and returns. Clear maxInitialConnectionAttempts (only initial connection capped); setupNewSuccessfulConnection.

(`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:498-735`.)

Retry delay uses max(error retry delay or 0, previousDelay*2), then capped to 60000ms iff isFluidError(error) and error.getTelemetryProperties().endpointReached===true, otherwise 8000ms (even an explicit retry delay above the cap is capped); when explicitly offline and no retry delay, skip recalculation but still wait previous delay. waitForOnline waits only if navigator.onLine===false and global addEventListener exists; otherwise resolves. Initial delay is 500ms, hence normal first retry is 1000ms. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:74-75`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:94-105`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:670-693`, `reference/fluidframework-3.11.0/packages/loader/driver-utils/src/runWithRetry.ts:180-202`.)

**Successful setup order:** assert no old connection (0x0e6) and new not disposed (0x28a); clear pendingConnection; capture old readonly; assign connection. Permission readonly = !claims.scopes.includes(DocWrite); require readonly permission implies read mode (0x0e8); assign permissions and emit readonly change only if effective value changed. If callback disposed manager, disconnect and return. Resume outbound, install op/signal/nack/disconnect/error/pong listeners. Sort initialMessages numeric SN; checkpoint=max(server checkpoint,last initial SN) when initial nonempty. Feed initial ops first with reason InitialOps/ReconnectOps, then store connectionDetails with adjusted checkpoint, call connectHandler, mark first=false. Finally enqueue signals: synthetic clear, synthetic joins in initialClients order, then initialSignals (after shape assertions). Ops and signals use separate queues: this does not promise cross-queue sequence ordering beyond enqueue order. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:832-983`.)

**Disconnect order:** reset pendingReconnect=false. If no active connection but pending exists, abort it, clear pending, emit cancelConnectionHandler with text `Cancel Pending Connection due to REASON`; return true. With active connection require no pending 0x27b; save socket, clear connection and details **before callbacks**; remove all six listeners; pause outbound (without awaiting), clear outbound, dispose socket, call disconnectHandler, clear verbose props, return true. No connection/attempt returns false. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:766-824`.)

**Reconnect order:** require active connection 0x0eb; disconnect first. A live socket error with canRetry=false still attempts reconnect (unlike fatal nack or initial nonretryable connect). Never mode calls closeHandler() without error; disposed/non-Enabled returns. Honor explicit retry delay and notification, await online, then trigger connect iff still Enabled, with requested mode and reason. Nack retries always request write; socket disconnect/error requests original defaultReconnectionMode (shouldJoinWrite may override). (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:993-1065`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:1230-1258`.)

setAutoReconnect forbids argument Never and current Never (0x278); sets mode; any not Enabled disconnects immediately; enabling alone does not start a connection. dispose idempotently sets disposed, Never, clears outbound, disconnects, then optionally sets readonlyPermissions=true with prior effective readonly for event comparison. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:388-431`.)

### Readonly and read/write submission

Effective readonly is true if FrozenDeltaStream storage-only, forced flag, or permissions===true; return `{readonly:true,forced,permissions,storageOnly,storageOnlyReason}` in that order (undefined omitted in JSON). Otherwise `{readonly:permissions}`; permissions can be undefined until first connection. Read connection mode alone does **not** mean readonly: it may upgrade to write. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:318-339`.)

forceReadonly stores flag before checking effective change. If effective unchanged: no notification/reconnect. Changed with Never throws UsageError after assignment. Switching effective true disconnects first, logging pending writes if any; then readonlyChangeHandler(new); reconnect as read only if it actually disconnected/cancelled something and auto-reconnect Enabled. Switching false emits change but does not proactively reconnect. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:437-487`.)

prepareMessageToSend: effective true asserts 0x1f0, closes GenericError `deltaManagerReadonlySubmit`, returns undefined. Else require socket 0x0e4; if lastSubmittedClientId differs, set it and reset generated/observed CSN=0. Runtime op resets localOpsToIgnore=0, any other type increments it. Return spread message with ++generatedCSN appended. sendMessages requires connected 0x2b4: WritableFrozenDeltaStream drops transport batch (runtime pending state retains it); read-mode connection schedules a single promise-microtask reconnect(write), guarded by pendingReconnect, then returns without queueing. Write mode requires !pendingReconnect 0x2b5 and pushes batch to outbound. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:1068-1164`.)

Before incoming-op processing assert current socket identity is not sender OR lastSubmittedClientId==sender (0x0ee). For lastSubmitted sender require observedCSN<incomingCSN (0x0ef) and incomingCSN<=generatedCSN (0x0f0), then set observed. Parse leave data; if leaving ID equals socket ID, begin reconnect(read) immediately, before protocol removes member. This intentionally makes an idle expired writer acquire a new read socket. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:1167-1211`.)

Signals bypass outbound op batching and op-write eligibility: submitSignal without a socket logs `submitSignalDisconnected` and drops it; with a socket it calls driver.submitSignal(content,targetClientId) immediately. Incoming op and signal callbacks accept a single item or an array; both normalize to arrays, but only signals undergo shape validation (`"type" in signal` throws Error `Unexpected type in ISignalMessage`; non-string content throws TypeError `Non-string content in ISignalMessage`). (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:122-132`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:1109-1115`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:1215-1227`.)

Other transport getters: maxMessageSize=connection.serviceConfiguration?.maxMessageSize ?? 16384; version without connection throws `Cannot check version without a connection`; serviceConfiguration and scopes return undefined without a socket. The size is a reported limit, not an additional DeltaManager batching/splitting algorithm. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:237-254`.)

### Membership connection state machine

Defaults: Disconnected, pending undefined, accepted clientId from paused session if supplied. Previous-client leave timer=host override??300000ms. Join-op timer=45000ms for write; join-signal timer=10000ms for read. `Fluid.Container.DisableJoinSignalWait!==true` selects membership=audience and makes read wait for self; otherwise membership=quorum and reads skip self-wait. Writes always wait. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:24-30`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:106-134`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:399-450`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:587-592`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:726-731`.)

| Trigger | Predicate | Execution-ordered state/effects |
|---|---|---|
| establishingConnection | caller starting attempt | save old; assign EstablishingConnection; callback(new,old,{text:`Establishing Connection due to REASON`,error}) |
| cancelEstablishingConnection | state EstablishingConnection and no connection (0x6d3/0x6d4) | save old; assign Disconnected; callback; no normal disconnect timer logic |
| receivedConnectEvent | socket details available | assign connection; save old; state=CatchingUp; pending=details.clientId; callback CatchingUp first; if !hasMember(pending) && shouldWaitForSelf start join timer; else if !leaveTimer set Connected |
| matching addMember | id==pending | stop join timer if running (or recovery telemetry if it already expired); start wait telemetry if leaveTimer running; applyForConnected |
| matching removeMember | id==accepted && leaveTimer running | clear leaveTimer; applyForConnected |
| pendingOpsSaved | leaveTimer running | clear timer; applyForConnected (aggregate dirty is irrelevant) |
| leave timeout | state!=Connected (0x2ac) | applyForConnected; timer no longer running |
| join timeout | state CatchingUp only | log NoJoinOp/NoJoinSignal; does not waive join requirement |
| disconnect | any changed state | clear connection first; normal Disconnected transition below |

(`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:407-440`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:467-580`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:603-644`.)

applyForConnected requires installed protocol 0x236 and (!leaveTimer OR hasMember(accepted)) 0x2e2. Exact acceptance predicate: pending!=accepted AND hasMember(pending) AND !leaveTimer. If true finish wait telemetry then set Connected; otherwise only telemetry. `setConnectionState` same-state logs and returns. For real transition assign new state first; compute old accepted ID's quorum presence. Connected requires old CatchingUp (0x1d8); if old accepted still in quorum flag shouldHaveLeft; then accepted=pending; callback. Disconnected stops join timer; starts/restarts leave timer **only** if old accepted in quorum AND hasPendingOps AND no leave timer already active (existing timer is not extended); callback before clearing pending ID. Accepted ID remains. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:507-554`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:647-723`.)

initProtocol assigns protocol, installs selected membership listeners. Add requires read-mode client OR corresponding quorum member (0x4b5); remove requires absent quorum member (0x4b6). Then if pending already member, run add handling. Assert no leave timer 0x99d. Finally, if restored accepted ID exists in quorum, restart leave timer **without** checking hasPendingOps. dispose asserts no join timer 0x2a5 and clears leave timer; it does not remove installed membership listeners. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:733-790`.)

At container layer, read NoJoinSignal error after loaded triggers disconnectInternal then connectInternal without storage fetch. A write NoJoinOp only logs, leaving op fetch/join recovery running. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:943-956`.)

### Catch-up adapter and event propagation

`Fluid.Container.DisableCatchUpBeforeDeclaringConnected!==true` enables adapter. Adapter externally mirrors Disconnected/EstablishingConnection/CatchingUp, asserting Establishing from Disconnected 0x6d2 and CatchingUp from Establishing 0x3e3. Base Connected requires external CatchingUp 0x3e1 and no monitor 0x3eb; create **and assign** CatchUpMonitor then start it, return without publishing Connected yet. Monitor target is current lastKnownSeqNumber at this moment. Callback requires base Connected 0x3e5 and external CatchingUp 0x3e6; assign external Connected then callback Connected,CatchingUp,{text:"caught up"}. On Disconnected dispose/clear monitor before forwarding. Monitor remains after success until disconnect. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:245-329`.)

Container on external state change logs first, propagates only while loaded: on Connected set protocol audience self then signalAudience self; on CatchingUp set signalAudience self to pending only. Update runtime connection status next; only Connected/Disconnected then call protocol.setConnectionState (internal proposal connected/disconnected events) and host connected/disconnected event. Modern runtime receives every state, canSendOps=true iff Connected&&!readonly, accepted ID when connected, pending ID when catching up, prior pending/accepted IDs when disconnected. Older runtime receives bool+accepted ID only at Connected/Disconnected during transitions. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:901-909`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:2211-2250`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:2570-2644`.)

### Runtime connection callback shapes

These are synchronous in-process objects, not service wire messages. Modern runtime `setConnectionStatus` receives the following properties in producer order; `readonly` is supplied as `readOnlyInfo.readonly ?? false` on state propagation, but the readonly-change listener passes its boolean/undefined event value directly. The callback is skipped unless runtime.disposed===false and container.loaded. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:2114-2118`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:2227-2230`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:2570-2649`.)

| State | Object literal (IDs are strings or undefined as indicated) |
|---|---|
| EstablishingConnection | `{connectionState:3,canSendOps:false,readonly}` |
| CatchingUp | `{connectionState:1,pendingClientConnectionId:pending,canSendOps:false,readonly}`; pending required |
| Connected | `{connectionState:2,clientConnectionId:accepted,canSendOps:!readonly,readonly}`; accepted required and equals pending |
| Disconnected | `{connectionState:0,priorPendingClientConnectionId:pending,priorConnectedClientConnectionId:accepted,canSendOps:false,readonly}`; either ID may be undefined |

Legacy runtime receives `setConnectionState(state===Connected && !readonly,acceptedId)`; state transitions limit it to Connected/Disconnected, but a readonly event calls it regardless of current state. No socket mode test is added here: a read-mode socket with write permission can be Connected/canSendOps and a subsequent op triggers the write upgrade. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:2574-2587`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:1144-1159`.)

The catch-up adapter delegates identity getters to the base handler. Thus base acceptance sets `clientId=pending` while externally exposed connectionState can still be CatchingUp. Catch-up gates runtime/host Connected publication, not the base identity assignment. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:167-175`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:268-291`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:671-681`.)

## 5. Invariants and asserts

Timer guards: start join requires no timer 0x234 and connection exists 0x4b3; stop requires timer 0x235; shouldWaitForSelf requires connection 0x4b4. Pending-attempt cancellation first asserts pendingConnection is defined (0x345), calls abort(), clears pendingConnection, logs cancellation, then calls cancelConnectionHandler. Commented-out 0x239 (no existing connection before triggerConnect), 0x30a (pending ops imply write) and 0x2a6 (leave wait implies write) are **not active asserts** and must not be enforced. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:747-755`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:807-815`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:609-616`.) All remaining state/transport asserts are given with exact predicates in transitions above. Membership must not promote a write client from its join **signal**; the read-filtered audience enforces this. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:445-455`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:587-592`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:736-753`.)

## 6. JS-semantics hazards

Readonly callbacks can close/dispose during successful setup; preserve the post-callback disposed check. Pending IDs are cleared after disconnect callbacks so runtime/telemetry can read them. Catch-up start can synchronously publish Connected, whose listener can force readonly/disconnect; assign monitor before start so reentrant cleanup sees it. Read-to-write reconnect uses a microtask to avoid disconnect during the originating runtime submit. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:870-884`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:715-723`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:279-290`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionManager.ts:1144-1157`.)
