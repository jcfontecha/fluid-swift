# presence, presence-definitions and presence-runtime

## 1. Role

Presence is ephemeral, signal-only per-container session state, not a DDS and not persisted in summaries. The public facade gets a singleton container extension; definitions supply attendee/workspace/value-manager interfaces; runtime implements session mapping, replicated in-memory state, batched signals and notifications. A new instance chooses `createSessionId()` as attendee ID, distinct from service user ID and connection ID. (reference/fluidframework-3.11.0/packages/framework/presence/src/getPresence.ts:23-33, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceManager.ts:95-133, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceManager.ts:253-258.)

## 2. Surface used by other packages

Public presence exposes `attendees.getMyself/getAttendees/getAttendee`, attendee events, `states.getWorkspace(address,schema,settings?)`, `notifications.getWorkspace(address,schema)`, and `workspaceActivated`. States use factories `latest({local,settings?,validator?})`, `latestMap({local?,settings?,validator?,keyValidator?}?)`; notifications use `Notifications(initialSubscriptions)`. Workspace registration is incremental (`add`, repeated getWorkspace ensures content); managers expose local values, remote retrieval/iteration, events and broadcast controls. Remote state is per **attendee**, not per service user or connection. The same attendee may accumulate multiple connection IDs over reconnects. ## 3. Wire and persisted formats

### Extension transport envelope

Presence submits `host.submitAddressedSignal([],message)`. Container runtime constructs `{address:"/ext/dis:bb89f4c0-80fd-4f0c-8469-4f2848ee7f4a/",contents:message}`; the trailing slash is real. Broadcast appends `clientBroadcastSignalSequenceNumber:number` (preincrement per broadcast) after those fields; targeted signals do not get this counter and pass message.targetClientId separately to transport. Incoming runtime unwraps `contents.type/content`, adds clientId and targetClientId from transport and routes address by `/` components; presence uses `addressChain[0] === "?"` as the optional-message flag; other address components are not routed further. No presence data enters an op or summary. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/extension/containerPresence.ts:80-85, reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1835-1861, reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3803-3865, reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/signalTelemetryProcessing.ts:203-231, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceManager.ts:182-207.)

### Every declared message

| `type` | `content` fields (all required except `?`) |
|---|---|
| `Pres:ClientJoin` | `sendTimestamp:number` epoch ms, `avgLatency:number` ms, `data:Datastore`, `updateProviders:string[]` connection IDs (producer emits in this order). |
| `Pres:DatastoreUpdate` | `sendTimestamp:number,avgLatency:number,acknowledgementId?:string,isComplete?:true,joinResponseFor?:string[],data:Datastore`. Incremental producer emits `sendTimestamp,avgLatency,data`. Complete producer emits `sendTimestamp,avgLatency,isComplete,data`, then appends joinResponseFor when requests exist. No `isComplete:false` is emitted. |
| `Pres:Ack` | `{id:string}` only; emitted message has `type,content,targetClientId` in order, targetClientId sender of acknowledged update. |

These are declaration and producer contracts, not an assurance every declared message is safely consumed (Ack caveat below). `acknowledgementId` is accepted/requested but normal 3.11.0 update producers do not populate it. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/protocol.ts:70-157, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:343-351, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:505-523, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:596-628, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:731-741.)

`Datastore = {"system:presence":{clientToSessionId:{[connectionId]:{rev:number,timestamp:number,value:attendeeId:string}}},[internalWorkspaceAddress]:{[managerKey]:{[attendeeId]:Value}}}`. Workspace prefixes `s:` for states, `n:` for notifications, followed by public address; activation regex requires public address `nonempty-prefix:nonempty-rest` (`/^([^:]):([^:]+:.+)$/`). A leaf is `{rev:number,timestamp:number,value:JSON}`; map tombstone omits `value`, **not** value:null. A directory is `{rev:number,items:{[key]:leaf|directory}}`, no timestamp at directory level. Notification leaf adds `ignoreUnmonitored:true` and value `{name:string,args:JSON[]}`. Runtime validation cache `validatedValue` is never a wire field. ## 4. Behavior

### Presence join / disconnect transitions

Initial joined=false; self attendee exists Disconnected with order=0, connectionId undefined; attendees Map includes self by attendee ID. Constructor listens to runtime disconnected and audience add/remove. If runtime client ID exists, joined status != disconnected, and audience already has self, call onJoin. Audience add for self also onJoin; other adds alone do not create attendees. On any nonlocal presence signal while !joined, assert self runtime ID exists then onJoin(selfID,alternateProvider=sender) **before** processing signal. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceManager.ts:63-67, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceManager.ts:111-172, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceManager.ts:187-207, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/systemWorkspace.ts:102-109.)

onJoin always first calls system.onConnectionAdded; only then, if !joined, sends joinSession and sets joined=true. system.onConnectionAdded requires self Disconnected and either self in audience or alternate-provider path. If this connection not recorded: insert `{rev:self.order++,timestamp:Date.now(),value:self.attendeeId}`. Set self connectionId and connection Map entry. If self in audience: clear stale set, add every currently Connected attendee from map values to stale Set, set 30,000ms stale timer; set self Connected; synchronously emit attendeeConnected(self). With stale audience, self remains Disconnected until later onJoin with self in audience. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceManager.ts:148-163, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/systemWorkspace.ts:167-215.)

joinSession snapshots audience, removes self from copied members, collects interactive all/writers in iteration order. If self present and no others mark complete reason `alone`; if self absent require alternate provider (0xcba). Providers are first three writers if any, else first three interactive clients; if empty and alternate provided use alternate. Submit ClientJoin with full clean datastore and current latency **even when alone**. Disconnected: joined=false; remove current client mapping's attendee connection status; delete complete reason. It does not erase attendee objects/state, mappings, pending response requests, or immediately clear all queued data. Audience remove also deletes that connection from pending response requests. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:250-288, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:291-367, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceManager.ts:166-172.)

### Attendee merge and leave transitions

For each received system connection mapping in Object.entries order, resolve existing attendee by session ID or construct it with mapping rev and connection ID. New attendee: Connected/isJoining iff this mapping's connection is the sender OR currently in audience; otherwise retain disconnected historical attendee. Existing attendee: isConnected iff `rev >= attendee.order && (inAudience || (isSender && rev > attendee.order))`; if rev > order update order and latest connectionId; if isConnected and was Disconnected set Connected/isJoining. Remove confirmed connected attendees from stale set; map every received connection ID to attendee. Queue attendeeConnected for new joins. Store previously unknown connection mapping verbatim; existing mapping must have same attendee value (0xa5a) and is not replaced even if timestamp/rev differs. This mapping state is independent of service user ID. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/systemWorkspace.ts:118-164, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/systemWorkspace.ts:290-355.)

Leave is audience removal, not a presence signal. Unknown connection ignored. Removing self cancels stale timer; removing remote while self Disconnected ignored. If removed ID equals attendee's latest connection AND attendee Connected: set Disconnected, synchronously emit attendeeDisconnected, remove from stale set. Old connection removal after reconnect does nothing. Historical attendee/state/mappings remain. At stale timer: first mark each stale attendee whose latest connection absent from audience Disconnected, then emit attendeeDisconnected for each in stale insertion order, then clear set. No automatic per-value TTL or periodic heartbeat exists. getAttendees returns a fresh deduplicated Set of map values; getAttendee unknown throws `Attendee not found`; never-connected getConnectionId throws `Client has never been connected`. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/systemWorkspace.ts:42-59, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/systemWorkspace.ts:218-282.)

### Join response election, deadlines and completeness

Named provider delay=200ms. Other responders: if self quorum member, relativeOrder=count of interactive quorum members with earlier sequenceNumber; else relativeOrder=count of interactive quorum members + Math.random()*10. Delay=`200 + 40*(3*updateProviders.length + relativeOrder)`. Record requestor→{deadlineTime:now+delay,responseOrder:relativeOrder}; named responder order is undefined. If not complete, self present and request count >= all other interactive audience members count makes reason `full requests`. Complete+named queues sendAll at delay; otherwise set/shorten request timer. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:178-190, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:842-942.)

Timer callback if joined and requests exist finds minimum deadline; if due and complete broadcasts full state; if due but incomplete sends nothing; if future schedules remaining delay. Full broadcast sets isComplete=true, includes all state with validation caches removed, appends joinResponseFor from pending request Map keys if any, clears requests and both timers, submits, then clears queued data. Receiving update.joinResponseFor containing self sets reason `join response`; delete each listed pending request. If none remain cancel timer; if just gained completeness with remaining requests cancel timer and queue post-update recheck. Receiving isComplete alone does not grant completeness. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:596-644, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:685-729, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:807-829.)

### Inbound processing and event order

1. Presence asserts non-null clientId; may join via sender as alternate as above.
2. Datastore takes received=Date.now(); known types are Join, Update, Ack. Unknown requires optional=true or assert 0xcbc; PresenceManager passes `addressChain[0] === "?"`; ordinary emitted empty addressChain produces false, while `/ext/<id>/?` accepts an unknown type as optional and drops it.
3. Local echo: n=min(n+1,256), averageLatency=(oldAverage*(n-1)+received-content.sendTimestamp)/n; return without replaying state/events.
4. Nonlocal: timeModifier=received-(ownAverageLatency+sender.avgLatency+sender.sendTimestamp). Join, if joined status not disconnected, schedules response before consuming data. Update handles response bookkeeping then, if acknowledgementId present, assert `submit_signals_v2` supported and immediately submit targeted Ack.
5. Before updates, for every data workspace not registered or previously seen whose address regex matches, synchronously emit workspaceActivated(publicAddress,`States`|`Notifications`|`Unknown`). Listeners may register that workspace before step 6.
6. Iterate data in incoming object key order. Registered workspace returns deferred update actions; unknown workspace merges into cached datastore. After all workspaces processed, invoke collected actions in order. System attendeeConnected actions therefore normally precede value events because producers put system first, but **receiver does not reorder hostile/out-of-order keys**. Unknown attendee lookup in a registered manager can throw if corresponding system mapping has not yet been processed.

(reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceManager.ts:182-207, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:646-800, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/workspace/presenceStates.ts:428-447.)

**Ack implementation hole:** knownMessageTypes includes Pres:Ack, but processSignal has no Ack-specific return. Local Ack echo reads nonexistent sendTimestamp and contaminates averageLatency with NaN. Remote Ack computes from missing fields then reaches Object.entries(message.content.data) with undefined and throws. No sender in this implementation requests acknowledgements in normal generated updates. Do not invent successful acknowledgement handling as oracle behavior. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:80-88, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:657-672, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:685-746.)

### State merge

Leaf update wins only if base absent or update.rev > base.rev; clone winning update, replacing timestamp with update.timestamp+timeDelta; equal/older returns existing identity. Directory update: absent base creates `{rev:update.rev,items:{}}`; if base.rev >= update.rev and base leaf, return leaf; if base directory retain it; if update newer create new directory with new rev and reuse base.items when directory, else empty. Recurse through **all** update.items even when directory's own rev is equal/older; never prune absent keys. This permits late partial map updates without losing a newer unrelated key. Unregistered manager/workspace retains per-attendee values unless property `ignoreUnmonitored` **exists** (even false), in which case skip. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/workspace/presenceStates.ts:152-225.)

Registered workspace invokes node.update with raw received value; it **does not apply timeModifier**. Node datastore.update merges with timeDelta=0. Thus cached-unregistered leaf timestamps are shifted whereas registered latest/latestMap use sender timestamps. A Swift implementation that normalizes all timestamps uniformly diverges. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/workspace/presenceStates.ts:359-371, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/workspace/presenceStates.ts:428-447, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/states/latestValueManager.ts:121-139.)

For each schema key, create manager; initialData installs local attendee value into datastore and gathers initial broadcast values. Batch uses minimum explicitly specified initial manager latency, or workspace default if none. State and notification public views reference same manager record. Repeated getWorkspace returns same workspace and ensures new content; existing manager must instanceof requested factory.instanceBase or TypeError. add asserts key absent; retains preexisting remote datastore entries but does not replay remoteUpdated. Deadline=now+allowableUpdateLatencyMs; if active timer expires no later, leave it. Earlier positive deadline replaces timer; nonpositive latency sends immediately. On send: clear timer; absent queue return; disconnected clear queue/return; sendAll full broadcast; else require self ID and mapping, build update with current system mapping **first**, queued workspaces next; clear queue then submit. `targetClientId` from local-update options is not forwarded here: current Notifications.unicast therefore broadcasts in this snapshot. TimerManager setTimeout first cancels old timeout; records Date.now,delay,expired=false; callback sets expired=true before callback. clear cancels stored ID, removes ID and marks expired; expired expireTime=0 otherwise startTime+delay. No periodic timer behavior is implicit. Optional manager latency falls back via `??` to workspace controls. ### Latest value manager

Factory captures `{rev:0,timestamp:Date.now(),value:shallowClone(local)}` (null remains null) once at factory creation. local setter increments rev, stamps Date.now, replaces value (no equality check/deep clone), calls localUpdate then emits localUpdated({value}). Remote update ignores <= stored rev; otherwise merge/store then queue remoteUpdated({attendee,value:accessor,metadata:{revision:rev,timestamp:wireTimestamp}}). Remote iterators and getStateAttendees exclude self but include disconnected attendees. getRemote absent throws `No entry for attendee`; metadata timestamp here is **Date.now()**, unlike getRemotes and events which use stored timestamp. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/states/latestValueManager.ts:71-141, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/states/latestValueManager.ts:150-194.)

With validator, remote value is a lazy getter closure: on first access when `validatedValue` property absent, call validator(raw) and cache result, **including undefined**; later reads return cached value. Without validator return raw value directly. Validation failure does not delete raw state, suppress update events or alter wire data. All full state sends strip cached validatedValue recursively; directory stripping shallow-copies parent but modifies its shared items object. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/states/validatedGetter.ts:20-60, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/runtime/presenceDatastoreManager.ts:530-593.)

### Latest map manager

Factory captures directory `{rev:0,items:{}}`; initial items each `{rev:0,timestamp:oneCapturedNow,value:item}`. Local set for never-seen key inserts `{rev:0,timestamp:0,value}` and increments countDefined; every set then increments directory and item's rev, stamps now, sets value, sends only `{rev:directoryRev,items:{key:item}}`, then emits localItemUpdated({key,value}). Delete present defined value decrements count, increments revisions/stamps now, deletes value property, sends partial, emits localItemRemoved({key}), returns true; absent/tombstone delete false/no event. clear throws `Method not implemented.` Tombstones stay in items; set after delete does not increment countDefined because key already exists: `size` can undercount although keys/has/get show value. Preserve this observed oracle inconsistency. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/states/latestMapValueManager.ts:85-165, reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/states/latestMapValueManager.ts:354-369.)

Remote map: initialize attendee directory if missing. Select items absent or with larger rev, independently of directory rev; no selected items returns no actions. Raise directory rev only when greater. Store each selected item even if key validator rejects it. Valid key+defined value queues remoteItemUpdated({attendee,key,value:accessor,metadata}); add it to aggregate items Map. Tombstone queues remoteItemRemoved only when prior value was defined; not included in aggregate items. Store merged state, then if any item actions append remoteUpdated({attendee,items}) (empty items for deletion-only). getRemote returns new Map of valid defined keys, accessors and per-item revision/timestamp; unknown attendee throws. Iteration and getStateAttendees exclude self, not disconnected clients. (reference/fluidframework-3.11.0/packages/framework/presence-runtime/src/states/latestMapValueManager.ts:218-331.)

## 5. Invariants and asserts

| Code | Exact predicate |
|---|---|
| 0xa3a | signal.clientId !== null |
| 0xcbf | receiving remote before joined requires runtime self ID |
| 0xaad | onConnectionAdded self status Disconnected |

## 6. JS-semantics hazards

Use Double revisions/timestamps/latency and preserve NaN consequences of Ack; Date.now is wall-clock epoch ms, not monotonic time. Keep object insertion order for system-before-values and manager events; Maps/Sets use identity and insertion order. `items in object`, `ignoreUnmonitored in value`, and `validatedValue in value` distinguish absent property from undefined. Undefined map value means tombstone, null means a defined value. Opaque JSON/read-only casts are identity casts, not serialization or copies; local values and queued map item references may alias mutable objects. Latest initial value only shallow clones; manager factory captures one state object reused if same factory is registered more than once. Do not add retry, TTL, reconciliation op or reliable delivery: signals are ephemeral.
