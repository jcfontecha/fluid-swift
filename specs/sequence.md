# sequence — client 3.11.0

## 1. Role

SharedString is the text/marker DDS over merge-tree; SharedSegmentSequence integrates runtime submission, event conversion, legacy catchup history and named interval collections. Intervals are **segment-relative endpoint references**, not saved absolute ranges. Use this spec with the complete [merge-tree index](merge-tree.md). `reference/fluidframework-3.11.0/packages/dds/sequence/src/sharedString.ts:139`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:542`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervals/sequenceInterval.ts:818`.

## 3. Wire and persisted formats

Channel type is `https://graph.microsoft.com/types/mergeTree`, snapshotFormatVersion `"0.1"`, packageVersion from packageVersion.ts. This attribute version is **not** merge-tree chunk version. Summary has optional root `header` blob for interval map (only if map nonempty), then `content` subtree for merge-tree snapshot. Readers accept all legacy/V1 content described in [merge-tree snapshots](merge-tree/snapshots.md). `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequenceFactory.ts:44`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:726`.

Sequence ops are direct merge-tree delta/group JSON or interval map ops. Interval wrapper emitted in insertion order is:

```
{key:<collection label>,type:"act",value:{opName:"add"|"change"|"delete",value:<interval payload>}}
```

The nested payload's serializer order is `end,intervalType,sequenceNumber,start,stickiness,startSide,endSide,properties`. End/start absent for property-only change; properties always includes `intervalId` and `referenceRangeLabels:[label]` after supplied property keys. Endpoint values are numbers or literal `"start"`/`"end"`; sides are numeric Before=0, After=1. sequenceNumber is merge-tree currentSeq and must be retained separately from runtime envelope refSeq. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollectionMap.ts:270`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollectionMapInterfaces.ts:143`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervals/sequenceInterval.ts:404`.

Interval summary map is a plain JS object mapping labels to `{type:"sharedStringIntervalCollection",value:<collection>}`. Handles are serialized before outer JSON.stringify. Accept V1 collection as array of full interval payloads, or V2 `{label,intervals,version:2}` in that writer order. V2 tuples are `[start,end,sequenceNumber,intervalType,properties,stickiness?]`. Writer omits sixth entry when stickiness==END (2) or absent. Remove referenceRangeLabels from tuple properties by setting undefined; decompressor restores label array, defaults stickiness to END, reconstructs sides from bit flags (start sticky→After else Before; end sticky→Before else After). No seventh/eighth tuple entries are emitted/read by implementation despite older explanatory comments mentioning them. `reference/fluidframework-3.11.0/packages/dds/sequence/src/IntervalCollectionValues.ts:13`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollectionMap.ts:136`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:71`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:90`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:276`.

Read compatibility: skip legacy map entries whose type is `Plain` or `Shared`; strip `intervalCollections/` prefix using **JS slice(20)** from old collection keys. Missing interval ID becomes `legacy${start}-${end}` (not a new random UUID, not necessarily unique). New local intervals use supplied ID or uuid(). Serialization format defaults `"2"`, optional `intervalSerializationFormat:"1"` writes older arrays. IntervalType Simple=0, SlideOnRemove=2, Transient=4. Stickiness NONE=0, START=1, END=2, FULL=3. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollectionMap.ts:154`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervals/sequenceInterval.ts:63`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1201`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervals/intervalUtils.ts:73`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervals/intervalUtils.ts:186`.

### Literal interval examples

On text long enough to contain positions 1 and 3, currentSeq=10, collection `comments`, add `{id:"i",start:1,end:3,props:{color:"red"}}` emits (ordinary numeric endpoints default Before/Before and therefore stickiness END):

```json
{"key":"comments","type":"act","value":{"opName":"add","value":{"end":3,"intervalType":2,"sequenceNumber":10,"start":1,"stickiness":2,"startSide":0,"endSide":0,"properties":{"color":"red","intervalId":"i","referenceRangeLabels":["comments"]}}}}
```

Property-only change to blue emits:

```json
{"key":"comments","type":"act","value":{"opName":"change","value":{"intervalType":2,"sequenceNumber":10,"stickiness":2,"properties":{"color":"blue","intervalId":"i","referenceRangeLabels":["comments"]}}}}
```

Endpoint-changing change includes both start/end and sides in the same serializer order as add; delete locally serializes the entire interval then wraps it with `opName:"delete"`. The declared delete payload also permits omitted endpoints; receiver needs properties.intervalId, not positions, to delete. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervals/sequenceInterval.ts:404-435`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1201-1233`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1238-1279`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1345-1365`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1699-1719`.

For the original red interval, root summary `header` blob using default V2 is exactly:

```json
{"comments":{"type":"sharedStringIntervalCollection","value":{"label":"comments","intervals":[[1,3,10,2,{"color":"red","intervalId":"i"}]],"version":2}}}
```

With intervalSerializationFormat="1" it is:

```json
{"comments":{"type":"sharedStringIntervalCollection","value":[{"end":3,"intervalType":2,"sequenceNumber":10,"start":1,"stickiness":2,"startSide":0,"endSide":0,"properties":{"color":"red","intervalId":"i","referenceRangeLabels":["comments"]}}]}}
```

FULL stickiness emits a sixth tuple element 3; NONE emits 0; END omits it. `"intervalCollections/comments"` is an accepted old outer label and normalizes to `comments`. `Plain`/`Shared` entries are ignored rather than reconstructed as intervals. Empty accessed collections persist as `{"label":"comments","intervals":[],"version":2}`; zero collections omit the whole interval header blob. Interval payload start/end are numbers or endpoint strings; sides/type/sequence/stickiness are numbers; properties is an optional bag in historical serialized types (current writer emits one). `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:71-130`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:276-288`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/IntervalCollectionValues.ts:13-25`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollectionMap.ts:136-179`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:726-751`.

## 4. Behavior

### Runtime and text flow

Install merge-tree delta listener with **prependListener**. On local non-rollback delta submit operation and pending metadata **before** emitting sequenceDelta. Emit sequenceDelta only for nonempty deltaSegments (obliterate may still submit an empty-visible delta). Maintenance is forwarded as SequenceMaintenanceEvent. Detached mutations do not submit; didAttach starts collaboration with runtime ID or `attached`. `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:552`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:677`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:924`.

Process message collections sequentially; reconstruct sequenced envelope per content. Local ack shifts inFlightRefSeqs; require operation type. Try interval dispatch first, else merge-tree. Resubmit shifts saved refSeq and temporarily installs it as currentRefSeq for all submissions during that callback (restore in finally), tries interval resubmit first, else regenerate merge-tree pending op. Squashed resubmit passes true. Stashed ops use same dispatch split and local mutation paths. This preserves original in-flight reference history across repeated reconnects, rather than replacing every interval's history with newest refSeq. `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:786`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:883`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:937`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:1039`.

Snapshot-format precedence is config `Fluid.Sequence.newMergeTreeSnapshotFormat`, factory option, runtime option, then loaded format; newly created default is legacy. Load interval header first but defer graph attachment until merge-tree body and catchups complete. Legacy catchups must have min/ref >=collab minSeq, seq>minSeq and seq>=currentSeq (same seq allowed for grouped batches). Errors log SequenceLoadFailed then rethrow. On graph attachment initialize saved interval endpoints against complete sequence, subscribe to collection creation, attach and emit createIntervalCollection for new collections. `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:495`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:522`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:820`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:1016`.

Legacy catchup recording: if incoming refSeq!=seq-1, temporarily listen to sequenceDelta and reconstruct operations from actual local deltas; stash shallow message clone with refSeq=seq-1 and one delta or GROUP. Otherwise stash original message. Periodically drop messages <=MSN; immediately before summarize drop them and set retained messages' minimumSequenceNumber to current MSN. V1 does not retain catchup list. `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:398`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:943`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:965`.

### Text replacement and event objects

replaceText delegates to replaceRange: insert at **Math.max(start,end) first**, then remove [start,end) only if insert returned an op AND start<end. Empty inserted segments yield no insert and therefore no remove; replace with an empty string is not automatically a deletion. Reverse/zero range only inserts at max, despite prose comments elsewhere. Separate insert/remove events and submissions follow this actual order, not an atomic replace or a remove-then-insert transaction. Relative text/marker insertion resolves marker-relative position before the reentrancy-guarded insertion. getText uses no marker placeholders; getTextWithPlaceholders repeats one space per nontext unit; getTextRangeWithMarkers uses newline+segment.toString for each marker (`M`+ID), not a literal star. **All positions and string slice bounds here are UTF-16 units**, so replacing half a surrogate is valid. `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequence.ts:765-776`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sharedString.ts:165-232`, `reference/fluidframework-3.11.0/packages/dds/merge-tree/src/client.ts:346-353`, `reference/fluidframework-3.11.0/packages/dds/merge-tree/src/MergeTreeTextHelper.ts:61-87`, `reference/fluidframework-3.11.0/packages/dds/merge-tree/src/mergeTreeNodes.ts:549-550`.

SequenceEvent stores opArgs/deltaArgs and isLocal=(no sequencedMessage). `ranges` is lazy: first access computes each segment's **then-current** position, propertyDeltas default {}, segment identity and operation, using SortedSegmentSet; first/last are separately lazy accessors of that set. `clientId` getter returns **this client's longClientId**, not the remote sender, despite its interface comment. Do not promise deep immutable event snapshots: ranges/segment refs are live objects and deferred access can observe later tree state. ACKNOWLEDGED and OBLITERATE permit empty delta arrays; other event kinds assert 0x2d8 nonempty. `reference/fluidframework-3.11.0/packages/dds/sequence/src/sequenceDeltaEvent.ts:71-143`.

### Interval creation, identity and indexing

Collection get is lazy and creates map entry/event even before any interval exists; remote first op also creates it. Map order is collection creation order; summary object conversion then imposes JS object key order. IdIntervalIndex uses Map insertion order for serialization. Position/overlap indexes are separate; do not serialize in spatial order. Before endpoint sliding, clone old interval/transient endpoints and remove from indexes; nested beforeSlide callbacks increment a counter; only after last matching afterSlide re-add indexes and report position change. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollectionMap.ts:130`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollectionMap.ts:245`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalIndex/idIntervalIndex.ts:19`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:291`.

Nontransient interval endpoints use RangeBegin/RangeEnd plus **StayOnRemove while local pending**, SlideOnRemove for remote or snapshot-created intervals; detached local adds immediately switch to SlideOnRemove. Transient intervals use Transient refs. Numeric endpoints default Side.Before; this is an anchor at a character, not an exclusive numeric range end. Start sticky when side After or endpoint `start`; end sticky when side Before or endpoint `end`. Start sliding preference is backward when start-sticky else forward; end sliding preference forward when end-sticky else backward. Endpoint slide permission requires enabled setting and non-NONE stickiness. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervals/sequenceInterval.ts:818`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervals/intervalUtils.ts:220`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1211`.

Compare intervals by start reference position, then start sides (Before sorts **after** After at same position); end reference position then **reversed** side comparator; finally ID string if both truthy. Overlaps compares only reference positions inclusively, not side-aware comparison. Do not assume comparator and overlap relation use identical endpoint semantics. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervals/sequenceInterval.ts:51`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervals/sequenceInterval.ts:219`.

### Local add/change/delete and events

Add resolves/validates endpoints and stickiness gate, creates UUID if necessary, constructs interval/refs, serializes and queues add with localSeq/interval metadata if collaborating, then emits addInterval(local=true,op=undefined). Delete removes indexes/listeners, queues serialized delete when local collaborating, then emits deleteInterval. Local change requires string ID, both start/end present or both absent, and forbids modifying referenceRangeLabels. Mutate properties first, optionally replace interval endpoints/index entries, submit change with original interval as consensus, then emit propertyChanged and legacy changed for properties, then changeInterval followed by changed for endpoints. Missing interval returns undefined/no change. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1180`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1240`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1300`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1138`.

Each ID has pending local linked list, endpoint-change linked list and consensus interval. Submission tracks add and endpoint-changing change in both queues; property-only change only in local queue. Process local ack removes metadata node and endpoint node first, asserts opName matches metadata.type, then dispatches ackAdd/ackChange/ackDelete. Remaining pending entry stores returned consensus, otherwise remove empty entry. This separates visible latest local interval from remote consensus—do not overwrite optimistic endpoints when remote changes race with pending local changes. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:736`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:707`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:867`.

Remote add constructs refs using sender's envelope perspective, deserializes, then emits addInterval. Local add ack does not re-add or duplicate add event; ackInterval converts eligible refs to sliding and handles removed destinations. Remote change targets pending consensus if present, else visible latest; mutate property manager and endpoints, but reindex/emit only when changed object is current visible interval. Property notifications require nonempty delta. Local change ack acknowledges pending properties and interval refs, not a second local change. Remote delete removes visible ID if present; local delete ack is no-op. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1399`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1661`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1699`.

AckInterval: if endpoints already not StayOnRemove return. Compute slide candidates, check remaining pending endpoint changes for same ID; only with none remaining switch endpoints to SlideOnRemove and relocate. If relocating, clone old interval, remove visible indexes/listeners, create replacement endpoint refs retaining properties, convert old endpoint refs to transient for event reporting, re-add and emit endpoint change with local=true,slide=true and ack op. Endpoint change emits changeInterval then changed. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1573`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1138`.

Remote endpoint+property changes have a different notification order from local changes: mutate properties, modify endpoints, remove/add visible interval in indexes, emit `changeInterval` then legacy `changed`, call deserializer, **then** emit propertyChanged and property legacy changed if nonempty. `emitChange` temporarily changes previous interval refs to Transient during both callbacks, then restores their types (not a permanent conversion). Local property-only change returns undefined because the return value is newInterval, even when properties changed; missing ID also returns undefined. Numeric add uses IntervalType.SlideOnRemove=2 regardless of whether endpoint refs are temporarily StayOnRemove. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:219-231`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1138-1147`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1330-1388`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1422-1458`.

### Interval reconnect/normalization/rollback

On merge-tree normalize, rebase all pending endpoint changes **before segment normalization**. Resubmit removes old metadata node, rebases only if it had an endpoint-change node, otherwise keeps original payload; resubmits with original metadata/localSeq. Rebase each endpoint through getSlideToSegoff with LocalReconnecting(currentSeq,localSeq) or squash variant. Imaginary endpoint survives; no destination without endpoint permission yields detached. If either detached, suppress op and delete matching local interval (including deleteInterval event); otherwise move refs/reindex+emit slide change as necessary, emit original payload spread with rebased start/end and sequenceNumber=currentSeq. Rebased absolute position is findReconnectionPosition(segment,metadata.localSeq)+offset. Deleting fully detached interval may itself submit a delete; do not replace this with silent index removal. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:923`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:987`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1052`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:1486`.

Rollback removes pending metadata, restores preceding local or consensus interval, reverses add/delete/change with rollback flags and emits corresponding local events. Stashed interval ops route through add/change/delete local APIs so queues and fresh metadata are created, rather than remote ack APIs. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:818`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:945`.

## 6. JS-semantics hazards

**UTF-16 everywhere:** text insertion length, range positions, interval anchor offsets, delta ranges, getText start/end and surrogate splitting inherit TextSegment's JS length/slice behavior. `getTextAndMarkers` independently uses **substring**, not slice (negative clamping and inverted-argument behavior differ). It gathers text until a matching Tile marker, appends parallel text/marker pair, resets accumulator, and **drops trailing text after last matching marker**. It also wraps truthy font-weight/text-decoration spans in b/u tags; do not substitute plain-text splitting. `reference/fluidframework-3.11.0/packages/dds/merge-tree/src/textSegment.ts:55`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sharedString.ts:263`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/sharedString.ts:294`.

JS Map insertion order is summary order for interval IDs; remove/re-add during index updates can change this. Outer object labels with array-index names stringify numerically before other labels. ID and ordinal comparisons use UTF-16 lexicographic order, not localized comparison. Undefined property entries are omitted, tuple holes become null, null property values delete via shared property manager, and omitted endpoints mean unchanged rather than position zero. Legacy key normalization uses slice by UTF-16, though prefix is ASCII. `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalIndex/idIntervalIndex.ts:19`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollectionMap.ts:136`, `reference/fluidframework-3.11.0/packages/dds/sequence/src/intervalCollection.ts:112`, `reference/fluidframework-3.11.0/packages/dds/merge-tree/src/segmentPropertiesManager.ts:97`.
