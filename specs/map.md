# map — SharedMap and SharedDirectory (3.11.0)

## Role

Two synchronous map-like channels. SharedMap is flat; SharedDirectory has a root at `/`, recursive child instances, and POSIX paths. Both maintain sequenced state separately from pending local state. Do not substitute the old pending-ID map implementation: this oracle uses pending key lifetimes. `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:73-152`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:409-437`.

## Surface used by other packages

SharedMap exposes size/get/has/set/delete/clear, keys/values/entries/iterator/forEach; set returns this. SharedDirectory adds absolutePath, getWorkingDirectory, create/get/has/deleteSubDirectory, subdirectories, countSubDirectory, disposed/dispose. Child IDirectory objects are not independent channels. Public kinds/factories use `https://graph.microsoft.com/types/map` and `https://graph.microsoft.com/types/directory`, snapshot versions Map `0.2`, Directory `0.1`. `reference/fluidframework-3.11.0/packages/dds/map/src/map.ts:78-170`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:470-656`, `reference/fluidframework-3.11.0/packages/dds/map/src/mapFactory.ts:30-40`, `reference/fluidframework-3.11.0/packages/dds/map/src/directoryFactory.ts:30-40`.

## Wire and persisted formats

### Ops and values

Literal producer field order (all fields required except inner value when undefined):

```json
{"key":"k","type":"set","value":{"type":"Plain","value":7}}
{"key":"k","type":"delete"}
{"type":"clear"}
{"key":"k","path":"/a","type":"set","value":{"type":"Plain","value":7}}
{"key":"k","type":"delete","path":"/a"}
{"type":"clear","path":"/a"}
{"subdirName":"b","path":"/a","type":"createSubDirectory"}
{"subdirName":"b","type":"deleteSubDirectory","path":"/a"}
```

Map constructs key before type; Directory set constructs key,path,type,value. Keys, path and subdirName are strings. Directory path identifies the **parent** for child operations. Sender, sequenceNumber, referenceSequenceNumber and clientSequenceNumber are supplied by the runtime envelope/member, not DDS content. No version field. `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:431-436`, `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:473-476`, `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:529-532`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1242-1248`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1317-1322`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1385-1390`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1494-1499`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1541-1545`.

Stored values are `{type:"Plain",value:V}` in that order, where V is arbitrary JSON-compatible data with recursively encoded handles. Undefined becomes `{ "type":"Plain" }` (without the spaces in actual JSON), null remains value:null. A handle is `{"type":"__fluid_handle__","url":"/store/channel"}` in type,url order; serialization binds the handle to the channel, and decoding resolves it. The intermediate ISerializedValue is `{type:"Plain",value:<JSON string or undefined>}`; persisted value is parsed back to a JSON value, **not** that intermediate string. Legacy `{type:"Shared",value:<handle URL string>}` is accepted: mutate type to Plain, wrap URL as serialized handle, parseHandles to resolve legacy relative paths, then serializer.encode with this channel's bind handle. `reference/fluidframework-3.11.0/packages/dds/map/src/internalInterfaces.ts:60-103`, `reference/fluidframework-3.11.0/packages/dds/map/src/localValues.ts:30-70`, `reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:120-162`.

### Map summary, exact partition algorithm

Emit zero or more `blob0`, `blob1`, ... in encounter order, then `header`. Header always has fields blobs then content, including empty list: `{"blobs":[],"content":{"k":{"type":"Plain","value":7}}}`; empty `{"blobs":[],"content":{}}`. Each extra blob is an unwrapped key→serializable-value object. Only **sequencedData**, not the optimistic overlay, is serialized. First assign serialized entries in Map insertion order to plain `{}`; then enumerate Object.entries (numeric-index keys first, ascending). `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:545-550`, `reference/fluidframework-3.11.0/packages/dds/map/src/map.ts:173-243`.

Initialize currentSize=counter=0, headerBlob={}, blobs=[]. For each intermediate [key,value]:

1. If value.value is truthy and its UTF-16 length >=8192, append `blob${counter++}` to blobs; immediately emit `{[key]:{type:value.type,value:JSON.parse(value.value)}}`. Do not change currentSize or headerBlob.
2. Otherwise add value.type.length+21, plus value.value.length when truthy, to currentSize. Key length is **not counted**. If currentSize>16384, emit the **previous** headerBlob as the next blob, reset headerBlob={} and currentSize=0. Do not re-add the triggering entry's cost after reset. Then assign headerBlob[key]={type,value:undefined-or-JSON.parse(value.value)}.
3. Emit header with the remaining headerBlob, even if empty. Comparisons are >=8192 and >16384, not byte lengths, not >=16384. Thus this is not a hard byte-size cap. `reference/fluidframework-3.11.0/packages/dds/map/src/map.ts:177-241`.

Load: if header.blobs is an array, populate header.content first, await all listed blob reads, then populate in **list order**, not completion order. Otherwise treat header itself as the old unwrapped key-value object. Populate serializer-decodes, Object.entries, migrates Shared, writes sequencedData without events. Duplicates replace values without moving existing Map positions. `reference/fluidframework-3.11.0/packages/dds/map/src/map.ts:246-261`, `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:557-563`.

### Directory summary, exact traversal and split

Header fields blobs,content. A node has ci, optional storage, optional subdirectories in **insertion order**; ci={csn:number,ccIds:string[]} with that field order. Empty root: `{"blobs":[],"content":{"ci":{"csn":0,"ccIds":[]}}}`. Example detached child and key: `{"blobs":[],"content":{"ci":{"csn":0,"ccIds":[]},"subdirectories":{"a":{"ci":{"csn":0,"ccIds":["detached"]},"storage":{"k":{"type":"Plain","value":7}}}}}}`. Actual detached creator ID is runtime.clientId if defined, otherwise detached. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:429-437`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1280-1295`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1001-1066`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2361-2367`.

Use stack [(root,{})]. Pop node, assign ci first, iterate **sequencedStorageData in Map order**. Allocate storage={} as soon as any key is encountered, even if every value splits out. For value JSON text truthy with length>=8192, emit next blob immediately; blob contains a sparse path chain, e.g. `{"subdirectories":{"a":{"storage":{"k":{"type":"Plain","value":"..."}}}}}`. Path wrappers use subdirectories computed-property objects; leaf storage uses computed key. No ci in these sparse blobs. Small values assign storage[key]=result, result constructed type,value; undefined drops value. Then enumerate optimistic subdirectories in sorted order, allocate subdirectories={} once, assign each child object, push each child pair. LIFO means last child is processed first, including its descendants/large blobs, but child property order remains forward insertion order. Emit all large-value blobs before header. **No 16K aggregation limit in Directory.** Structure is optimistic, key storage sequenced. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1001-1066`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1399-1434`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2350-2367`.

Load supports wrapped format when Array.isArray(blobs), otherwise legacy root object. Populate header first, then extra blobs in listed order after parallel reads. Iterative LIFO populate creates children in Object.entries order **before** populating current storage; existing children are reused for sparse blobs. For new child ci.csn>0 use seq=csn, clientSeq=per-parent/per-pop counter starting 0 for that csn (increment after each); missing ci or csn<=0 uses seq=0, clientSeq=++parent.localCreationSeq. ccIds is empty when ci missing, otherwise ordered Set(ci.ccIds). Then push children, parseHandles each storage wrapper, migrate Shared, write storage without events. Root's ci is not loaded into root constructor state. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:691-781`.

Handle encoding additionally permits required-type/url plus optional final `payloadPending:true`: `{"type":"__fluid_handle__","url":"/store/blob","payloadPending":true}`. It is emitted only when the internal handle has payloadPending===true; otherwise the field is absent, never false. Decoder recognizes any value whose type property equals the marker (not a structural url validator), resolves relative URLs against serializer context, and constructs a remote handle with pending flag iff payloadPending===true. User objects with this marker therefore decode as handles rather than ordinary data. `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/handles.ts:31-56`, `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/handles.ts:95-105`, `reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:149-162`.

## Behavior

### SharedMap pending lifetimes and concurrency

State: sequencedData: ordered Map<key,{value}>, pendingData: ordered array of `lifetime(key,keySets[])`, `delete(key)` and `clear`. Individual set metadata is the **same object identity** as `{type:"set",value:{value:V}}` in the lifetime; delete and clear metadata are their pending entries. Optimistic get scans backward for clear or matching key: none→sequenced wrapper; lifetime→last set wrapper; delete/clear→absent. has tests wrapper existence, so set(undefined) is present. `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:73-115`, `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:345-438`.

- Set rejects null/undefined key. Detached: sequenced set then valueChanged({key,previousValue},true,map). Attached: find last clear-or-key; absent/delete/clear starts new lifetime at pending tail; otherwise reuse lifetime. Append set metadata, submit op, emit valueChanged even for equal/undefined values. `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:393-443`.
- Delete detached removes sequenced key, emits only when prior wrapper existed, returns actual removal. Attached always appends delete and submits, even absent; emits only when prior wrapper existed, returns true even absent. `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:450-490`.
- Clear snapshots visible entries first. Detached clears sequenced state; attached appends clear and submits. Both emit clear(local=true,map), then valueChanged({key,previousValue},true,map) for collected entries in iteration order. Clear emits even when empty. `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:496-537`.
- Local ACK set: find first non-clear matching-key entry, assert lifetime; shift first set and identity-match metadata, remove empty lifetime, sequencedData.set(key,pending value). Delete: find first non-clear key, assert delete and metadata identity, remove, sequenced delete. Clear: sequenced clear **before** shifting/asserting first pending clear and metadata identity. No ACK events. `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:708-845`.
- Remote set/delete always update sequenced state (set migrates Shared first); emit valueChanged with **previous sequenced value**, even deleting absent key, iff there is no pending clear or matching-key entry. Remote clear collects sequenced keys having no pending lifetime/delete, clears sequenced state, and iff no pending clear emits clear(false,map) then per-collected-key valueChanged(false). Pending sets remain visible; hidden remote writes still matter to later rollback. Last sequenced mutation wins after locals retire; a pending overlay hides, rather than discards, earlier remote changes. `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:724-845`.

Iteration uses live sequenced-key and pending-array iterators. First yield sequenced keys with no pending clear/delete using current optimistic value. Then pending lifetimes: yield only if lifetime index>last matching delete-or-clear index, and key absent in sequenced state OR a matching delete/clear exists. This places re-added keys at their new lifetime position. size consumes immediately. forEach snapshots into a native Map of **wrappers**; callback receives unwrapped value,key,that temporary Map (whose get returns wrappers). Do not silently replace this third argument with channel. `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:180-269`, `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:332-343`.

ReSubmit forwards unchanged content and identical metadata; unknown type returns false (caller ignores that return on resubmit). Disconnect no-op. Stash invokes normal clear/delete/set (with Shared migration); shared base decodes handles first, so replay recreates pending entries/submission/events. Incoming non-op ignored; unknown applied op fails 0xab2. `reference/fluidframework-3.11.0/packages/dds/map/src/map.ts:264-300`, `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:574-629`, `reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/sharedObject.ts:541-542`.

Rollback clear pops/asserts matching clear identity, emits valueChanged(previousValue:undefined) for each now-visible entry, no clear event. Set/delete find **last** non-clear matching key (not necessarily array tail). Delete asserts identity then removes, emits previousValue:undefined only if wrapper now visible (including wrapper of undefined). Set pops/asserts last set identity, removes empty lifetime, always emits previousValue=rolled-back value. Never restore a captured old value over newer sequenced data; removing overlay exposes current sequenced state. `reference/fluidframework-3.11.0/packages/dds/map/src/mapKernel.ts:637-699`.

### Directory storage and events

Each SubDirectory has sequencedStorageData: Map<key,V>, pendingStorageData lifetimes/delete/clear, sequenced children, pending children array, seqData, creator clientIds, localCreationSeq and deleted flag. Storage lifetime read/has/iteration rules match Map but store raw V; has separately tracks presence of undefined. Directory forEach iterates directly and supplies the SubDirectory itself as the third callback argument, unlike Map's temporary wrapper Map; size counts its immediate iterator. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1103-1135`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1656-1781`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1552-1566`.

Directory value event pair means channel.valueChanged({key,path,previousValue},local,channel), then subdir.containedValueChanged({key,previousValue},local,subdir). Root contained events are synchronously forwarded to SharedDirectory (registered before external listeners). Subdirectory child lifecycle events propagate upward with posix.join(childName,relativePath), listener registration order applies. Registrations are not deduplicated when a child is reused. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:452-469`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1250-1260`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2580-2586`.

Local set mirrors Map pending logic, metadata includes path and subdir identity; submit before event pair. Local delete always submits attached, returns true; emits pair only when previous **value !== undefined** and current path reachable/not disposed (detached also requires successful removal). Thus deleting a present undefined value emits in Map but **not Directory**. Local clear detached clears storage then channel.clear(true,channel), channel.cleared(path,true,channel). Attached append pending clear, emit those two events **before submitting**. No per-key delete events, no contained-clear event, no child deletion. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1187-1261`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1459-1545`.

Process in batch order only op envelopes. Resolve path through **sequenced children**, ignore missing/disposed target, then apply the instance predicate below. Set migrates wrapper before target processing. Local clear shifts/asserts metadata identity; local set shifts/asserts pending set identity; local delete removes first key delete and validates type/key, **not metadata identity**. Write sequenced storage and emit no ACK events. Remote set/delete update sequenced storage, emit event pair only when path reachable/not disposed and no pending clear/key. PreviousValue is sequenced value. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:783-810`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:835-967`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1923-2027`.

Remote clear is deliberately unlike Map: collect one `{key,previousValue:sequenced.get(key)}` **per pending lifetime**, including duplicates; clear sequenced storage. If no pending clear emit channel.clear(false,channel) then cleared(path,false,channel), without a reachability guard on these two emissions. Then for every collected pending lifetime emit **only channel.valueChanged** (no contained event), even with a pending clear, stopping when current directory is disposed or path no longer resolves. It does not emit per removed sequenced key. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1853-1912`.

### Directory child lifecycle and create/delete races

Instance acceptance for any op on a directory is exactly `(metadata target absent OR target===this) AND (sender nonnull and in creator clientIds OR clientIds contains "detached" OR seq!=-1 and seq<=envelope.referenceSequenceNumber)`. Storage metadata target is subdir; child-op metadata target is parentSubdir. This excludes stale old-instance edits even if the path exists again, but permits concurrent creators' edits. Root seq=0 accepts ordinary ref>=0. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2564-2577`.

Optimistic child lookup scans backward for name: latest create→its object, latest delete→absent, none→sequenced child; disposed object is absent unless getIfDisposed=true. Reachability is `!disposed && getWorkingDirectory(absolutePath)!==undefined` (not identity equality). Paths use POSIX resolve rooted at `/`, or child's path for relative lookup, normalize dot/dotdot and repeated separators. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:621-656`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1790-1837`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2554-2555`.

1. Local create rejects null/undefined or name containing `/`; empty/dot names aren't rejected here. Lookup including disposed; allocate local seq (attached -1, detached 0; clientSeq=++localCreationSeq) **even if reusing**. New child gets creator runtime.clientId??"detached"; reuse undisposes bottom-up when needed and adds creator ID. Always register bubbling listeners. Only newly-created child: attached append create(name,child), submit with `{type:"createSubDir",parentSubdir:this}`; detached insert sequenced child. Then emit parent.subDirectoryCreated(name,true,parent). Reuse has no create op/event. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1268-1347`.
2. Local delete detached removes sequenced child; if present fully dispose tree then emit subDirectoryDeleted, return actual removal. Attached absent optimistic child→false/no op. Otherwise append delete(name,parent), submit `{type:"deleteSubDir",subDirectory:oldChild,parentSubdir:this}`, emit subDirectoryDeleted **then** recursively emit disposed bottom-up without setting deleted flags or clearing data. This distinction allows pending rollback. Return true. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1360-1396`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2606-2618`.
3. Sequenced create requires accepted parent and nonnull sender. Local: remove first name entry, assert create, take pending child; if sequenced child already exists return immediately (including skipping seq fix). Otherwise undispose pending child if needed and insert. Remote: optimistic lookup including disposed; allocate if absent with seq=envelope.sequenceNumber, clientSeq=member.clientSequenceNumber, creator sender; otherwise undispose if needed and add sender. Register bubbling; set sequenced child. Emit subDirectoryCreated(name,false,parent) iff no pending same-name entry and child reachable/not disposed, **even when reused**. Finally if parent.seq!=-1 and <=message seq and child.seq==-1, set child's seq/clientSeq from message. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2039-2126`.
4. Sequenced delete accepts **parent** instance, not a child creation-ID embedded in op (none exists). Missing sequenced child: local remove first same-name pending delete after assertion; remote no-op. Present: remove sequenced child, fully dispose tree, then local remove first matching delete; remote emit subDirectoryDeleted iff there is no pending same-name **delete** (pending create alone does not suppress it). Full disposal recursively visits optimistic children bottom-up, sets seq/clientSeq=-1, clears sequenced storage/children/creator IDs, adds current runtime ID??detached, and sets deleted=true/emits disposed. Pending storage and pending child entries survive. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2137-2199`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2589-2603`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2677-2683`.

Consequences: concurrent creates can coalesce onto a pending child object and accumulate creator IDs; a remote create during a pending delete allocates a different sequenced object because optimistic lookup returns absent. A remote delete can dispose a coalesced pending-create object; local create ACK/reSubmit may undispose it, retaining its pending edits but not cleared sequenced data. Child name is not identity. Do not reduce this to unconditional name-level LWW. These are direct branches of the above transitions. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2039-2199`.

subdirectories snapshots sequenced names first, then unique pending-only names, resolves each optimistically, sorts stably: acknowledged/detached seq>=0 before negative; within either group seq ascending then clientSeq ascending. This sorted structure controls summaries and disposal order. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:366-385`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:1399-1434`.

### Directory reconnect, rollback, stash

Disconnect no-op. ReSubmit routes using metadata's original object, **not a freshly resolved path**; skip if target/parent disposed. Clear forwards original op/metadata only if any pending clear remains. Delete-key requires pending delete with matching key. Set requires matching lifetime containing identical set metadata. Create finds **last** pending create of name, adds new runtime clientId??detached to its child, undisposes tree bottom-up (emits undisposed even already live), submits with **fresh** create metadata. Delete-child finds last pending delete, asserts metadata's saved child exists, resubmits with saved child and fresh metadata. No local storage replay/events except undispose/bubbling consequences. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:681-688`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:835-967`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2219-2342`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2621-2627`.

Rollback resolves **optimistic path**; absent→no-op. Clear pops pending tail; absent→return, otherwise assert both clear types (not identity), emit event pair for every restored visible key with previousValue undefined. Set/delete locate last non-clear matching-key entry; absent→return. Delete asserts identity, removes, emits pair only if newly-visible value!==undefined; set pops/asserts metadata identity, removes empty lifetime, always emits pair with previousValue=rolled-back value. No restoration into sequenced storage. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:813-821`, `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2397-2480`.

Rollback create finds last pending create of name, absent→return; emits disposed tree bottom-up **without flags/data mutation**, removes pending create, then subDirectoryDeleted. Rollback delete finds last pending delete, absent→return; removes it, asserts saved child, undisposes its tree bottom-up, registers bubbling again, emits subDirectoryCreated. Does **not** explicitly reinsert into sequenced children. Unsupported op/metadata combination throws. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:2482-2545`.

Stash resolves optimistic path and invokes normal clear/create/delete/deleteSubDirectory/set; missing path→no-op (set still performs legacy migration before optional call). Recreates normal metadata/events/submissions. Unknown stash type unreachable-case failure. `reference/fluidframework-3.11.0/packages/dds/map/src/directory.ts:970-998`.

## JS-semantics hazards

`__proto__` is a legal live Map/storage key and op.key **string value**; constructing set/delete ops does not assign a dynamic property with that name. It therefore survives wire ops. Map summary first does serializedMapData[key]=wrapper on plain `{}`: `__proto__` invokes inherited setter, changes prototype to wrapper, creates no own property, is omitted by Object.entries, never reaches either small or large split. Its value size cannot rescue it. Reload of an authored summary loses it. A legacy/manually-authored JSON object's own `__proto__` is read via Object.entries: JSON.parse creates an own data property; decode returns the input when no handles change, or an object-spread clone preserving that own property when handles change.
