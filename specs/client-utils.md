# client-utils — 3.11.0

## 1. Role

The actual npm name is `@fluid-internal/client-utils`. It supplies cross-platform byte/string/hash operations and two distinct synchronous event systems to loader, runtime and DDS clients. Node/browser entrypoints select their own buffer/hash implementations; shared event implementations are the same. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/indexNode.ts:9-51`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/indexBrowser.ts:9-51`)

## 3. Wire and persisted formats

No independent summary version. Byte conversions and digests are inputs to persisted formats and must be exact:

- Base64 encodes raw bytes using the standard alphabet and `=` padding. UTF-8 `hello` => bytes `68 65 6c 6c 6f` => `aGVsbG8=`. `fromUtf8ToBase64` encodes UTF-8 then base64; reverse decodes base64 bytes then UTF-8. `toUtf8(input,"utf8"|"utf-8")` returns input unchanged, not a decode/re-encode. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/base64EncodingNode.ts:20-50`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferBrowser.ts:40-55`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferBrowser.ts:194-215`)
- `hashFile(file,algorithm="SHA-1",hashEncoding="hex")`: digest only view bytes, no framing. Algorithms exactly SHA-1 and SHA-256; lowercase hex (two digits per byte) or standard padded base64. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/hashFileNode.ts:28-47`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/hashFileBrowser.ts:11-34`)
- `gitHashFile(file)` hashes UTF-8/ASCII `blob `, decimal **byteLength**, one NUL byte, then exact file bytes with SHA-1; output lowercase hex. For `hello world` with no newline, input is `62 6c 6f 62 20 31 31 00 68 65 6c 6c 6f 20 77 6f 72 6c 64`; result `95d09f2b10159347eece71399a7e2e907ea3df4f`. Raw SHA-1 of that file is `2aae6c35c94fcfb415dbe95f408b9ce91ee846ed`; SHA-256 base64 is `uU0nuZNNPgilLlLX2n2r+sSE7+N6U4DukIj3rOLvzek=`. These are fixtures from the producing hash paths, not illustrative guesses. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/hashFileNode.ts:62-68`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/hashFileBrowser.ts:81-92`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/test/mocha/hashFile.spec.ts:20-26`)
- Trace result construction order is `totalTimeElapsed:number`, `duration:number`, `tick:number`, all fractional milliseconds. With start tick 100, last tick 100, next tick 104.5, result is `{"totalTimeElapsed":4.5,"duration":4.5,"tick":104.5}`. This is telemetry data, not an op envelope. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/trace.ts:14-34`)

## 4. Behavior

### Node-compatible EventEmitter and TypedEventEmitter

`EventEmitter` is re-exported from `events_pkg`, the npm `events` implementation. `TypedEventEmitter` subclasses it and binds addListener/on/once/prependListener/prependOnceListener/removeListener/off to the instance; no behavioral override exists. The resolved dependency implementation is available in the oracle harness and the following precise behavior is read from that code, not from native Node assumptions. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/eventEmitter.cts:7`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/typedEventEmitter.ts:49-75`, `harness/node_modules/events_pkg/events.js:120-372`)

1. Registration validates a function. If a newListener listener exists, emit `newListener(event,originalListener)` **before insertion**; once wrappers are unwrapped for that notification. Re-read the event map afterward because that callback may replace it. Insert at end for on/addListener; at beginning for prepend. Duplicates are allowed. Calls return the emitter for chaining. A listener inserted by a newListener callback can precede the listener whose registration triggered it. (`harness/node_modules/events_pkg/events.js:164-235`)
2. Emit synchronously: gather args; for missing non-error listener return false. A single handler is called directly; for multiple handlers clone the array and invoke in that order with `this=emitter`. Return true after completion. A thrown listener exception interrupts remaining listeners and escapes. Returned promises are ignored, not awaited. (`harness/node_modules/events_pkg/events.js:120-162`)
3. Removal during an emit affects future emits, **not the cloned current list**. Adding during emit likewise does not extend the current list. Nested emit runs immediately and takes the *current*, newly mutated list; it completes before the outer callback resumes. Thus A removing B gives outer A,B but nested emit after removal sees only A. (`harness/node_modules/events_pkg/events.js:147-159`, `harness/node_modules/events_pkg/events.js:269-319`)
4. once/prependOnce create a bound wrapper with `{fired:false,wrapFn,target,type,listener}`. On invocation while not fired: remove wrapper first (including synchronous removeListener notifications), set fired=true, call original with emitter this and original args. Ordinary recursive emit from the original cannot invoke it again. Subtle exception: reentrant emission from the removal notification occurs **before** fired=true; a captured wrapper may still be invoked by that reentrancy. (`harness/node_modules/events_pkg/events.js:237-266`)
5. removeListener/off validate callback; absent event/callback is no-op returning emitter. Match raw callback or wrapper.listener; search multiple handlers **backward**, removing only the last matching registration. Collapse array to one function when one remains. After removal, emit removeListener(event,originalCallback) if that meta-event still exists. Mutated membership is observable from the callback. (`harness/node_modules/events_pkg/events.js:268-321`)
6. removeAllListeners without a removeListener observer clears directly. With an observer, remove event listeners in reverse registration order; all-events removal iterates Object.keys, excludes removeListener until last, clears all bookkeeping afterward. (`harness/node_modules/events_pkg/events.js:323-372`)
7. An unobserved error event throws its Error argument as-is; non-Error payload creates `Error("Unhandled error." + (payload ? " ("+payload.message+")" : ""))` and assigns `.context=payload`. Other event names never get this special handling. (`harness/node_modules/events_pkg/events.js:120-145`)
8. listeners returns a copy with once wrappers unwrapped; rawListeners returns copy retaining wrappers; listenerCount counts registrations including duplicates; eventNames returns own event keys. Default max listeners is 10; setMaxListeners accepts a nonnegative non-NaN number, throws RangeError otherwise. Max-listener threshold is advisory, not a registration limit: excess registration succeeds and emits a warning once per listener array, carrying name `MaxListenersExceededWarning`, emitter, type and count. Zero disables warnings. (`harness/node_modules/events_pkg/events.js:65-118`, `harness/node_modules/events_pkg/events.js:205-220`, `harness/node_modules/events_pkg/events.js:374-426`)

### createEmitter / CustomEventEmitter — deliberately different

Storage is Map<event,Set<callback>>. on obtains/creates Set, **rejects duplicate callback identity** with `Attempted to register the same listener object twice for event <description>`, inserts, returns Off closure which calls off(event,callback). No once/prepend, newListener/removeListener meta-events, or special error behavior. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/events/emitter.ts:24-31`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/events/emitter.ts:86-96`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/events/emitter.ts:132-147`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/events/emitter.ts:224-228`)

`emit`: get Set, snapshot `[...listeners]`, loop in insertion order, and **before each invocation test the original Set still has callback**. Consequently A removing B prevents B from running in that same emit. New callbacks do not run until later/nested emit. Remove+re-add of the same callback into the *same* Set before its turn makes it eligible again; remove of the final listener deletes the Map entry, so later registration creates a new Set and is not part of the old emission. All callbacks synchronous; exceptions escape and abort iteration. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/events/emitter.ts:98-114`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/events/emitter.ts:149-158`)

Nested emit runs immediately with a fresh snapshot and finishes before its caller continues; `emit` returns void, not legacy EventEmitter’s boolean. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/events/emitter.ts:98-114`)

`emitAndCollect` snapshots Set values and **does not test membership** before invoking each callback. Removed callbacks therefore still run in the current collection. Push return values, including promises/undefined, in snapshot order; return [] when no Set exists. No awaiting. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/events/emitter.ts:116-130`)

`off`: delete callback; only if deletion succeeds and Set becomes empty, delete event entry then synchronously call noListeners(event). Repeated Off does nothing unless the same callback has since been re-registered (the closure is not a one-shot token). `hasListeners()` checks Map.size; with event checks Map.has. noListeners may reenter registration safely because deletion precedes notification. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/events/emitter.ts:145-165`)

### Buffer allocation, views and conversions

Buffer surface: `Uint8ArrayToString(array,encoding?)` defaults utf8; `stringToBuffer(input,encoding):ArrayBuffer`; `bufferToString(blob:ArrayBufferLike|Uint8Array,encoding):string`; shared conversions each accept one buffer/view and return the stated ArrayBufferLike/ArrayBuffer. `IsoBuffer` supports Uint8Array operations (set, slice, subarray, byteOffset/byteLength/buffer), toString(encoding?), static from overloads, isBuffer(obj), and browser fromString/fromArrayBuffer. Browser isBuffer uses instanceof IsoBuffer, not arbitrary Uint8Array. A numeric browser constructor allocates zero-filled bytes; constructor from array-like copies, from backing buffer shares memory, through Uint8Array constructor semantics. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferBrowser.ts:34-81`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferBrowser.ts:120-220`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferShared.ts:17-90`)

Browser IsoBuffer subclasses Uint8Array. `from(string,encoding?)` decodes to fresh bytes; `from(Uint8Array)` copies exactly its bytes and ignores offset/length arguments; `from(ArrayBufferLike,offset?,length?)` shares backing storage, defaults offset 0, length buffer.byteLength-offset. Reject offset<0, offset>length, length<0, offset+length>buffer.byteLength with RangeError `Invalid range specified.` Unsupported input throws TypeError `Input value was neither a string, a Uint8Array, nor an ArrayBuffer.` (`reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferBrowser.ts:120-192`)

UTF-8 encoding uses TextEncoder (unpaired UTF-16 surrogates become U+FFFD); decoding uses non-fatal default TextDecoder (malformed sequences replaced; a leading UTF-8 BOM is stripped). Base64 uses base64-js. Before base64 decode: split at first `=`, discard suffix; remove characters matching `/[^\w+-/]/g` (keeps ASCII letters, digits, underscore, plus, minus, slash); if length mod4 is 1/2/3 append 3/2/1 `=` respectively. This tolerates missing padding, junk and URL-safe spelling. Unsupported encoding throws `invalid/unsupported encoding`. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferBrowser.ts:40-55`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferBrowser.ts:194-245`)

Node IsoBuffer is native Buffer; Uint8ArrayToString reuses a Buffer input or copies other arrays then calls toString. Node `stringToBuffer` slices backing allocation to exact byteOffset..byteOffset+byteLength; browser returns newly decoded IsoBuffer.buffer. bufferToString preserves Uint8Array views rather than treating their entire allocation as payload. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferNode.ts:98-145`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferBrowser.ts:65-81`)

Shared conversions: ArrayBufferLikeToArrayBuffer returns ordinary ArrayBuffer as-is, otherwise copies through a fresh Uint8Array slice. Uint8ArrayToArrayBufferLike returns backing buffer only for full-span view, otherwise slices backing buffer at exact extent and preserves backing-buffer type. AnyUint8ArrayToArrayBuffer reuses only a full-span ordinary ArrayBuffer; otherwise `new Uint8Array(array).buffer` copies exactly bytes. Never use Node Buffer.slice().buffer: slice is a view and exposes pooled neighbors. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferShared.ts:17-25`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferShared.ts:41-54`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferShared.ts:71-90`)

Browser/Node BOM distinction is observable: browser `bufferToString([EF BB BF 61],"utf8")` yields "a" via TextDecoder; Node Buffer.toString yields "\uFEFFa". Encoding either string uses TextEncoder/Buffer and preserves an explicitly present U+FEFF. This is not a reason to normalize every string in the port: select the oracle environment for the affected path. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferBrowser.ts:40-55`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferNode.ts:117-145`)

### Hashing, timing and layer compatibility

Node hashFile constructs sha1/sha256 engine, updates once with view bytes, digests chosen encoding. Browser uses crypto.subtle.digest on view, awaits, then encodes; if subtle is undefined dynamically imports Node hash implementation. Browser gitHashFile allocates prefix+payload sized buffer, sets prefix at 0 and payload at prefix.byteLength, calls default hashFile. Node incrementally updates prefix then file. No events. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/hashFileNode.ts:28-68`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/hashFileBrowser.ts:50-92`)

Trace.start samples performanceNow and initializes both startTick and lastTick. trace samples once, builds total/duration/tick, updates lastTick, returns event. `checkLayerCompatibility(requirements,details?)` substitutes `{supportedFeatures:new Set(),generation:0,pkgVersion:"unknown"}` for absent details; marks incompatible only when generation<minSupportedGeneration (not a >= test: NaN does not trip it); collects unsupported required features in requirement-array order (duplicates retained); returns `{isCompatible:true}` or `{isCompatible:false,isGenerationCompatible,unsupportedFeatures:arrayOrUndefined}` in that order. JSON drops undefined unsupportedFeatures. Generation for this version is 11. Policy windows in months/generations: new Driver/old Loader 12, new Loader/old Driver 12, new Runtime/old Loader 12, new Loader/old Runtime 3, new Runtime/old DataStore 3, new DataStore/old Runtime 3. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/trace.ts:14-34`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/layerCompat.ts:24-49`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/layerCompat.ts:116-120`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/layerCompat.ts:174-205`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/layerGenerationState.ts:8-12`)

### UUID ownership boundary

No UUID bytes are produced by this package. Adjacent runtime createSessionId/generateStableId call uuid.v4 then assertIsStableId (0x4a3). The required string form is 36 code units, hyphens at 8/13/18/23, `4` at 14, variant digit in 8/9/a/b (either case) at 19, hexadecimal elsewhere. Native UUID.uuidString defaults to uppercase: normalize authored v4 IDs to lowercase to match uuid.v4 output; accept upper/lowercase in validators. Do not replace id-compressor's numeric UUID arithmetic with platform UUID ordering. (`reference/fluidframework-3.11.0/packages/runtime/id-compressor/src/utilities.ts:13-102`, `harness/node_modules/uuid/dist/cjs/stringify.js:3-39`)

## 5. Invariants and asserts

Duplicate createEmitter registration is an Error, not a no-op. Legacy EventEmitter allows duplicates. Buffer range failures are recoverable RangeError, not assertion traps. Neither event implementation catches listeners. Hash length is bytes, not Unicode character count. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/events/emitter.ts:98-147`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferBrowser.ts:175-192`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/hashFileNode.ts:62-68`, `harness/node_modules/events_pkg/events.js:194-203`)

## 6. JS-semantics hazards

A single generic Swift event bus cannot stand in for both emitter contracts: removal, duplicates, collection and reentrancy differ. Closure identity must be explicit. Maintain synchronous callbacks on container executor, not unstructured Tasks. Byte views must not leak pooled allocation neighbors into hashes/base64. UTF-8 conversion is intentionally lossy for lone surrogates; JSON string preservation elsewhere is not. A Map/Set is not serialized as its entries by JSON.stringify. (`reference/fluidframework-3.11.0/packages/common/client-utils/src/events/emitter.ts:98-165`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferShared.ts:71-90`, `reference/fluidframework-3.11.0/packages/common/client-utils/src/bufferBrowser.ts:194-211`)
