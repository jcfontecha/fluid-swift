# driver-base — Swift port contract (3.11.0)

## Role

Shared socket.io document connection implementation, subclassed by Routerlicious and other remote drivers; owns the Fluid handshake, initial-message capture, event forwarding and permanent teardown. It does not reconnect an established document connection itself. Also exports message-range validation, promise racing and browser timing helpers. Source: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:54-115`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/driverUtils.ts:15-168`.

## Wire and persisted formats

No persisted records or REST calls originate here. Socket event arguments are positional, not an object wrapping all parameters. Incoming objects retain their server property order: this class does not reconstruct them. Outgoing ops retain caller property order. Optional undefined object properties disappear under socket.io JSON serialization; explicit null remains. Sources: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:348-389`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:482-694`.

### Complete event inventory

| Direction/event | Positional arguments and action |
|---|---|
| Send `connect_document` | One `Connect` object, once all handlers and the timer are registered. `Connect={tenantId:string,id:string,token:string|null,client:Client,versions:string[],mode:"read"|"write",driverVersion?:string,nonce?:string,epoch?:string,supportedFeatures?:Record<string,unknown>,relayUserAgent?:string}`. Caller insertion order is retained; `supportedFeatures` is overwritten with a spread of existing flags then `submit_signals_v2:true`. Routerlicious's exact producer order is specified in its spec. |
| Receive `connect_document_success` | One `Connected` object: required `claims:Claims,clientId:string,existing:boolean,maxMessageSize:number,initialMessages:SequencedMessage[],initialSignals:Signal[],initialClients:SignalClient[],version:string,supportedVersions:string[],serviceConfiguration:{maxMessageSize:number,blockSize:number,noopTimeFrequency?:number,noopCountFrequency?:number},mode:"read"|"write"`; optional `nonce:string,checkpointSequenceNumber:number,epoch:string,supportedFeatures:Record<string,unknown>,timestamp:number,relayServiceAgent:string`. Nonce and mode checks below. Note accessor maxMessageSize uses **serviceConfiguration.maxMessageSize**, not top-level maxMessageSize. |
| Receive `connect_document_error` | One error object; optional nonce participates in filtering. Base accepts arbitrary errors, subclass can translate `{code:number,message:string,retryAfter?:number,retryAfterMs?:number,internalErrorCode?:string|number}`. Matching error permanently disconnects and rejects initialization. |
| Send `submitOp` | `(clientId:string, batches:DocumentMessage[][])`. `submit(messages)` wraps exactly once: `[messages]`. |
| Send `submitSignal` | `(clientId:string, signals)`; v2 `signals=[{content:string,targetClientId?:string}]`, fields inserted content then target; legacy `signals=[[content]]`. |
| Receive `op` | `(documentId:string,messages:SequencedMessage[])`; early handler appends all messages, without document-id filtering; registered live handler forwards unchanged arguments. |
| Receive `signal` | `(Signal|Signal[])`; early handler flattens an array, otherwise appends one; live forwarding preserves incoming single-versus-array shape. |
| Receive `nack` | `(documentId:string,nacks:Nack[])`; lazy live forwarding unchanged; **no** retry, disconnection or early nack queue in this class. |
| Receive `disconnect` | `(reason,details?)`; create retryable generic network error with scenario disconnect and `socketErrorType=details?.context?.type`, `socketCode=details?.context?.code`; close and emit local disconnect. |
| Receive `error` | One arbitrary error; retryable except exactly the string `"Invalid namespace"`; close and emit local disconnect, not local error. |
| Receive `connect_error` | One socket.io error, counted and processed by the transport state machine below. |
| Receive `connect_timeout` | No payload consumed; close/reject with retryable connect_timeout error. |
| Send `ping` / local `pong` | On first local pong listener, `socket.volatile?.emit("ping",ackCallback)` immediately. Ack emits local `pong(Date.now()-start)` then schedules another ping 60,000 ms later. This is an application ack, not a socket `pong` listener. No ack means no next ping. |

### Handshake fixtures and pre-handshake ordering

A complete accepted read-mode success example (server field order illustrative):

```json
["connect_document_success",{"claims":{"documentId":"doc","scopes":["doc:read"],"tenantId":"t","user":{"id":"u"},"iat":1700000000,"exp":1700003600,"ver":"1.0"},"clientId":"c1","existing":true,"maxMessageSize":1024,"initialMessages":[],"initialSignals":[],"initialClients":[],"version":"0.4.0","supportedVersions":["^0.4.0"],"serviceConfiguration":{"maxMessageSize":1024,"blockSize":65536},"mode":"read","checkpointSequenceNumber":8,"supportedFeatures":{"submit_signals_v2":true}}]
["connect_document_error",{"code":401,"message":"expired"}]
```

Success uses the received claims, no local JWT verification here; read is allowed without doc:write even if requested write. For a queued op9 before success, response initial op8, queued op10 after success but before initialMessages access: consumer first registers op listener, then reads initialMessages -> [op8,op9,op10] after numeric sort. A signal received before success and one between success and initialSignals access append after response.initialSignals in arrival order. There is no “success received, stop queuing” transition. `reference/fluidframework-3.11.0/packages/common/driver-definitions/src/protocol/sockets.ts:84-177`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:280-318`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:599-655`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:724-734`.

## Behavior

### Connection state machine and exact ordering

Represent states as **constructed**, **handshaking**, **connected/capturing**, **connected/live**, **disposed**; capturing ops and signals are independent flags, not one combined drain. `_details` is assigned only when the handshake promise continuation runs. Source: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:79-115`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:482-500`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:654-696`.

1. Constructed → handshaking on initialize: attach early op, early signal; set earlyOpHandlerAttached=true; merge feature flag; initialize connection failure counter; create promise; schedule timeout at `timeout+2000` ms; register connect_error, connect_timeout, success, tracked disconnect, tracked error, connect_document_error in that order; emit connect_document. No socket `connect` handler or separate send-on-connect is added here. Source: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:482-693`.
2. Success with both request/response nonce defined and unequal: ignore completely, leaving timer/listeners active. Otherwise compute write permission by `claims.scopes.includes("doc:write")`. With write permission require actualMode===requestedMode; without write permission reject only actualMode==="write". Rejection is nonretryable and disconnects. Success logs ConnectDocumentSuccess; if checkpoint undefined delete that property, else copy to connection; remove all connection-only listeners and clear timeout; resolve response; promise continuation assigns `_details`; assert not disposed. No local connected event. Early listeners remain installed. Source: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:599-656`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:696-697`, `reference/fluidframework-3.11.0/packages/common/driver-definitions/src/protocol/scopes.ts:10-25`.
3. Matching connect_document_error → disconnect then reject; mismatched defined nonce → ignore. Timeout → disconnect with orderingServiceHandshakeTimeout then reject. Failure helper catches/logs teardown exceptions and still rejects original error. Source: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:500-527`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:678-694`.
4. On first external op/signal/nack listener, subscribe socket forwarding before that local listener is inserted (newListener semantics). Internal and external callbacks can both observe an arriving op until the initial drain. Reading initialMessages requires an op listener and attached early op handler; removes early op handler, appends queued ops to response.initialMessages, numeric sorts by sequenceNumber **only if queue nonempty**, empties queue, returns that array. No deduplication. Reading initialSignals requires signal listener; removes early signal handler, appends queued signals in arrival order, empties queue, returns response.initialSignals. It has no repeated-read guard. initialClients returns response array. Source: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:162-209`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:280-328`.
5. Connected send: submit asserts not disposed then emits the nested batch; submitSignal checks `supportedFeatures?.submit_signals_v2 === true`; v2 sends targeted/untargeted object; legacy allows only untargeted nested strings; targeted legacy throws UsageError. emitMessages itself suppresses stale sends on disposed subclasses. Source: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:348-389`.
6. Any disconnect path: if already `_disposed`, return. Clear pending latency timer; set `_disposed=true`; remove tracked socket listeners in Map insertion order; remove connection listeners and clear handshake timeout; remove early op and signal; clear tracked map; invoke disconnectCore (base calls socket.disconnect); then emit local disconnect(error). No op/signal clearing or listener removal on the connection emitter itself. Source: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:442-480`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:765-787`.
7. dispose logs ClientClosingDeltaConnection even on repeated calls. Fluid error is normalized with driverVersion; otherwise wrap error?.message or exact `Client closing delta connection`, canRetry iff argument undefined. Then perform step 6. Source: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:415-439`.

### Initial socket transport failures

For connect_error increment count first. If `context` is an object, test `context.statusText?.code === "DEPTH_ZERO_SELF_SIGNED_CERT"`; otherwise, if description object, test `description.error?.code` for same code, then flag TransportError when error.type equals that string and clear description.target. Certificate error closes nonretryably. Exceptions while extracting are swallowed. Only the description branch flags websocket transport error. If transport error AND downgrade enabled AND transports[0]!=="polling", set transports `["polling","websocket"]`; if manager reconnection disabled set enabled and reconnectionAttempts=1. If reconnection enabled and failureCount < reconnectionAttempts+1, leave handshake running. Otherwise close/reject retryably. Thus Routerlicious defaults allow the first failed websocket plus one polling-upgrade attempt, still bounded by the original handshake timer. Source: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:492-498`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:530-597`.

### Native FluidSocketIO integration boundary

The existing Swift transport is single-use Socket.IO5/Engine.IO4, JSON/default namespace/websocket only. Register all early capture, handshake and teardown handlers before starting connect; arm the Fluid handshake deadline at initialization (22000 ms for R11s) while transport connect has its own20000 ms timeout. Await transport connect **outside the inbound event handler** before emitting connect_document: JS socket.io buffers this early emit, Swift emit throws until connected. Do not start a fresh22000 ms deadline after transport connect. Each handler must hop to the container serial executor and finish without awaiting a future inbound event, because native delivery awaits handlers sequentially. For ping use emit("ping",arguments:[],ack:handler), not an event named pong; Engine.IO heartbeat belongs to the transport. Source integration boundary: `Sources/FluidSocketIO/SocketIOClient.swift:41-50`, `Sources/FluidSocketIO/SocketIOClient.swift:83-134`; oracle registration/deadline: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:482-527`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:689-697`.

Native transport has neither volatile drop semantics nor the optional JS polling-upgrade retry. Preserve the application handshake/early queues above; don't invent transport reconnection inside the document driver. Websocket-only failures are surfaced to the loader for a new connection; tests of the JS downgrade branch need a transport mock because this native transport cannot execute polling. This is an explicit integration limitation, not evidence that upstream has no downgrade branch. `Sources/FluidSocketIO/SocketIOClient.swift:41-50`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:565-591`.

### Helpers

`validateMessages` checks only `last.sequenceNumber+1 === from+length`, not every interior item. On inequality strict mode or first.sequenceNumber!==from clears array. Otherwise retain first contiguous prefix by adjacent +1 checks. Log OpsFetchViolation after mutating, with original from/start/last/length and resulting validLength, optional lastValidOpSeqNumber, strict. Empty arrays do nothing. Source: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/driverUtils.ts:125-168`.

Promise race attaches then(resolve({index,value})).catch(reject) in input order; empty input never settles. W3C scan starts at final resource and stops at index **1**, never zero. Match exact initiatorType and resource.name.includes(url). Return fields in order dnsLookupTime,w3cStartTime,redirectTime,tcpHandshakeTime,secureConnectionTime,responseNetworkTime,fetchStartToResponseEndTime,reqStartToResponseEndTime. Deltas are respectively domainLookupEnd-start, fetchStart, redirectEnd-start, connectEnd-start, connectEnd-secureStart when secureStart>0 else 0, responseEnd-responseStart iff start>0, responseEnd-fetchStart iff fetchStart>0, responseEnd-requestStart iff requestStart>0. No match leaves all undefined. Source: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/driverUtils.ts:42-117`.

## JS-semantics hazards

Keep listener registration, queue draining, promise completion and disconnect emission on the container serial executor. A task hop between removing early capture and installing consumer loses ops. Stable numeric sort retains equal-sequence arrival order and does not remove duplicates. Do not normalize Signal into arrays on the live forwarding path. Keep explicit null clientId/token distinct from absent fields. newListener fires before insertion; pong ack can be synchronous in mocks, so it can emit before newly-added listener is present. Teardown clears timers but does not cancel an already in-flight ping ack. Sources: `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:162-209`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:280-318`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:442-471`, `reference/fluidframework-3.11.0/packages/drivers/driver-base/src/documentDeltaConnection.ts:724-742`.
