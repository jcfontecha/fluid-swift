## 3. Wire and persisted formats

Schema object: `{version:1,refSeq:<nonnegative integer>,runtime:<property bag>,info?:<informational properties>}`. Desired construction order is `version,refSeq,info,runtime`; runtime order `explicitSchemaControl,compressionLz4,idCompressorMode,opGroupingEnabled,createBlobPayloadPending,disallowedVersions` (undefined omitted). Accepted runtime values: boolean features **true or undefined only**, idCompressorMode undefined/delayed/on, disallowedVersions undefined or array not containing this package version. Unknown runtime key fails; unknown root keys are not enumerated/rejected by this validator. No retired features in this source. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:63-91` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:216-304` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:325-342` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:370-408` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:693-706`

Persist in `.metadata.documentSchema`; wire upgrade is `{type:"schema",contents:<schema>}`. Incoming `contents.refSeq` is compare-and-swap expected previous schema ref, while accepted stored schema ref becomes current sequenced message number. Legacy schema retains refSeq 0; explicit summary stores document schema, legacy stores desired schema. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/messageTypes.ts:132-139` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:763-783` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:853-881`

### Concrete schema and floor contracts

Desired schema for default options is `{"version":1,"refSeq":0,"info":{"minVersionForCollab":"2.0.0"},"runtime":{"explicitSchemaControl":true,"compressionLz4":true,"opGroupingEnabled":true}}`. If upgrading this document to ID mode on at expected ref0, proposal is `{"type":"schema","contents":{"version":1,"refSeq":0,"info":{"minVersionForCollab":"2.0.0"},"runtime":{"explicitSchemaControl":true,"compressionLz4":true,"opGroupingEnabled":true,"idCompressorMode":"on"}}}`: merged runtime order is existing keys first, then previously absent desired keys. Desired construction order is **not** reapplied as canonical sorting during merge. In memory undefined-valued desired properties can be present as own keys and affect insertion order before JSON omission. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:423-485` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:693-706`

On accepting that proposal at server sequence12 store `{...proposal.contents,refSeq:12}` without changing refSeq's position; update session schema against that accepted document state. A competing op still expecting ref0 is ignored by CAS; do not validate its future feature contents as though it had won. Info is `{minVersionForCollab:<semver>}`; AND retains normalized persisted floor if info exists, else provided; OR takes greater normalized persisted/provided floor. Historical persisted 2.x prerelease `2.40.0-internal.1.0.0` normalizes to stable `2.40.0`; normalization is not applied indiscriminately to all major versions. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:438-485` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:496-504` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:853-899`

Layer generation in this pinned tree is 11, runtime→loader policy window12 months gives minimum0; runtime→datastore window3 gives minimum8. A sufficiently new generation still fails if any required feature absent; a high package semver does not waive generation/features. Loader runtime-supportedFeatures empty; datastore boundary has `encodeHandlesInContainerRuntime` and `notifiesReadOnlyState`. These are in-process Set values, not emitted JSON arrays in document schema. `reference/fluidframework-3.11.0/packages/common/client-utils/src/layerGenerationState.ts:12` `reference/fluidframework-3.11.0/packages/common/client-utils/src/layerCompat.ts:28-44` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/runtimeLayerCompatState.ts:34-111`

Load sequence verification takes real last-message metadata (lastMessage for explicit schema, message for legacy). Skip comparison when pendingLocalState supplied or metadata sequence unavailable. Otherwise if runtime sequence differs from loader initialSequenceNumber: bypass → nothing; log → SequenceNumberMismatch; close (default) → context.closeFn(DataCorruptionError("Summary metadata mismatch")). It does not unconditionally throw after calling closeFn. Poison message.sequenceNumber −1 is for older readers, not the real runtime baseline. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1154-1187`



## 4. Behavior

1. Reject providing oldestSupportedClient and deprecated minVersionForCollab together. Choose first nonundefined, else default floor **2.0.0**. Validate supported version before choosing defaults and validate explicit runtime options against floor. This checkout still supplies default even though comments elsewhere discuss later removal. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1011-1056` `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/compatibilityBase.ts:19-32`
2. At 2.0.0 defaults: grouped batching true, LZ4 compression enabled threshold 614400, ID compressor undefined/off, explicit schema control true, TurnBased flush, gcOptions empty (sweep is **not** automatically enabled for 3.x), createBlobPayloadPending undefined. Explicit validation allows payload-pending only at floor >=2.40.0; ID modes/grouping/compression/GC sweep all supported at 2.0.0 floor. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerCompatibility.ts:105-156` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerCompatibility.ts:172-202` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/compressionDefinitions.ts:40-44`
3. Undefined option values usually pick defaults via destructuring, not dictionary overwrite. Disabling grouping defaults compression to disabled; features requiring explicit control (currently createBlobPayloadPending) cannot be enabled without it. Selected effective session schema—not raw app configuration—controls what may emit. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1076-1105` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerCompatibility.ts:76-91` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1815-1823`
4. Load validates document schema version exactly 1, numeric integer nonnegative refSeq, runtime object/non-null, all runtime features supported. Document info minVersionForCollab newer than this client logs warning rather than alone rejecting; feature incompatibility is the fatal check. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:370-408` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:677-690`
5. Existing schema absent synthesizes version1/ref0 with legacy runtime bag. New document schema equals desired. Explicit mode enabled if persisted OR requested. Legacy/new clients use desired session directly. Existing explicit mode uses intersection document/desired for session and union for future upgrade. Boolean ordinary intersection is AND, union OR; explicit-control intersection is OR (sticky); id mode intersection returns persisted mode, union ranks delayed<on; disallowed versions union as insertion-ordered set for both intersection and union. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:216-291` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:709-760`
6. Before user ops, `maybeGenerateSchemaMessage` emits future schema only when not disabled and no pending proposal, marks pending. On incoming schema op, disabled-upgrade mode throws even for remote. Validate content ref not in future of document and document ref not in future of op; require document ref strictly before op. CAS mismatch returns false **before** local expectation assertions/feature check. CAS match validates schema, stores with op seq, recalculates session intersection, sets explicit true, clears future (does not recompute another upgrade), invokes onSchemaChange. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:792-803` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:835-899`

## 6. JS-semantics hazards

Undefined/off is a meaningful ID compressor setting; do not substitute generic false. Boolean property bag encodes disabled by omission, not false/null. Preserve ordering of set union for disallowed versions. Feature intersection is not a uniform boolean operation: explicit control and ID mode have sticky exceptions. Semver comparisons are numeric/prerelease-aware, not lexical. In CAS processing order matters: stale incompatible proposal must be ignored before validating its feature payload. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:216-304` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/documentSchema.ts:862-875` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1240-1242`
