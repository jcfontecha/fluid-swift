# container-runtime / blob manager

## 1. Role

Separates local handle identity from storage identity, uploads payloads, sequences attachment ops to make uploads durable, supports offline restoration, and supplies blob GC/summary state. Upload success alone is not shared durability. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:678-704` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:821-856`

## 3. Wire and persisted formats

Handle/GC path is `/_blobs/<localId>`. BlobAttach runtime envelope has type `blobAttach`, omitted contents; `localId` and storage ID `blobId` are metadata, not contents. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/messageTypes.ts:108-111` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:901-906` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:1128-1149`

`.blobs` subtree contains Attachment summary objects for unique storage IDs in redirect-map value insertion order; optional `.redirectTable` blob is JSON array of nonidentity `[localId,storageId]` entries in map order. Reader gets IDs from snapshot blob **values**, excludes redirect blob, loads array then adds storageId→storageId identity mappings. Identity entries are never serialized in redirect array but their attachment remains, allowing identity reconstruction and old storage-ID handles. Empty subtree omitted at container root. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManagerSnapSum.ts:40-84` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManagerSnapSum.ts:91-117` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2960-2965`

Live local cache states: `localOnly`/`uploading` with bytes; `uploaded`/`attaching` with bytes, storageId, uploadTime (ms), optional minTTLInSeconds; `attached` with bytes. Pending state keyed by localId serializes only attached-handle pending blobs. `blob` becomes base64; uploading→localOnly, attaching→uploaded; attached omitted. Uploaded record is spread before state/blob replacement, so preserve original field insertion order when matching bytes. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:154-225` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:1093-1119`

### Literal persisted and transport examples

A BlobAttach sends runtime content string `{"type":"blobAttach"}` with metadata `{"localId":"localA","blobId":"storageA"}` (plus batch markers/ID if applicable); it is not `{contents:{blobId,...}}`. Both IDs must be strings; extra metadata keys are allowed by the shape predicate. Blob metadata creation preserves localId then blobId. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/metadata.ts:62-73` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2234-2243` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:901-906`

Redirect map `[localA→storageA,storageA→storageA,localB→storageA]` produces this exact summary subtree:

```json
{"type":1,"tree":{"0":{"id":"storageA","type":4},".redirectTable":{"type":2,"content":"[[\"localA\",\"storageA\"],[\"localB\",\"storageA\"]]"}}}
```

Attachment keys are decimal counters starting at `0` per SummaryTreeBuilder, **not the storage IDs**. Deduplicated attachment values retain first occurrence order, then redirect blob is appended. On snapshot load the `blobs` table's attachment values are the storage IDs; keys are not identities. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManagerSnapSum.ts:40-84` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManagerSnapSum.ts:91-117` `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/summaryUtils.ts:193` `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/summaryUtils.ts:275-277`

Pending records for bytes `00 01 02` are, for example:

```json
{"localA":{"state":"localOnly","blob":"AAEC"},"localB":{"state":"uploaded","blob":"AAEC","storageId":"storageB","uploadTime":1000,"minTTLInSeconds":60}}
```

Optional TTL omits when undefined; uploadTime/storageId are required for uploaded. Dictionary local IDs follow attached-handle tracking-set order (then JS numeric-key ordering when encoded); localOnly always state then blob. Restored uploaded preserves bytes and original upload time so TTL safety is recomputed, not renewed on restore. Uploading and attaching are never persisted as those state literals. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:154-225` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:759-768` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:1093-1119`



## 4. Behavior

1. Detached create: reject already aborted signal; allocate UUID, cache uploading, use detached blob storage pseudo-ID, mark attached, redirect local→pseudo, return ordinary non-payload-pending handle. Container attach patch requires detached state; snapshot entries before adding identity entries, translate every pseudo-ID through supplied map, add identity storage mappings. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:604-621` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:1049-1071`
2. Create while Attaching waits for attached event. In Attached state legacy creation allocates UUID/localOnly, awaits upload **and attach**, then returns nonpending handle. Payload-pending feature returns handle immediately without upload; sharePayload starts once, attachGraph tracks pending handle, local get returns bytes. Notify payloadShared after success, payloadShareFailed/error after failure. `notifyFailed` sets error and emits but does not change payloadState: it remains pending, with no failed-state literal. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:582-601` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:624-662` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:112-138`
3. Upload/attach accepts only localOnly or uploaded. Check abort before beginning and again after starting aggregate unshared tracking (dirty event listener can synchronously abort). For localOnly upload, register processedBlobAttach and abort listeners before calling storage. If an old-client attach arrives or abort occurs, mark upload result irrelevant so a late createBlob callback cannot overwrite authoritative state. Upload failure discards local blob and rejects. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:678-707` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:718-781`
4. For uploaded blob, TTL unsafe iff TTL exists and `Date.now()-uploadTime > TTL/2*1000` (strict >). Unsafe resets localOnly and emits blobExpired; outer loop uploads again. Otherwise state→attaching, register listeners, send BlobAttach, wait for processed attach; abort discards/rejects; blobExpired resolves false and repeats upload loop. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:231-233` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:791-869`
5. Resubmit only when local cache state attaching. Expired resets localOnly/emits blobExpired so existing upload loop resumes; otherwise resend original metadata. Missing/unattached/unretained pending blobs are not resubmitted. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:879-898`
6. Processing BlobAttach is authoritative for local or remote old-client ack: any cached state becomes attached; clear attached-pending/pending-only sets; write local→storage and storage→storage mappings; **then** clear aggregate unshared work (listener can now resolve ID), **then** emit processedBlobAttach. Preserve this order even if a listener throws. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:901-931`
7. Get verifies not deleted, notifies GC requested (may throw tombstone), then returns cached bytes if present. Else redirect to storage. Unknown ID asserts unless incoming handle is payload-pending; pending handle waits for matching processedBlobAttach indefinitely, including when local feature disabled. Never invent timeout as success or 404; source wait can remain unresolved if sender disappears. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:514-566`
8. Pending restoration resumes sharing only after runtime connected and not read-only; blob manager snapshots pending-only IDs, clears set, starts upload/attach promises concurrently and waits all. Capture only pending handles reachable by attachGraph; don't serialize every local cache entry. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5839-5860` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:1080-1119`
9. Sweep removes local redirects and collects possible unused storage IDs; scans remaining nonidentity redirects to remove still-referenced storage IDs from candidate set; removes leftover identity mappings so next summary drops attachments. Source has a known dedup hazard: a legacy identity handle still in use can lose its mapping when distinct local-ID references are removed. Faithful port must not silently change oracle behavior. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:975-1015`

## 6. JS-semantics hazards

TTL units are seconds for driver TTL but milliseconds for Date and persistence. Promise/listener races with authoritative attach must not resurrect old uploading state. Base64 operates on raw bytes, never Swift textual encoding. Map→array and Set(value) ordering affects redirect blobs/attachment ordering. Handle graph attachment and payload sharing are independent flags; a handle can be reachable while payload pending. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:231-233` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:736-780` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManagerSnapSum.ts:91-117` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:122-138`
