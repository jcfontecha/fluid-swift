# container-runtime / datastore routing, envelopes and signals

## 1. Role

Dispatches logical messages to datastore contexts without conflating runtime batching with DDS batching, resolves handle/alias routes, and routes unsequenced signals to container, datastore or extension listeners. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:934-1044` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3804-3865`

`ChannelCollection` owns datastore contexts, aliases, creation/attach, request handling, processing/resubmit/stash/rollback and GC route updates. ## 3. Wire and persisted formats

Datastore op is `{type:"component",contents:{address:<datastoreId>,contents:{type:<datastore message type>,content:<payload>}}}`. Each layer strips exactly its envelope. Attach is `{type:"attach",contents:{id,snapshot,type}}`, where snapshot is converted ITree from datastore attach summary with added GC data blob. Alias is `{type:"alias",contents:{internalId,alias}}`; `.aliases` summary is ordered alias/internal-ID entry array. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/messageTypes.ts:88-103` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:986-1025` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:640-655` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/dataStore.ts:30-38` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2948-2951`

Container signal envelope is `{contents:{type,content}}`, datastore signal adds `address:<storeId>`; signal tracking may add `clientBroadcastSignalSequenceNumber`. Target client is supplied separately to loader, not a sequenced op. Extension signal envelope is `{address:"/ext/<extensionId>/<addressChain joined by slash>",contents:<outbound extension message>}`, with extension message's target forwarded separately too. Inbound listener payload is `{clientId,content,type,targetClientId}`; clientId may be null for server signals. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4293-4298` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1835-1860` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3811-3817` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/signalTelemetryProcessing.ts:198-208`

### Concrete routing and signal vectors

A datastore message of type `op` with arbitrary DDS payload `{"address":"ddsA","contents":{"n":1}}` addressed to storeA becomes:

```json
{"type":"component","contents":{"address":"storeA","contents":{"type":"op","content":{"address":"ddsA","contents":{"n":1}}}}}
```

Runtime strips component; channel collection strips storeA and `type:"op"`/`content`; only that content goes to datastore runtime with original per-element local metadata and logical CSN. Alias request is `{"type":"alias","contents":{"internalId":"storeA","alias":"root"}}`, later summary `.aliases` = `[["root","storeA"]]`. Attach shape is `{type:"attach",contents:{id:string,snapshot:ITree,type:string}}`: the two type keys are different layers; the concrete ITree example below supplies entry fields. Snapshot is ITree entries, not an ISummaryTree object; generator appends `.gcdata` blob containing datastore attach graph before conversion. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:640-655` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:986-1044` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/dataStore.ts:30-38`

Container broadcast `submitSignal("cursor",{x:1})` emits `{"contents":{"type":"cursor","content":{"x":1}},"clientBroadcastSignalSequenceNumber":1}` if it is the first broadcast. Targeted form uses `{"contents":{"type":"cursor","content":{"x":1}}}` and separate targetClientId argument, without incrementing broadcast counter. Extension `presence` with empty addressChain emits address `/ext/presence/` (trailing slash intentional), so receiver suffix is `[""]`, **not** empty array. Example targeted extension payload `{"address":"/ext/presence/room","contents":{"type":"cursor","content":{"x":1},"targetClientId":"peer"}}` forwards peer separately; on receive authoritative target comes from outer transport `message.targetClientId`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1835-1860` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3804-3865` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4293-4298` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/signalTelemetryProcessing.ts:203-207`

With source client c, inbound listener sees `{clientId:"c",content:{x:1},type:"cursor",targetClientId:undefined}` in that insertion order, then receives local boolean as separate callback argument. Server signal uses clientId null. General signal envelope missing address emits at container; address `""` routes to missing datastore (not container). Slash path not handled by registered extension is dropped, not rerouted into datastore or treated as reliable op. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3811-3867`



Attach snapshot conversion is recursive in Object.entries order: string blob→BlobTreeEntry(path,contents,"utf-8"), binary blob→base64 encoding, tree→TreeTreeEntry with nested ITree, attachment→AttachmentTreeEntry; a summary Handle throws `Should not have Handle type in summary tree`. ITree output fields are `entries`, optional `unreferenced`, optional `groupId`; blob entry's fields are parameter property `path`, then `mode:"100644"`, `type:"Blob"`, `value:{contents,encoding}` in the pinned ES2022 class-field order; tree entries have path/value parameter properties followed by mode/type initializers. Attachment entry fields are `path,id,mode,type,value` where value is `{id}`; tree fields are `path,value,mode,type`, mode `"040000"`, type `"Tree"`. Field order is not used for dispatch, but is preserved by stringify. Minimal blob-only snapshot example is `{"entries":[{"path":".gcdata","mode":"100644","type":"Blob","value":{"contents":"{\"gcNodes\":{\"/\":[]}}","encoding":"utf-8"}}]}`. Real datastore attach also includes its attributes and DDS trees in their generated order; the GC entry is appended last. Old attach readers allow no snapshot or no `.gcdata`, returning no initial GC edges. `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/summaryUtils.ts:415-482` `reference/fluidframework-3.11.0/packages/loader/driver-utils/src/blob.ts:13-73` `harness/node_modules/@fluidframework/driver-utils/lib/blob.js:10-68` `reference/fluidframework-3.11.0/packages/common/driver-definitions/src/protocol/storage.ts:25-29` `reference/fluidframework-3.11.0/packages/runtime/runtime-definitions/src/garbageCollectionDefinitions.ts:35`

## 4. Behavior

### Logical batch dispatch and events

After pending correlation runtime updates dirty state, emits batchBegin at beginning, adjusts logical messages' minimum/processed client sequence numbers, groups contiguous messages of same runtime type, dispatches those groups, then emits logical op events. batchEnd emits in finally with caught error and last message. Do not emit op for intermediate chunks. Grouped batch messages share server sequence but not logical CSN; retain local metadata per element. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3560-3673` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3747-3750`

Channel collection further bunches contiguous component messages with identical datastore address AND datastore message type. On either change dispatch preceding bunch, passing stripped payloads and corresponding local metadata/CSNs; flush last bunch. A deleted context's op is logged/ignored; unknown nondeleted context throws `No context for op`. Each accepted op updates GC usage and scans encoded handles for outbound references. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:959-1044`

Handle scan recursively visits object entries, records serialized handle URLs, takes the first `address` property encountered as DDS address, and reports routes from `["",storeId,ddsAddress].join("/")`. Preserve this source heuristic rather than assuming all handles originate at datastore root. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:1717-1753`

### Datastore attachment, aliases and lookup

Locally visible attached-container store submits attach before setAttachState(Attaching), then binds context. Detached container only binds; store appears in later attach summary. Attach snapshot fields are id,snapshot,type. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:640-687`

Alias first claimant wins: alias already in map OR existing context ID is conflict. Unknown/deleted target fails. Success first adds root→store GC reference when timestamp available, then alias map, aliased-store set, in-memory-root flag. Local trySetAlias rejects slash and staging, caches ongoing result for same alias instead of sending another request. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:597-634` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/dataStore.ts:76-90`

Get-store checks deleted status first (404 deleted header), then bound/remoted context with wait option; missing context 404. get-if-available returns undefined for both deleted/missing instead. Handle resolver strips legacy `_channels`, recognizes leaf `_blobs/<id>`, honors payloadPending and wait:false; it does not equate legacy wire route `_channels` with persisted `.channels`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:1047-1105` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2840-2858`

### Signals and extensions

1. Verify open on submit. Broadcast (target undefined) gets monotonically incremented client broadcast signal number for telemetry; targeted signals do not. General submit rejects addresses beginning slash; extension submit is the intentional separate slash-addressed path. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1835-1860` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4293-4298` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/signalTelemetryProcessing.ts:198-208`
2. Receive transforms payload; self signal telemetry runs before routing. No address emits container signal and returns. Address without initial slash routes to datastore with adjusted `{content:{address,contents:<payload>}}`; slash address splits into path parts and `/ext/<id>/...` calls registered extension processSignal with suffix. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3804-3865`
3. Missing remote datastore signal may be pre-attach: log and drop. Missing local datastore signal asserts `0x163`. Deleted datastore signals are dropped; existing datastore receives stripped signal. Signals are not put in outbox/pending op replay. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:1177-1201` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1835-1860`
4. Extension acquisition validates host generation/features before construction. Missing extension constructs via factory only when injection allowed. Existing instance short-circuits with factory instanceof identity; otherwise compare exact version and capability superset. Older requested version or injection-disallowed delegates mismatch to existing extension; newer/more-capable requested version delegates prior-instance migration to new factory. On reuse call onNewUse, then return interface. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5986-6063`
5. Extension host events use connectedToService/disconnectedFromService/operabilityChanged when loader supports connection state; legacy fallback translates connected to joined(canWrite:true) and disconnected. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5898-5913`

## 5. Invariants and asserts

`0xa66` bunched context still exists; missing context op is fatal while missing remote signal is allowed. `0x163` missing local signal context is impossible. `0xa31/0xa32` event batches have key message; empty groups are given a representative key before event handling. ## 6. JS-semantics hazards

Envelope keys distinguish `contents` (runtime routing) and `content` (datastore/signal payload). Preserve missing address vs empty string: only undefined selects container signal; empty string still routes datastore. Slash splitting keeps empty segments, including trailing extension segment. Preserve contiguous batching (never regroup all same-store messages across other stores). Handle traversal uses JS object-entry order and first-address wins; missing DDS address becomes empty join field, not Swift optional debug text. Synchronous callbacks can throw; batchEnd must still occur. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3828-3865` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:1014-1044` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/channelCollection.ts:1726-1753` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3664-3673`
