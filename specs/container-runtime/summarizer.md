# container-runtime / summarizer and summary trees

## 1. Role

Coordinates elected interactive parents and dedicated summarizer clients, schedules summaries, tracks proposal/broadcast/ack, and creates incremental summary trees without racing incoming changes. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryManager.ts:197-257` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4688-4725`

## 2. Surface used by other packages

`summaryManager` creates/runs/stops a summarizer; runtime exposes `summarize`, `submitSummary`, on-demand/enqueued requests and ack refresh; `SummarizerNode` tracks per-subtree changed state and reusable handles, with GC-aware node subclass. Results are three staged promises: submitted, broadcast, ack/nack. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5868-5891` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summaryGenerator.ts:243-244` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summaryGenerator.ts:292-297` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summaryGenerator.ts:339-361` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerNode/summarizerNode.ts:189-246`

## 3. Wire and persisted formats

### Root layout and byte strings

Datastore summaries are always wrapped under `.channels`; output tree insertion starts with that wrapper, then container state adds `.metadata`, `.idCompressor` if loaded, `.chunks` if partial, `.recentBatchInfo` if detector returns state, `.aliases` if nonempty, `.electedSummarizer` if election exists, `.blobs` if nonempty, `gc` if GC returns summary. **GC key is `gc`, not `.gc`.** `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryFormat.ts:276-281` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2924-2970` `reference/fluidframework-3.11.0/packages/runtime/runtime-definitions/src/garbageCollectionDefinitions.ts:11`

`.metadata` is JSON in construction order: creation metadata spread (`createContainerRuntimeVersion?`, `createContainerTimestamp?`), `summaryNumber` (postincrement), `summaryFormatVersion:1`, GC metadata spread, `telemetryDocumentId`, `message`, `lastMessage`, `documentSchema`. GC spread emits `gcFeature`, `gcFeatureMatrix?`, `sessionExpiryTimeoutMs?`, `sweepEnabled:false`, `tombstoneTimeoutMs?`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2902-2921` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/gc/garbageCollection.ts:905-916`

With explicit schema control, `message` is `{sequenceNumber:-1}` to fail older clients' sequence check, and `lastMessage` is real metadata; without it real message goes in `message`, `lastMessage` absent. Extract real message in order `clientId,clientSequenceNumber,minimumSequenceNumber,referenceSequenceNumber,sequenceNumber,timestamp,type`; use current last message or previous summary's saved message. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2888-2918` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryFormat.ts:185-198`

`.electedSummarizer` JSON order: `{electionSequenceNumber,electedClientId?,electedParentId?}`. Historical `electionSequenceNumber` actually stores latest summary-ack sequence seen for incumbent, else election sequence; parent-only changes preserve baseline. `.aliases` is array of alias→internal-ID pairs; `.chunks` array of client→string-array pairs; ID/blob/GC specs define other root fields. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerClientElection.ts:343-348` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2937-2957`

Summary upload context: `{proposalHandle:<last acked proposal or undefined>,ackHandle:<last ack or loaded version>,referenceSequenceNumber}`. Summarize op contents, in order: `{handle,head:parent,message:"Summary @<ref>:<min>",parents:parent===undefined?[]:[parent]}`. Missing head is omitted by stringify. Ack/nack correlation uses `contents.summaryProposal.summarySequenceNumber` (proposal's **server sequence**, not reference sequence). `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4794-4797` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4980-5004` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryCollection.ts:462-488`

Legacy readers: absent root metadata means version 0/nonisolated; metadata's `disableIsolatedChannels` controls root lookup. Datastore `.component` attributes support unversioned pkg string, `snapshotFormatVersion:"0.1"` with JSON-array pkg string, and `summaryFormatVersion:2` with isolation unless disabled. Do not infer datastore isolation from root alone because handle-reused stores may retain old format. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryFormat.ts:38-119` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryFormat.ts:200-240`

### Concrete summary blobs and protocol records

For an explicit-schema document created at timestamp 1000, telemetry ID `doc`, next summary number 1, GC disabled, and last processed op c/CSN7/sequence10 at timestamp2000, a metadata blob can be the following exact string (fields whose values are undefined omit):

```json
{"createContainerRuntimeVersion":"3.11.0","createContainerTimestamp":1000,"summaryNumber":1,"summaryFormatVersion":1,"gcFeature":0,"sweepEnabled":false,"telemetryDocumentId":"doc","message":{"sequenceNumber":-1},"lastMessage":{"clientId":"c","clientSequenceNumber":7,"minimumSequenceNumber":5,"referenceSequenceNumber":9,"sequenceNumber":10,"timestamp":2000,"type":"op"},"documentSchema":{"version":1,"refSeq":0,"info":{"minVersionForCollab":"2.0.0"},"runtime":{"explicitSchemaControl":true,"compressionLz4":true,"opGroupingEnabled":true}}}
```

This example disables session expiry, hence omits its/tombstone timeouts. With legacy explicit-control off, remove `lastMessage` and put that real message in `message`. With no current or remembered last message, explicit mode still emits poison `message` but omits `lastMessage`; legacy mode omits `message`. Summary number is emitted old value and then incremented, even if upload fails. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2888-2921` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/gc/garbageCollection.ts:905-916` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryFormat.ts:185-198`

Other root blob examples: `.electedSummarizer` = `{"electionSequenceNumber":12,"electedClientId":"summaryChild","electedParentId":"c"}`; no identities = `{"electionSequenceNumber":12}`. `.aliases` = `[["root","storeA"]]`; `.chunks` = `[["c",["partial"]]]`; `.recentBatchInfo` = `[[10,"c_[7]"]]`. Empty aliases/chunks/recent maps omit their blobs; the election blob can exist without IDs. `.idCompressor` is a JSON **string literal** containing base64. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerClientElection.ts:343-348` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2932-2957`

Root representation uses SummaryType numbers Tree=1, Blob=2, Handle=3, Attachment=4. A minimal GC-disabled root is structurally `{"type":1,"tree":{".channels":{"type":1,"tree":{}},".metadata":{"type":2,"content":"<the metadata string>"}}}`. The angle-bracket text here denotes the complete blob string above, not literal serialized content. Blob/GC examples specify their subtrees. `.channels` holds datastore-ID keys and datastore trees/handles; each modern datastore tree contains `.component` attributes and its own `.channels` containing DDS-ID trees. Do not flatten these two isolation levels. `reference/fluidframework-3.11.0/packages/common/driver-definitions/src/protocol/summary.ts:26-69` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryFormat.ts:242-281`

For upload handle `p1`, loaded/acked parent `a0`, captured reference10/min5, proposal contents are exactly `{"handle":"p1","head":"a0","message":"Summary @10:5","parents":["a0"]}`. With no parent, omit head and use `parents:[]`. Ack payload is `{handle:string,summaryProposal:{summarySequenceNumber:number}}`, e.g. `{"handle":"a1","summaryProposal":{"summarySequenceNumber":11}}`. Nack payload is `{summaryProposal:{summarySequenceNumber:number},code?:number,message?:string,retryAfter?:number}`, e.g. `{"summaryProposal":{"summarySequenceNumber":11},"code":429,"message":"retry","retryAfter":2}`. Server field insertion order is not constrained by this reader; correlation ignores JSON field order and uses proposal sequence11, not reference10 or ack sequence12. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4980-5004` `reference/fluidframework-3.11.0/packages/common/driver-definitions/src/protocol/protocol.ts:447-498` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryCollection.ts:462-502`

Legacy datastore attributes are literally `{"pkg":"package","isRootDataStore":true}` (v0), `{"pkg":"[\"package\"]","snapshotFormatVersion":"0.1","isRootDataStore":true}` (v1), or `{"pkg":"[\"package\"]","summaryFormatVersion":2,"isRootDataStore":true}` (v2). Attribute reader accepts optional root flag; old absent flag preserves old root behavior. V2 may have `disableIsolatedChannels:true`; absent root `.metadata` uses unisolated datastore trees excluding reserved tree names `.protocol`, `.logTail`, `.serviceProtocol`, `.blobs`, `gc`, `.idCompressor`. These are accepted read layouts, not a reason to emit v0. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryFormat.ts:38-119` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryFormat.ts:221-242`



## 4. Behavior

### Election and ownership

- Eligible clients: interactive or type summarizer; old missing details is eligible in helper. Pick oldest eligible interactive parent by smallest join sequence, and oldest summarizer child if present as incumbent. Successor picks first eligible parent younger than prior parent's retained join sequence, wrapping oldest. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerClientElection.ts:29-33` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerClientElection.ts:112-118` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerClientElection.ts:284-340`
- Eligible added summarizer replaces interactive incumbent, retaining parent; if parent missing, added interactive fills it. Removing incumbent chooses parent (or next parent if it was also parent); removing only parent retains incumbent child and elects successor parent. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerClientElection.ts:120-157`
- An incumbent change resets election sequence and last-ack baseline; parent-only change does not. Store new state before `electedSummarizerChanged`. Ack updates progress baseline. Excess ops without summary **log only**; they do not rotate a live election. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerClientElection.ts:159-186` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerClientElection.ts:240-267`
- Manager states Off→Starting→Running→Stopping→Off. Parent must be current client, connected, and before Running also incumbent client. While Starting/Stopping, election refresh waits; late stop intent must be replayed after async creation. Stop has two-minute forced cleanup; generation token prevents late cleanup from corrupting a replacement instance. Cleanup closes child, removes listeners and restarts if still eligible. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryManager.ts:197-257` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryManager.ts:300-335` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryManager.ts:376-438`
- Startup uses throttler plus initial delay unless op threshold bypasses it; waiting races timer against ops threshold and removes listener. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryManager.ts:446-499`

### Election restore and recovery predicates

Serialized restore first accepts a recorded parent only if still a quorum member and eligible. Missing electedClientId preserves absent election until the next ordinary-op handler. Recorded incumbent absent from quorum logs InitialElectedClientNotFound, leaving incumbent undefined. Eligible incumbent restores; if it is not a summarizer and parent absent, make incumbent parent. Ineligible incumbent chooses next eligible parent with join sequence strictly greater than that member; **no wrap in this constructor fallback**. Ordinary op when incumbent absent resets from current quorum. Every accepted summaryAck updates progress sequence, not just acks attributed by client ID. Transition with unchanged parent+incumbent returns with no event; changed incumbent resets progress, changed parent alone preserves it; update fields, emit telemetry, recover if incumbent undefined, then emit electedSummarizerChanged. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerClientElection.ts:159-186` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerClientElection.ts:189-267`



### Manager asynchronous transitions

Off with shouldSummarize true sets Starting before any await (`0x261`, no prior summarizer `0x262`) and captures cycle generation. After startup delay: disposed → early exit; if initial-delay mode was used and now ineligible → early exit. Otherwise assert still Starting (`0x263`) and set Running **before** awaiting child creation. Assign created child, wire forwarded events, replay pendingStopReason and clear it. Recheck eligibility: if false and either initial delay was used or stop reason is not parentNotConnected, set Starting, stop child and exit; otherwise run last attempt despite current ineligibility. Child run uses latest parent client ID. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryManager.ts:260-335` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerUtils.ts:40-48`

Stopping is entered only from Starting/Running; store stop reason, call optional child.stop, replace two-minute timeout. Timeout cleans up only if still Stopping **and child exists**; it cannot force-clear an unresolved child-creation promise with no instance. Finalizer checks captured generation equals current; stale cycles log and return. Cleanup increments generation, sets Off, clears pending reason/timer, removes forwarded listeners, closes child, clears child pointer, then restarts if eligible. This ordering makes late run completion harmless after timeout restart. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryManager.ts:376-438`



### Heuristics and retries

Default heuristic configuration: min idle 0ms, max idle 30000ms, max time 60000ms, max weighted ops 100, last-summary minimum 10, ack wait 180000ms, runtime weight 1, nonruntime weight .1. Effective config may be overridden; preserve disabled/disableHeuristics/summaryOnRequest modes rather than always electing automatically. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryHelpers.ts:35-59` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerTypes.ts:809-835`

On heuristic run, evaluate max-time first (`elapsed > maxTime`), then weighted ops (`rWeight*rCount+nWeight*nCount > maxOps`); otherwise restart idle timer. Idle interval linearly decreases from maxIdle to minIdle with `weighted/maxOps`, capped at min for ratio >=1. Never start if reference-sequence delta from last successful summary <=0. Last summary requires weighted count >= configured minimum. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summarizerHeuristics.ts:118-186` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summarizerHeuristics.ts:197-242`

At attempt capture reference/time and current counters/size. Ack retires only captured counts, leaving ops received during attempt pending; clears missing-op-data marker. One summary action runs at a time; heuristics may defer another attempt. Retry only when retryAfterSeconds supplied, positive value sleeps seconds×1000. Failure stage changes attempt cap: default 2, pre-submit failure 5 (config may lower submit cap); one final attempt is distinguished. Nack carries retryAfter; no fixed unconditional retry loop. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summarizerHeuristics.ts:75-100` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/runningSummarizer.ts:731-879` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summarizer.ts:54-59`

### Summary transaction

1. Refuse a nonempty outbox. If op-dirty, wait for internal opsSaved (not aggregate blob dirty) or timeout, clean listeners, then apply pending-op failure policy. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4711-4775`
2. Pause inbound ops; by default pause inbound signals too. Capture reference/minimum sequence and prior ack context only **after** pause. Start root summarizer-node WIP at that reference. Revalidate cancellation, stable last sequence and unchanged ack context across awaits. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4779-4803` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4834-4871`
3. Run GC as configured, collect datastore summaries, wrap `.channels`, load delayed compressor before writing container state, and validate summarizer-node participation; apply the pending-op policy again after generation. Nonfinal pending-op attempts return base-stage failure; finalAttempt logs the condition but deliberately continues. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4381-4388` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4884-4931`
4. Update saved last message; compute stats; upload tree with previous ack context. Recheck continuation after generation and upload. Submit summarize op with captured reference, then `completeSummary(uploadHandle)` to remember pending node state. Return `stage:"submit"`; failures return base/generate/upload stage with accumulated data, not a successful result. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:4933-5047`
5. In `finally`, clear WIP; record summary attempt **before** inbound resume, then resume op and optional signal queues. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5048-5059`
6. Generator resolves submitted, waits for proposal broadcast and then ack/nack with cancellation/deadline races. Ack marks heuristic success then awaits runtime ack refresh before resolving final success (next summary cannot outrun state adoption). Nack resolves failure with retriable error and retryAfter. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summaryGenerator.ts:243-327` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summaryGenerator.ts:339-388`

### Exact retry and deadline transitions

Attempt state starts `maxAttempts=2,currentAttempt=0,status=success`. Increment count; if canceled, status=canceled and exit without invoking generator. Otherwise invoke generator with `finalAttempt:false`, await ack result. Success exits loop; failure awaits submitted result to select cap 2 if submitted or configured submit-failure cap (default5) otherwise. Emit failed `summarize` event before delay. Set loop done when retryAfter missing OR currentAttempt>=cap−1. Even when loop done, a positive retryAfter still incurs its delay. RetryAfter=0 is defined and retriable with no sleep. After loop success/cancel emits one corresponding `summarize` and returns. Failure with defined retryAfter runs exactly one extra attempt with incremented count and `finalAttempt:true`, then emits `summarize` for it. Remaining failure remembers final error and invokes stop callback `failToSummarize`; no unconditional retry follows. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/runningSummarizer.ts:784-910`

Pending-op policy before and after generation: clean → continue; dirty and nonfinal → `{stage:"base",referenceSequenceNumber,minimumSequenceNumber,error:RetriableSummaryError("PendingOpsWhileSummarizing",delayMs/1000; default delayMs=1000)}`; dirty and final → log `PendingOpsDuringSummaryFinalAttempt` and continue. Aggregate blob work alone is not this predicate. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5074-5125` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:662`

One pending-ack timer starts **before broadcast wait** and the same timeout promise is used for ack wait; do not grant a fresh full deadline after broadcast. Broadcast timeout and ack timeout produce retryAfterSeconds=0, cancellation produces disconnect failure without that retry delay. After broadcast promise resolves, store proposal server sequence in lastAttempt. On ack: mark last attempt successful → successful-summary callback → telemetry end → await runtime refresh → resolve final success. Nack resolves remaining failure stage with retryAfter copied from server (undefined is different from zero). Always clear timers on exit. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summaryGenerator.ts:265-390`



### Collection and incremental adoption

Collection watches by clientId/CSN until broadcast, then tracks proposals by server sequence. Ack consumes matching proposal, only updates latest ack/emits when proposal sequence newer than last; unknown ack logs when newer than initial load sequence but is ignored. Ack/nack may have JSON payload in `op.data` instead of contents; accept both. `waitSummaryAck(ref)` loops until latest ack proposal reference >= requested ref. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryCollection.ts:373-415` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryCollection.ts:436-502`

Tracked node summarize reuses tree handle only if handle reuse enabled, !fullTree, !changed and prior summary reference exists; mark skip-recursion. Otherwise pass incremental context `{summarySequenceNumber,latestSummarySequenceNumber,summaryPath}` if previous baseline exists. Untracked summarize calls implementation directly without WIP. Complete recursively remembers proposal reference; new child under a skipped parent without a prior baseline cannot get a reusable handle. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerNode/summarizerNode.ts:189-246` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerNode/summarizerNode.ts:343-371`

Ack refresh may not run during WIP. A tracked pending proposal advances node baseline and GC state; an untracked newer ack forces runtime latest-snapshot verification/stop rather than pretending local state can safely reuse that remote tree. GC-aware changed checks include sorted used-routes string equality; reference state alone can invalidate handle reuse. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerNode/summarizerNode.ts:392-425` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5639-5672` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5771-5777` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerNode/summarizerNodeWithGc.ts:456-500`

### Incremental node state transitions

Node changed predicate is recorded change sequence > last successful reference; invalidation only raises recorded sequence, never lowers it. Tracked summarize sets wipSummarizeCalled **before** reuse check. Reused tree is `{type:3,handle:<summaryHandleId>,handleType:1}` with handle count1. Unreused incremental context at WIP ref20 and prior baseline10 is `{summarySequenceNumber:20,latestSummarySequenceNumber:10,summaryPath:<summaryHandleId>}`—despite names, both values here are reference sequences, not proposal op sequences. FullTree passes no incremental context. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerNode/summarizerNode.ts:189-246` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerNode/summarizerNode.ts:492-508`

Validate participation: a child skipped by a reused parent need not have summarize called; otherwise each node must have wipSummarizeCalled or validation fails. Completion visits children first (skip flag OR parent skip), then writes pendingSummaries[proposalHandle]={referenceSequenceNumber:wipRef}, replacing same-handle pending state, then recursively clears WIP. If skipped parent's child never had a baseline, clear its WIP and do not create reusable pending state. Failure/finally clear WIP without advancing latest baseline. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerNode/summarizerNode.ts:296-381`

Refresh rejects active WIP before changing anything. Set isSummaryNewer by requested ref > current ref; independently find proposal handle in pending. If found, mark tracked, recursively adopt that pending ref, remove matched proposal plus all pending entries with lower ref (not equal-ref alternatives), update latest successful ref, and refresh children. Missing child's pending record is allowed only if it never had a prior summary (`0x1a6`); matched references must agree (`0x1a7`). GC node used-routes are default-sort-mutated before storing; referenced iff routes includes empty string OR slash. A change of sorted used routes makes a node changed unless GC disabled. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerNode/summarizerNode.ts:414-485` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerNode/summarizerNodeWithGc.ts:456-500`

Collection nack looks up proposal server sequence; found → settle nack promise, delete pending, emit summaryNack. Unknown nack does nothing. Unlike ack, nack never advances latest ack or wakes next-ack waiters. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryCollection.ts:505-512`

## 6. JS-semantics hazards

Date.now is milliseconds; heuristic > versus >= boundaries differ. Promise settlement ordering is observable: ack result waits for refresh; attempt accounting happens before resume. IDs/election maps retain insertion order for ties (strict smaller-sequence comparisons). Undefined election IDs/metadata fields omit, not null. Summary-number increments on metadata construction, not ack: failed generations can consume numbers. Handle reuse must preserve old subtree encoding, not rewrite it gratuitously. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summarizerHeuristics.ts:197-234` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summaryGenerator.ts:339-361` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5052-5059` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summarizerClientElection.ts:309-348` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2902-2918`
