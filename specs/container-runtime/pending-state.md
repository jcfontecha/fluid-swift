# container-runtime / pending state, reconnect and stashed operations

## 1. Role

`PendingStateManager` separates initial stashed messages, live pending messages, and saved already-acked ops needed to restore a client from an older snapshot. It correlates local acks and rejects forked pending state. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:387-419` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:645-668`

`onFlushBatch`, `onFlushEmptyBatch`, `processInboundMessages`, `applyStashedOpsAt`, `replayPendingStates`, `getLocalState`, pending/dirty queries, and staged-batch popping. ## 3. Wire and persisted formats

Pending record (declaration and emission order): `{type:"message",referenceSequenceNumber,content,runtimeOp,localOpMetadata,opMetadata,batchInfo}`; `sequenceNumber?` is later stamped on ack. `content` is serialized runtime envelope; `opMetadata` is wire metadata; local metadata is DDS-owned ack/resubmit/rollback state. Shared per-batch object is `{clientId,batchStartCsn,length,staged}`. Unsent batch uses random UUID and CSN −1. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:42-92` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:505-544`

Serialization removes `runtimeOp` and `localOpMetadata` by setting undefined (JSON omits); retain `content`. Old stash without `batchInfo` is accepted and patched `{clientId:uuid(),batchStartCsn:-1,length:-1,staged:false}`. This sentinel length skips batch length validation. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:245-252` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:1037-1047` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:805-811`

Outer runtime stash: `{pending:{pendingStates:[...]},pendingIdCompressorState?,pendingAttachmentBlobs?,sessionExpiryTimerStarted?}` in that order. Pending list is saved ops strictly newer than supplied snapshot sequence, followed by serialized live pending ops. Pending reference sequence older than snapshot throws. Compressor uses session-inclusive serialization; blobs use their own base64 records. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5806-5825` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:387-419`

### Concrete stash example

For an offline singleton `rejoin` at reference 10, using UUID `00000000-0000-4000-8000-000000000001`, capture emits this object (before an outer loader serializes it):

```json
{"pending":{"pendingStates":[{"type":"message","referenceSequenceNumber":10,"content":"{\"type\":\"rejoin\"}","batchInfo":{"clientId":"00000000-0000-4000-8000-000000000001","batchStartCsn":-1,"length":1,"staged":false}}]}}
```

`opMetadata` is omitted here because it is undefined. With metadata it appears after `content` and before `batchInfo`. On acknowledgment at sequence 12, `sequenceNumber:12` is appended after batchInfo in the saved record. A capture with snapshot 11 includes that saved record, snapshot 12 excludes it. A pending record at reference 10 with snapshot 11 throws rather than silently filtering it. The runtime object always contains pending, even with empty `pendingStates`; optional compressor/blob/expiry values omit on JSON serialization. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:245-252` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:387-419` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:519-543` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:723-726` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5815-5825`

Empty replay record has `content:"{\"type\":\"groupedBatch\",\"contents\":[]}"`, `opMetadata:{"batchId":"c_[7]","groupedOpCount":0}`, and batchInfo length **1**, although the wire group has zero elements. Stash reload detects emptiness by parsed content, regenerates local metadata `{emptyBatch:true}`, and never invokes a DDS apply callback. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opGroupingManager.ts:94-111` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:164-167` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:551-600`

`sessionExpiryTimerStarted` is epoch milliseconds, selected by nullish-coalescing caller prop over GC's original timer start; capture is not a new expiry lease. `pendingIdCompressorState` is a base64 string (not a JSON compressor object); `pendingAttachmentBlobs` maps local IDs to the literal records in the blob spec. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5809-5819` `reference/fluidframework-3.11.0/packages/runtime/id-compressor/src/idCompressor.ts:988`

## 4. Behavior

### Flush and acknowledgment

1. Register raw batch after send or offline flush, one record per logical op (not one per chunk/wire message). All share the same batch-info object; staged must not have a sent CSN. Empty batch registers one placeholder. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:489-544`
2. At local batch begin require pending head and nonstaged. Compare original start CSN, known batch length (empty inbound means expected pending length 1), and explicit IDs; discrepancies are **telemetry only**. Do not promote them to fatal validation. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:788-843`
3. For each local op stamp sequence number on pending head, append serializable copy to saved ops, pop pending head, then reconstruct incoming string as `JSON.stringify({type,contents})` and compare **exact string equality**. On mismatch log diagnostic and throw `pending local message content mismatch`; return pending local metadata on success. Empty batch consumes placeholder without payload compare and returns no logical messages. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:678-779`
4. Remote batch start whose effective ID equals pending head's effective ID throws forked-container error, even if actual client IDs differ. Other remote messages receive no local metadata. Runtime duplicate detection runs before pending correlation. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:620-668` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3400-3454`

### Stashed-op application

1. Constructor enqueues `pendingStates` and opens applying lifecycle eagerly when nonempty. Runtime stays read-only through application; this is not an application-controlled edit transaction. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:457-477` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3017-3035`
2. `applyStashedOpsAt(seq)` stops if head reference > seq, throws if < seq, applies only exact matches; undefined seq means drain all. Shift each record; empty batch gets `{emptyBatch:true}` and is requeued without applying. Otherwise await runtime apply callback; attached clients regenerate local metadata and parse `content` into `runtimeOp`, patch legacy batch info, enqueue pending. Detached application requires undefined local metadata and does not enqueue live pending. Failures wrap as data-processing error. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:551-600`
3. Only after successful full initial-queue drain flip applying→ended, then synchronously fire `onAfterStashedOpsApplied` once. Failures are fatal load failures; lifecycle is not “recovered” by reopening/closing. Loader replay notifications apply stash at the corresponding sequence. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:603-611` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3343-3345`
4. Runtime apply delegates component/attach/alias to channel collection; idAllocation is ignored because tip compressor state is already restored; schema and blobAttach are ignored. Rejoin throws; GC stashing throws; unknown closes and throws. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3075-3120`

### Reconnect/resubmit

1. Require initial stash fully drained; must be connected except staged commit. Same clientId must not replay twice (staged commit exempt). Snapshot pending queue count before replay; consume **only that original count**, since callbacks append reconstructed ops to the same queue. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:853-889`
2. Runtime suppresses dirty events, resets compressor unfinalized range cursor, invokes replay, restores dirty bookkeeping in `finally`, then emits final dirty transition if changed. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3037-3061`
3. Preserve distinct original batch boundaries. Compute effective batch ID before resubmitting. Empty marker calls resubmit with empty array; singleton absent marker calls once; true marker collects until false, rejecting nested begin/missing end. Use original staged and squash settings. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:906-984`
4. Runtime wraps resubmit in batch runner and explicitly flushes afterward; passes batch ID only if batch-ID tracking enabled. Component/attach/alias route to datastore resubmission; idAllocation drops; blobAttach uses TTL-aware blob-manager resubmit; schema marks pending CAS op unacked rather than replaying old proposal; rejoin/GC submit again. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5476-5503` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5541-5591`
5. Normal replay clears saved ops after reconstruction (new pending no longer depends on earlier local acknowledgments). Staged commit retains nonstaged prefix, clears staged flags for replayed batches; nonstaged after staged asserts. Staged discard pops suffix LIFO, calls rollback only for typical runtime ops, then asserts no staged records remain. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:894-904` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:987-990` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:1009-1033`
6. Getting pending state flushes first; prohibited during staging, manual batch accumulation, or obsolete `notifyImminentClosure:true`. Initial stash must already be applied. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5780-5798` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:390-393`

### Dirty publication and no-progress reconnect

Dirty has two layers: op dirty and aggregate blob work. On update, recompute op dirty, save it first, and during replay suppression update last-emitted state without publishing. If op dirty changed, synchronously call loader `updatePendingOpState(opDirty)` under a nesting counter. That callback can reconnect, emit connected and submit another op. Emit internal `opsSaved` only when the old computed value was clean **and remains clean after that callback**. Only after the nesting unwinds publish current aggregate dirty/saved, storing last-emitted value before host event. Suppress host publication after disposal, during replay and while notification runner active. This prevents a saved listener disconnect from being overwritten by a stale outer connection callback. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5143-5195`

Reconnect progress limit: if max<=0, never stop; otherwise if no pending messages, reset count and continue; at exactly floor(max/2) emit `ReconnectsWithNoProgress`; continue only count<max. Processing a local op resets count. This guard is separate from PSM's once-per-client replay assertion. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2973-3006` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3540-3544`



Connection write-capable edge: flush while old canSendOps still false → set canSendOps → require Attached/reset signal tracking if becoming writable → replay pending states → if reentrant replay changed canSendOps, return without propagating stale state → datastore connection → GC connection → connected/disconnected event → service connection events. Leaving writable increments no-progress count; default max7, halfway telemetry at3, close on seventh loss with pending ops. Read-only service connectivity is not synonymous with writable runtime connectivity. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3240-3302` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:892`

## 6. JS-semantics hazards

Exact envelope property order and `JSON.stringify` omission matter for ack identity; equivalent parsed dictionaries are not sufficient. Keep serialized content stable through rebase and preserve encoded handles in parsed stashed ops. `batchInfo` identity is shared within a batch and `Set` of batch-info objects deduplicates by object identity, not value. Preserve original-count queue iteration and synchronous callback side effects. Saved-op sequencing and initial-op reference sequencing are different filters. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:169-175` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:585-592` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:526-544` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:880-889` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:983-1003` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/pendingStateManager.ts:397-410`
