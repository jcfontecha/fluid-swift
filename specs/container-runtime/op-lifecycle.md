# container-runtime / operation lifecycle

## 1. Role

`Outbox` and `BatchManager` preserve atomic user batches while `OpGroupingManager`, `OpCompressor`, `OpSplitter` virtualize them for transport. `RemoteMessageProcessor` reverses those transforms before logical runtime dispatch. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:196-217` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/remoteMessageProcessor.ts:130-188`

## 2. Surface used by other packages

The runtime supplies submission callbacks, current reference/last-processed client sequence numbers, reentrancy state, a resubmit hook, pending manager and an ID-allocation producer. Local messages carry `runtimeOp`, `referenceSequenceNumber`, optional metadata/local metadata and staging state; only transport-facing messages carry serialized `contents`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:137-163` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:309-329` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2290-2309`

## 3. Wire and persisted formats

1. Serialize logical `{type,contents}` with the handle-aware JSON replacer (`isFluidHandle` → encoded internal handle). A nonempty string received from the loader is JSON-parsed; an already-parsed value is retained. Empty string is not parsed. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opSerialization.ts:32-50` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opSerialization.ts:77-96`
2. Multi-op ungrouped batches mark first op metadata `batch:true`, last `batch:false`, middles absent; singleton has neither marker. Resubmit `batchId` is stamped on first op. Effective implicit ID is `${originalClientId}_[${batchStartCsn}]`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/batchManager.ts:40-66` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/batchManager.ts:174-201`
3. Grouped contents are `{"type":"groupedBatch","contents":[{"contents":<parsed runtime envelope>,"metadata":<original metadata>,"compression":<optional string>},...]}` in that property order. Undefined inner fields disappear. Outer metadata is `{batchId?,groupedOpCount:N}`. Singletons are returned unchanged (not wrapped). Grouping accepts only original `batch`/`batchId` metadata keys. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opGroupingManager.ts:125-177`
4. Empty replay batch wire contents are `{"type":"groupedBatch","contents":[]}` with `{batchId,groupedOpCount:0}`. Its local-only pending metadata is `{emptyBatch:true}`; this placeholder is not a DDS op. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opGroupingManager.ts:84-113`
5. Compression input is the literal string `[` + singleton serialized contents + `]`, UTF-8 encoded, then **`lz4js.compress`**, then standard base64. Wire contents become JSON `{packedContents:<base64>}` with outer `compression:"lz4"`; retain outer metadata/reference sequence. This is an LZ4 codec compatibility requirement, not permission to substitute a raw LZ4 block stream. Compressed size accounting is base64 string length, not wrapper length. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opCompressor.ts:40-65` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opCompressor.ts:84-89`
6. Chunk envelope is `{type:"chunkedOp",contents:{chunkId,contents,totalChunks,...}}`; IDs start at 1. Only final chunk adds `originalMetadata`, `originalCompression`, `originalType:"component"` in that order (undefined fields omit). Chunk count is `floor((contentLength-1)/chunkSize)+1+(extraOp?1:0)`; each slice uses JS string offsets. `extraOp` deliberately permits a final empty slice. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opSplitter.ts:316-329` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opSplitter.ts:344-396`
7. `.chunks` summary blob is JSON array of `[clientId,string[]]` entries in chunk-map insertion order; absent when no partial messages. Quorum removal deletes that client's partial chunks. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2937-2940` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2311-2315`

### Literal transform vectors

These examples use an intentionally tiny logical `rejoin` op so virtualization is visible without DDS-specific fields. A normal singleton serializes as `{"type":"rejoin"}` (the missing `contents` is not `null`). Two such logical messages group as this exact string:

```json
{"type":"groupedBatch","contents":[{"contents":{"type":"rejoin"},"metadata":{"batch":true}},{"contents":{"type":"rejoin"},"metadata":{"batch":false}}]}
```

The grouped transport metadata is `{"groupedOpCount":2}`. On replay with explicit ID `c_[7]`, the first inner metadata becomes `{"batch":true,"batchId":"c_[7]"}` and the outer metadata is `{"batchId":"c_[7]","groupedOpCount":2}`. Marker mutation precedes grouping; grouping keeps the inner markers rather than stripping them. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/batchManager.ts:174-201` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opGroupingManager.ts:143-177`

Forced through the compression path, singleton `rejoin` has compressor input UTF-8 bytes for `[{"type":"rejoin"}]`, and the installed lz4js writer produces:

```json
{"packedContents":"BCJNGEBw3xMAAIBbeyJ0eXBlIjoicmVqb2luIn1dAAAAAA=="}
```

Outer `compression` is `"lz4"`; its logical pending content remains `{"type":"rejoin"}`. This vector was derived with the installed codec, not a hand-built frame. The lz4js frame starts magic bytes `04 22 4d 18`, descriptor `40 70 df` (4 MiB maximum block, no block-independence/checksum/content-size flags), then little-endian block lengths with high bit set for literal blocks, and final zero-length block. Compressor falls back to literal block when compression returns 0 or exceeds original block length. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opCompressor.ts:40-65` `harness/node_modules/lz4js/lz4.js:34-55` `harness/node_modules/lz4js/lz4.js:460-519`

The existing Swift `FluidLZ4.compress` uses `LZ4F_compressFrame` with default preferences; this is a framed codec, not raw blocks. It need not produce lz4js-identical compressed bytes to be wire-compatible, but its decompressed bytes must be identical. Native codec golden tests cover lz4js→Swift decoding and native roundtrip, not by themselves native→lz4js decoding. Matching summary JSON remains byte-exact; compression bytes have a different compatibility criterion. `Sources/FluidLZ4/LZ4.swift:1-21` `Tests/FluidLZ4Tests/FluidLZ4Tests.swift:32-44` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opDecompressor.ts:125-132`

With chunk size 3 and serialized transport contents `abcdef`, split produces the following inner chunk objects; this is a slicing vector, not a claim that `abcdef` is valid complete JSON:

```json
[{"chunkId":1,"contents":"abc","totalChunks":2},{"chunkId":2,"contents":"def","totalChunks":2,"originalCompression":"lz4","originalType":"component"}]
```

Each is wrapped as `{"type":"chunkedOp","contents":<chunk>}`. Adding `extraOp:true` makes `totalChunks:3` in every object, strips original fields from chunk 2, and emits final `{"chunkId":3,"contents":"","totalChunks":3,"originalCompression":"lz4","originalType":"component"}`. If original metadata is present it is inserted before `originalCompression`. `.chunks` for a partly received stream is e.g. `[["c",["abc"]]]`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opSplitter.ts:316-329` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opSplitter.ts:344-395` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:2937-2940`

`.recentBatchInfo` is JSON `[[serverSequenceNumber,effectiveBatchId],...]`, e.g. `[[101,"c_[7]"],[104,"d_[8]"]]`, retaining map insertion order. It has no explicit-ID bit or client record: those are memory-only. Empty detector state omits the blob. Before each new batch, remove entries with sequence **strictly less than** the incoming MSN, stopping at the first retained entry; then look up effective ID. Duplicate does not overwrite original. Summary extraction resets processed/peak telemetry counters, not retained identities. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/duplicateBatchDetector.ts:81-89` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/duplicateBatchDetector.ts:100-155` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/duplicateBatchDetector.ts:162-201`

## 4. Behavior

### Outbound

- Maintain separate main and blob-attach accumulators; blob-attach disables grouping. Before each push, compare both accumulators' reference and client sequence numbers with current numbers; undefined is a wildcard. Unexpected advancement throws, while reentrant advancement is allowed until rebase. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:212-217` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:250-306` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/batchManager.ts:204-215`
- Push stores the first last-processed CSN; reference sequence for the accumulated batch is the last message's reference sequence. Pop clears accumulator, CSN and reentrant flag. Checkpoint rollback splices the suffix and processes it in reverse order; generating ops during rollback throws. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/batchManager.ts:86-137` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/batchManager.ts:142-163`
- Flush is a no-op if both accumulators empty and no replay ID. It cannot run reentrantly. Flush blob-attach first, main second. If both empty but replay ID supplied, send/track the empty placeholder. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:339-401`
- For a reentrant batch, pop it, assert not a resubmitted batch, set rebasing, invoke runtime resubmit on each raw op in original order with `squash:false`, then flush the reconstructed batch. It must not reenter rebasing. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:413-439` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:482-515`
- If disconnected or staged, add batch metadata and register raw messages with pending manager without serialization/transport or ID allocation. Otherwise generate an allocation op just in time **after rebase**, prepend it, add markers, virtualize and send, then register raw messages with the pending manager using the representative starting CSN. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:442-473`
- Virtualize: serialize raw ops and sum serialized `.length`; optionally group; if result has more than one message, return it without compression. A singleton compresses when `minimumBatchSizeInBytes <= contentSizeInBytes` and modern `submitBatchFn` exists. Thus equality **does compress**, despite prose descriptions saying “exceed.” Then chunk only if compressed base64 length **greater than** chunk size. Without chunk support, compressed size `>=maxBatchSize` fails `CompressionInsufficient`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:531-572`
- Split sends first N−1 chunks immediately via batch callback; last chunk is returned for normal send. Intermediate chunks have no outer metadata; last outer metadata copies `batch` and `groupedOpCount`, deliberately not `batchId` (restored from inner `originalMetadata`). Extra empty final chunk is requested when estimated socket size `>=maxBatchSize`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opSplitter.ts:185-219`
- Before ordinary send reject socket estimate `contentSize+200*messageCount >= maxBatchSize`. Callback returns last wire CSN; subtract transport message count−1 to obtain start CSN. Legacy loader path must have no compression. Defaults: max batch 716800; chunk 204800; compression threshold 614400. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:170-187` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:581-618` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:641-643` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/compressionDefinitions.ts:40-44`

### Runtime flush scheduling and rollback

Submit first offers schema upgrade, queues it in main accumulator if returned, then queues the requested op in main or blob accumulator, calls `scheduleFlush`, then updates dirty and staged-change notifications. Schema proposal therefore precedes the triggering user op but an allocation later prepended by flush can precede both. Submit errors wrap as data-processing errors, close, and rethrow. Detached submit asserts `0x132`; explicit ID allocation asserts `0x9a5`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5306-5394`

Automatic scheduling is suppressed while staging and main count is below `stagingModeAutoFlushThreshold` (default 1000). Otherwise if already scheduled return; set scheduled flag first. Immediate mode flushes synchronously unless a batch runner is active. TurnBased enqueues `Promise.resolve().then(flush)`—a microtask, not an arbitrary timer. Flush clears scheduled flag before asserting no active manual runner, sends outbox, asserts empty (`0x3cf`), then updates staged notifications; errors close and rethrow. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3886-3911` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5396-5435` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opGroupingManager.ts:22-26`

`orderSequentially` is synchronous and nestable; it is not an async transaction. With `Fluid.ContainerRuntime.EnableRollback===true`, outermost nonstaging call enters silent staging and captures **main** batch checkpoint; nested calls also capture a checkpoint. On callback throw rollback checkpoint suffix in reverse via `rollbackStagedChange`, update dirty, discard temporary stage controls; rollback failure closes with `RollbackError`. Without checkpoint callback failure closes with `orderSequentially callback exception`. Rethrow original callback error after successful rollback/close path. Success commits temporary staging with `squash:false`, then flushes only if not TurnBased and outermost runner finished. Internal staging emits no `stagingModeChanged`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3914-3988`



### Inbound

- Loader queue aggregation must not begin an ungrouped multi-message batch until its end has arrived. System ops or another client's op cannot interleave; pause at the beginning of an incomplete batch, resume when complete. This avoids processing half a local ack before reconnect. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/inboundBatchAggregator.ts:66-110` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/inboundBatchAggregator.ts:115-210`
- Copy the sequenced outer envelope; parse runtime JSON. If chunked, append per client only when `chunkId == storedCount+1`, otherwise corruption. Return nothing for nonfinal chunks. At final: join strings, clear map, parse (`""` → undefined), replace type/metadata/compression from final chunk. Use final chunk's sequence numbers/timestamp. Historical partial-stream mode may discard the first unreconstructable stream per client; live mode is strict. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opSplitter.ts:114-132` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opSplitter.ts:239-303`
- If compressed, decode base64, LZ4-decompress, decode string, JSON-parse root array; then unroll. Accept explicit `compression:"lz4"` and historical missing compression metadata only when contents has exactly one nonempty string `packedContents` property that roundtrips base64 exactly. Reject other compression identifiers when decompressing. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opDecompressor.ts:49-89` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opDecompressor.ts:105-133`
- Legacy compressed multi-message batches: first marker true installs root array and consumes element 0; continuation marker absent requires undefined contents and consumes next; false terminates/reset. No batch marker means a compressed singleton, consumed and reset immediately. Output clears `compression` and clones metadata. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opDecompressor.ts:139-188`
- Ungroup only after unchunk/decompress. Each inner message copies outer envelope but overwrites CSN with 1,2,… and contents/metadata/compression with inner fields; sequence number remains outer sequence. Preserve original outer CSN separately as `batchStartCsn`. Empty group returns `fullBatch` with no messages but original key message. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opGroupingManager.ts:181-192` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/remoteMessageProcessor.ts:139-180`
- Promote each runtime envelope's type/contents. Ungrouped marker machine starts with no active batch: absent → singleton `fullBatch`, true → `batchStartingMessage`, false invalid. During active batch, absent → continuation, false → continuation/end and clear active state, true invalid. Preserve legacy already-unpacked messages and address-without-type envelope as `component`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/remoteMessageProcessor.ts:195-243` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/remoteMessageProcessor.ts:254-300`

## 6. JS-semantics hazards

“Bytes” counters are mostly **UTF-16 code-unit lengths**, not UTF-8 counts; chunk slicing is UTF-16 too. Only compression explicitly encodes UTF-8. Preserve base64 canonicalization and absent vs null metadata. Do not derive batch IDs from synthetic inner CSNs or first chunk CSNs. Grouping retains original aggregate size rather than recomputing JSON wrapper size. Preserve the order of immediate chunk sends relative to representative send and pending registration. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/outbox.ts:145-154` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opSplitter.ts:355-385` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opCompressor.ts:47-64` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/opGroupingManager.ts:168-177` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/opLifecycle/remoteMessageProcessor.ts:25-48`
