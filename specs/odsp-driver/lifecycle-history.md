# ODSP factory, file creation and historical loading

## Role

Factory owns shared discovery/prefetch/file caches, copies host policy, creates per-file epoch tracking, and exposes regular or injected historical services. File creation supports an initial combined snapshot, an empty temporary file followed by attachment/summary upload, or a Fluid partition on an existing file. Historical loading combines a sealed file version snapshot with live deltas bounded at a target. Sources: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspDocumentServiceFactoryCore.ts:145-175`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspDocumentServiceFactoryCore.ts:311-390`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createFile.ts:55-151`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/pointInTimeDriver/createPointInTimeDocumentService.ts:119-247`.

## Wire and persisted formats

Let A=API root, d=driveId. New file item address is `items/root:<enc(normalizedFolderPath)>/<enc(filename)>` when parentFolderId undefined; folder path empty/undefined→empty, else ensure leading slash then encodeURIComponent whole path (slashes encoded). Parent-ID form `items/<enc(parentFolderId)>:/<enc(filename)>`. Filename rejects any `" * / : < > ? \ |` character before network. Sources: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createFile.ts:46-75`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createFile.ts:200-225`.

| Request | Exact URL/body |
|---|---|
| Empty file | PUT `A/drives/d/<item-address(filename+".tmp")>:/content?@name.conflictBehavior=rename&select=id,name,parentReference`; body undefined; Content-Type application/json |
| Initial summary file | POST `A/drives/d/<item-address(filename)>:/opStream/snapshots/snapshot` plus optional `?createLinkScope=<scope>[&createLinkRole=<role>]` |
| Existing file partition | POST `A/drives/d/items/i/opStream/snapshots/snapshot`; additional If-Match=eTag iff eTag!==undefined |
| Final rename | PATCH `A/drives/d/items/i?@name.conflictBehavior=rename`; JSON `{"name":"requestedName"}` |

Sources: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createFile.ts:216-340`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createFile.ts:343-381`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createNewContainerOnExistingFile.ts:58-86`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspUtils.ts:531-543`.

Initial summary payload property order `{entries:[...],message:"app",sequenceNumber:protocolAttributes.sequenceNumber,type:"container"}`. Only `.protocol` then `.app` are included at root in that order. Entry order differs from ordinary proposal upload: `{path:key,type:gitType,value:{type:"tree",entries:[...]}|{type:"blob",content:string,encoding:"utf-8"|"base64"},unreferenced?:true,groupId?:string}`. Handles rejected; attachments hit Unknown tree type. Example entry `{"path":"header","type":"blob","value":{"type":"blob","content":"hi","encoding":"utf-8"}}`. Source: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createNewUtils.ts:115-206`.

Creation core JSON-stringifies snapshot, constructs UMP URL by URL.searchParams.set(ump,1), obtains token for that **POST UMP URL first**, then builds literal `--B\r\nAuthorization: AUTH\r\nX-HTTP-Method-Override: POST\r\nContent-Type: application/json\r\n[additional headers]\r\n_post: 1\r\n\r\nJSON\r\n\r\n--B--`. Use UMP iff UTF8 byte length of this body **<=79872** and authHeader.startsWith("Bearer") (case-sensitive prefix, not strict scheme parser). Otherwise request a **second auth header for original URL**, POST original JSON with Content-Type application/json and additional headers. Epoch params go body only for UMP. Deprecated forceAccessTokenViaAuthorizationHeader is destructured out/not used. Sources: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createNewUtils.ts:209-324`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspUtils.ts:521-523`.

New summary create response requires truthy itemId; empty create/rename require truthy id. Summary create response interface fields `@odata.context,driveId,id,itemId,itemUrl,sequenceNumber,name` plus optional sharing/sharingLink/sharingLinkErrorReason. Existing-file creation destructures id as summaryHandle without extra validation callback. Creation cache uses new UUID per blob and actual byte buffers, empty ops, sequenceNumber/latest from protocol attributes, root id=summaryHandle,snapshotFormatV=1; epoch wrapper adds timestamp/envelope. Sources: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/contracts.ts:179-199`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createFile.ts:263-275`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createFile.ts:325-331`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createFile.ts:372-379`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createNewUtils.ts:46-112`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createNewContainerOnExistingFile.ts:76-113`.

Historical endpoints (distinct from opStream snapshot versions): GET `A/drives/d/items/i/versions`, pages `{value?:[{id:string,lastModifiedDateTime:string}],"@odata.nextLink"?:string}`. Resolve version seq with GET `A/drives/d/items/i/versions/<enc(versionId)>/opStream/snapshots/trees/latest?blobs=2`, accept `application/json, application/ms-fluid; v=1.0`. Epoch-only requests GET live/version trees/latest?blobs=0. ## Behavior

Factory defaults persistedCache=LocalPersistentCache (in-memory, sliding document expiry3600000ms), hostPolicy={}; snapshot-copy nonempty safe headers; isolate socket cache if host isolateSocketCache===true **or safe headers present**. enableRedeemFallback defaults true, sessionOptions defaults forceAccessTokenViaAuthorizationHeader=true then host spread. Each service policies storageOnly=fileVersion!==undefined, summarizeProtocolTree=true,supportGetSnapshotApi=true; connectToStorage lazily creates one manager but returns a new RetryErrorsStorageAdapter each call. Adapter has own disposed flag; calls runWithRetry for every storage method, checks disposed before each attempt, and does not dispose underlying service. Sources: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspDocumentServiceFactoryCore.ts:311-333`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspCache.ts:39-96`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspDocumentService.ts:138-200`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/retryErrorsStorageAdapter.ts:27-119`.

Creation transitions: validate filename→if no summary create empty file, pendingRename=requested filename; otherwise convert/upload summary, capture itemId/id/sharing. Resolve actual internal URL with path `/`, mutate shared fileEntry docId/resolvedUrl **before cache write**; carry context/appName/codeHint; if create link exists append nav locator. Set resolved.shareLinkInfo/pendingRename; cache initial summary only requested and summary present; await cache put. Sharing response extraction only if enableSingleRequestForShareLinkWithCreate truthy: createLink.link copies scope, maps role from sharingLink.type, webUrl then spreads sharingLink (later source properties win), error/shareId copied. Sharing creation error does not invalidate successful file creation. Sources: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createFile.ts:55-192`.

Initial conversion requires combined app/protocol. Read document attributes, replace protocolSummary.tree.attributes in-place with JSON.stringify(documentAttributes), construct root only protocol/app, convert recursively in Object.keys order. New-cache conversion traverses whole passed summary, keeps unreferenced/groupId and rejects both Handle/Attachment. Existing-file partition requires nonundefined summary else UsageError, resolves file with CLP/eTag and updates fileEntry, then optional cache. Source: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createNewUtils.ts:46-206`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createNewContainerOnExistingFile.ts:58-116`.

### Historical selection transitions

Every findBaseForSeq(target) re-enumerates paged versions newest-first; preserve server order, no sort; exclude index0 (mutable tip), scan remaining sealed versions sequentially. For each increment versionsProbed; resolve sequence via PromiseCache keyed versionId, coalescing calls and evicting failed resolutions; sequenceNumberFetchCount increments only on miss. Track minimum sequence seen. First seq<=target is selected, then validate lineage before returning `{kind:"found",base:{versionId,lastModifiedDateTime,sequenceNumber},versionsProbed,sequenceNumberFetchCount}`. Exhaustion returns `{kind:"noBaseVersion",oldestResolvedSeq?,versionsProbed,sequenceNumberFetchCount}`; never use tip as fallback even if sole version/near head. Sources: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspVersionManager/odspVersionManager.ts:111-145`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspVersionManager/odspVersionManager.ts:203-218`.

Lineage concurrently reads fresh live epoch and cached sealed-version epoch (separate cache by versionId). Either missing→nonretryable incorrectServerResponse. Different→nonretryable fileOverwrittenInStorage with versionMarkAvailabilityOutcome=lineageMismatch. Epoch reads deliberately bypass EpochTracker (raw fetchArray+host header merge) so both epochs can be compared. Sequence reads use tracker; JSON content-type takes priority before binary here (reverse of regular trees-latest classification), require numeric nonnegative integer sequence or incorrectServerResponse; pagination follows truthy nextLink until absent with a token per page, a token-refresh repeat restarts enumeration. Sources: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspVersionManager/odspVersionManager.ts:148-183`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspVersionManager/odspFileVersionFetcher.ts:112-230`.

Historical service creation builds fresh NonPersistentCache + shared EpochTracker, finds base; noBaseVersion→UsageError outcome baseVersionMissing; resolve internal URL adding fileVersion and retaining optional path/package; create recoverable service then live service with same cache/tracker; if live creation fails, dispose recoverable (log disposal error) then rethrow original. Wrapper advertises only `{storageOnly:true}`, forwards live metadataUpdate. connectToStorage proxies historical storage overriding getSnapshot/getVersions to FetchSource.noCache. Delta storage delegates live fetchMessages with exclusive upper=min(suppliedTo,target+1) or target+1 when undefined. Synchronous fetch/read failures retain original error but annotate missingOps only for cannotCatchUp or genericNetworkError with telemetry opsFetchFailure=tooManyRetries. connectToDeltaStream always throws; disposal removes metadata listener then disposes recoverable then live. Sources: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/pointInTimeDriver/createPointInTimeDocumentService.ts:77-247`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/pointInTimeDriver/odspPointInTimeDocumentService.ts:29-166`.

Create-request builder returns `{url,headers:{[DriverHeader.createNew]:{fileName}}}`. URL is `siteUrl?driveId=enc(driveId)&path=enc(filePath)` or parentFolderId selector, optionally `&containerPackageName=<extractedName>` (package name **not URI-encoded here**) and `&createLinkScope=<scope>[&createLinkRole=<role>]`. Options overload rejects no selector, both selectors, empty parentFolderId; old positional builder simply uses path. Factory honors createLinkScope/role only with enableSingleRequestForShareLinkWithCreate; scope/role must be truthy enum-index lookups, invalid role omitted. Sources: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createOdspCreateContainerRequest.ts:124-170`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspDocumentServiceFactoryCore.ts:476-497`.

Factory creation dispatches to existing-file partition when resolved.itemId truthy, else new file when fileName truthy, otherwise throws. Combined detached summary must have protocol sequenceNumber exactly0 or throws. It constructs fileEntry with fileVersion undefined before creating cache/tracker; creation then mutates its file identity after server success. Source: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspDocumentServiceFactoryCore.ts:191-240`.

## Invariants and asserts

Initial key no slash 0x9cc; combined summary required; no handles/attachments in detached cache conversion. Creation cache requires summaryHandle!==undefined 0x203 (empty still passes); truthy server IDs required in specified create callbacks. FileVersion is storage-only even empty string. ## JS-semantics hazards

The snapshot creation UMP threshold uses UTF8 bytes, unlike telemetry JSON lengths in UTF16; don't select transport from String.count. Creation mutates protocol attributes and fileEntry. A cache-put or final rename failure can reject after server file exists; automatic retry of whole attach can duplicate files. Historical tip exclusion is required even with cached seq values; no chronology sort or live-head fallback. Raw epoch probes must not teach/overwrite shared tracker. Sources: `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createNewUtils.ts:123-128`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createNewUtils.ts:239-295`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/createFile/createFile.ts:106-149`, `reference/fluidframework-3.11.0/packages/drivers/odsp-driver/src/odspVersionManager/odspVersionManager.ts:111-183`.
