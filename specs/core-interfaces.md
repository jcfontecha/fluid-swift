## 2. Surface used by other packages

### Handles and loadable capabilities

- Public `IFluidHandle<T>`: readonly isAttached:boolean; get():Promise<T>; readonly symbol-keyed erased internal handle. Internal handle additionally has readonly absolutePath:string, attachGraph():void, and string-keyed `IFluidHandle` provider. Do not turn a handle into the loaded object during decoding. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/handles.ts:57-92`, `reference/fluidframework-3.11.0/packages/common/core-interfaces/src/handles.ts:208-237`)
- Symbol identity is **Symbol.for("FluidHandle-3978c7cf-4675-49ba-a20c-bf35efbf43da")**, globally registered, not a fresh symbol per module. `IFluidHandleContext` is a self-provider named `IFluidHandleContext`, with absolutePath:string, optional routeContext, isAttached:boolean, attachGraph():void and resolveHandle(IRequest):Promise<IResponse>. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/handles.ts:13-49`, `reference/fluidframework-3.11.0/packages/common/core-interfaces/src/handles.ts:200-202`)
- Internal payload-pending adds readonly payloadPending:boolean. Public pending handle exposes payloadState:`"pending"|"shared"`, events with payloadShared():void. Local pending handle adds optional sharePayload():void, readonly payloadShareError:unknown and payloadShareFailed(error:unknown):void. These event types do not themselves dispatch or order events. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/handles.ts:99-185`)
- `IFluidLoadable` is a self-provider with property `IFluidLoadable` and readonly handle:IFluidHandle. The provider key is the literal string `IFluidLoadable`; this is capability discovery, not a wire type tag. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/fluidLoadable.ts:11-31`)

### Routing and event contracts

IRequest is `{url:string,headers?:{[name:string]:any}}`; IResponse is `{mimeType:string,status:number,value:any,headers?:{[name:string]:any},stack?:string}`. These are in-process request/response objects, not HTTP serialization rules. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/fluidRouter.ts:9-36`)

Legacy IEvent accepts event:string and callback variadic any args; IErrorEvent adds error(message:any). IEventProvider exposes readonly on, once, off methods returning the provider for chaining via TransformedEvent. The newer Listenable/IEmitter family separates on(event,listener):Off and off(event,listener):void from emit(event,...args):void, emitAndCollect(event,...args):ReturnType[], and hasListeners(event?):boolean. Event keys are string or symbol, callbacks matched by identity. Duplicate registration throws per contract; no once/prepend methods. Off is ()=>void. These types do not imply asynchronous delivery or implement an event loop. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/events.ts:10-56`, `reference/fluidframework-3.11.0/packages/common/core-interfaces/src/events.ts:123-126`, `reference/fluidframework-3.11.0/packages/common/core-interfaces/src/events/emitter.ts:12-73`, `reference/fluidframework-3.11.0/packages/common/core-interfaces/src/events/listeners.ts:29-80`)

### JSON, configuration and disposal

`JsonString<T>` brands a string only at compile time; `JsonSerializable<T>`, `JsonDeserialized<T>`, opaque JSON and readonly/erased/branded utility types add no runtime tag or validator. `JsonStringify` is literally the same function object as JSON.stringify, and `JsonParse` literally JSON.parse with type casts. Therefore ordinary JSON rules apply: object undefined/function/symbol values disappear, array holes/undefined become null, non-finite numbers become null, toJSON runs, bigint/cycles throw absent customization, parsed values are not schema-validated. Do not emit TypeScript brand fields. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/jsonString.ts:74-125`, `reference/fluidframework-3.11.0/packages/common/core-interfaces/src/jsonUtils.ts:30-90`)

`IDisposable` requires readonly disposed:boolean and dispose(error?:Error):void; there is no automatic destructor or cancellation behavior. `IConfigProviderBase.getRawConfig(name:string)` returns string|number|boolean|number[]|string[]|boolean[]|undefined; undefined means not configured. It performs no string/array coercion itself. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/disposable.ts:16-28`, `reference/fluidframework-3.11.0/packages/common/core-interfaces/src/config.ts:11-43`)

### Error base types

FluidErrorTypes literal values, in construction order: `genericError`, `throttlingError`, `dataCorruptionError`, `dataProcessingError`, `usageError`, `layerIncompatibilityError`; keys equal values. FluidErrorTypesAlpha spreads exactly that object, no extra categories. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/error.ts:12-68`)

IErrorBase requires readonly errorType:string and message:string; name?:string, stack?:string, optional getTelemetryProperties():ITelemetryBaseProperties. It extends Partial<Error> so it need not be an Error instance. Generic error fixes errorType=genericError and adds error?:any. Usage error fixes usageError. Throttling warning fixes throttlingError and requires retryAfterSeconds:number. Layer incompatibility requires errorType=layerIncompatibilityError, layer:string, incompatibleLayer:string, layerVersion:string, incompatibleLayerVersion:string, compatibilityRequirementsInMonths:number, actualDifferenceInMonths:number, details:string. No constructor, retry logic or automatic telemetry is provided here. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/error.ts:81-186`)

### Telemetry

TelemetryBaseEventPropertyType is string|number|boolean|undefined, not arbitrary JSON (no null/array/object). Tagged<V,T> is `{value:V,tag:T}` where tag is a string. ITelemetryBaseProperties maps property names to a primitive or Tagged<primitive>. ITelemetryBaseEvent additionally requires category:string,eventName:string. ITelemetryErrorEvent requires eventName but no category. ILoggingError extends Error and requires getTelemetryProperties(). (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/logger.ts:14-51`, `reference/fluidframework-3.11.0/packages/common/core-interfaces/src/logger.ts:136-149`)

LogLevel constants are verbose=10, info=20, essential=30 in that insertion order. ITelemetryBaseLogger.send(event,logLevel):void has **required** level argument; optional minLogLevel defaults by contract to info=20 and is a requested filter threshold for consumers, not implemented by this interface. Mixed-version logger implementations must accept an omitted level from older callers and substitute essential=30 **before filtering or forwarding**, despite this version’s required-argument declaration. Send does not itself scrub tagged data or serialize. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/logger.ts:62-126`)

## 3. Wire and persisted formats

### Handle JSON (also embedded in DDS blobs/ops)

Literal schema `{type:"__fluid_handle__",url:string,payloadPending?:true}`. Emission order **type, url, payloadPending**; last field is emitted only if internal payloadPending exists and is exactly true. Otherwise it is omitted, not false or null. Writer uses handle.absolutePath. Examples from the encoder: ordinary handle at `/store/map` => `{"type":"__fluid_handle__","url":"/store/map"}`; pending blob at `/_blobs/b1` => `{"type":"__fluid_handle__","url":"/_blobs/b1","payloadPending":true}`. There is no version field. (`reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/handles.ts:31-48`, `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/handles.ts:62-65`, `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/handles.ts:95-106`)

Readers still accept legacy relative URLs: `{"type":"__fluid_handle__","url":"map"}` decoded in `/store` context becomes absolute `/store/map`, and a subsequent encoding writes the absolute form. Readers interpret pending only when `===true`; omitted/false/null do not activate pending behavior. Serialized recognition checks only `.type` equality, not presence/type of url; malformed reserved-marker objects fail later when startsWith is called, rather than being preserved as ordinary user objects. (`reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/handles.ts:54-56`, `reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:149-165`)

### Signal envelope and telemetry shapes

TypedMessage is `{type:string,content:unknown}`. ISignalEnvelope is `{address?:string,clientBroadcastSignalSequenceNumber?:number,contents:TypedMessage}`. This package only declares these shapes; it does not serialize them and therefore defines no property insertion order. Required contents is not the same field name as TypedMessage.content. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/messages.ts:15-52`)

Telemetry example admitted by interfaces: `{"category":"generic","eventName":"Load","duration":12,"document":{"value":"id","tag":"UserData"}}`; this order belongs to this constructed example, not to an interface-imposed serializer. A property whose value is undefined is dropped by JSON.stringify; a tagged object with undefined value retains its tag but loses its value property. No telemetry transport or document format version is defined here. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/logger.ts:14-51`)

## 4. Behavior

### Handle encode / decode / resolution

1. FluidSerializer construction records context, then follows routeContext until undefined to select root resolver. (`reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:64-72`)
2. encode asserts bind is ISharedObjectHandle (0xb8c), then passes non-null objects through recursivelyReplace; primitives pass through unchanged. stringify asserts bind (0xb8d) and invokes JSON.stringify with encodeValue replacer. stringify therefore uses JSON's toJSON and replacer visitation order, unlike the manual encode walker. (`reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:87-123`)
3. encodeValue recognizes a Fluid handle by non-null typeof object and presence of fluidHandleSymbol (inherited property allowed). It asserts bind exists (0xa93), extracts the internal handle, calls bind.bind(handle) **before** encoding the marker. Binding may attach the referenced graph; serialization is not a pure getter. (`reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:136-143`, `reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:224-230`, `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/handles.ts:112-114`)
4. Internal extraction checks symbol presence both on input and on its symbol value, then returns symbol value, not necessarily input; wrapper handles can delegate identity. Invalid internal shape throws TypeError `Invalid IFluidHandle`. compareFluidHandles extracts both internals then compares absolutePath with JS string strict equality. (`reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/handles.ts:122-126`, `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/handles.ts:173-182`)
5. recursivelyReplace invokes replacer at current object first; if original or replacement is Fluid handle, stop descending. Otherwise enumerate Object.keys(input), recursively replace non-null object children, shallow-clone only on first changed child, overwrite changed properties, and return clone or original. It does not mutate original. There is no cycle detection. (`reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:173-215`)
6. decode uses that walker without binding; parse uses JSON.parse reviver, whose children are visited before parents. For marker values, preserve leading-slash URL or join relative URL to context, construct RemoteFluidObjectHandle(absolutePath,root,payloadPending===true). Decode does not fetch or emit a payloadShared event. (`reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:106-112`, `reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:128-165`)
7. Remote handle isAttached is always true; construction asserts absolute path begins slash (0x19d). attachGraph does nothing. First get creates request in order url then headers, with headers `{viaHandle:true,payloadPending:<boolean>}`, calls root.resolveHandle and caches the resulting promise. Fulfillment accepts mimeType exactly `fluid/object` and returns response.value; it does **not** additionally require status=200. Otherwise reject responseToException. Later get reuses even a rejecting promise, no automatic retry. (`reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/remoteFluidObjectHandle.ts:23-69`, `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/utils.ts:24-28`)
8. Response exception is an object constructed in order errorFromRequestFluidObject:true, message:response.value, name:"Error", code:response.status, lazy stack getter, underlyingResponseHeaders:response.headers. Stack comes from response if it has a stack property, otherwise a generated Error. This is not necessarily an Error instance. (`reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/dataStoreHelpers.ts:84-102`)

The handle capability declarations themselves emit no events; payloadShared/payloadShareFailed transitions are notifications supplied by concrete local payload subsystems, not a side effect of `get` in RemoteFluidObjectHandle. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/handles.ts:125-185`, `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/remoteFluidObjectHandle.ts:45-69`)

## 5. Invariants and asserts

0xb8c/0xb8d enforce shared-object bind contexts; 0xa93 forbids handle encode without bind; 0x19d requires absolute remote path. Marker collisions are real: ordinary application JSON with type `__fluid_handle__` will be interpreted as a handle. Public IFluidHandle's generic T and erased symbol types are compile-time constraints, not JSON fields. (`reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:87-88`, `reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:120-122`, `reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:138-140`, `reference/fluidframework-3.11.0/packages/runtime/runtime-utils/src/remoteFluidObjectHandle.ts:39-42`, `reference/fluidframework-3.11.0/packages/common/core-interfaces/src/handles.ts:208-237`)

## 6. JS-semantics hazards

Preserve UTF-16 URLs, symbol capability identity, absent vs null pending flag, JS property enumeration and JSON replacer/reviver order. Manual encoding uses shallow copy-on-write and preserves identity of untouched branches; a deep clone changes observable identity. JSON.stringify does not serialize symbol keys and drops undefined object fields, but null is data. Native Swift `Codable` handle dumps must not leak isAttached, routeContext, cached promises or provider self-references. Errors may be structural plain objects; checking only Swift Error subclasses or JS instanceof Error loses legitimate IErrorBase values. (`reference/fluidframework-3.11.0/packages/common/core-interfaces/src/handles.ts:200-237`, `reference/fluidframework-3.11.0/packages/common/core-interfaces/src/error.ts:81-118`, `reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:120-129`, `reference/fluidframework-3.11.0/packages/dds/shared-object-base/src/serializer.ts:173-215`)
