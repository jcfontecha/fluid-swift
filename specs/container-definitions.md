# container-definitions — 3.11.0

## 1. Role

Contracts between host/loader, container and runtime: attachment, connection, audience, ordered delta delivery, lifecycle and code loading. These are mostly declarations; concrete loader algorithms below are included to pin the observable meaning of the contracts rather than invent behavior from interface names. The source tree, not npm API history, is the oracle. (`reference/fluidframework-3.11.0/packages/common/container-definitions/src/loader.ts:335-577`, `reference/fluidframework-3.11.0/packages/common/container-definitions/src/runtime.ts:157-253`)

## 3. Wire and persisted formats

### Tags and boundary payloads

AttachState literal strings in declaration order: Detached="Detached",Attaching="Attaching",Attached="Attached". ConnectionState numeric values **Disconnected=0,EstablishingConnection=3,CatchingUp=1,Connected=2**; progression is 0→3→1→2, not numeric sorting. Both are independent of closed/disposed. (`reference/fluidframework-3.11.0/packages/common/container-definitions/src/runtime.ts:42-59`, `reference/fluidframework-3.11.0/packages/common/container-definitions/src/loader.ts:270-329`)

ConnectionStatus is in-process, not a persisted envelope. Concrete loader construction order and exact fields:

- Establishing: `{connectionState:3,canSendOps:false,readonly:boolean}`.
- CatchingUp: `{connectionState:1,pendingClientConnectionId:string,canSendOps:false,readonly:boolean}`.
- Connected: `{connectionState:2,clientConnectionId:string,canSendOps:!readonly,readonly:boolean}`.
- Disconnected: `{connectionState:0,priorPendingClientConnectionId:string|undefined,priorConnectedClientConnectionId:string|undefined,canSendOps:false,readonly:boolean}`.

JSON example from connected writable branch: `{"connectionState":2,"clientConnectionId":"c1","canSendOps":true,"readonly":false}`. Undefined prior IDs disappear if serialized; no null substitution. (`reference/fluidframework-3.11.0/packages/common/container-definitions/src/runtime.ts:67-149`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:2591-2642`)

IBatchMessage fields all optional: contents:string,metadata:Record<string,unknown>,compression:string,referenceSequenceNumber:number. contents is already serialized, not a JSON object to stringify again. These declarations impose no emission order. Example admitted by contract: `{"contents":"{\"type\":\"component\"}","metadata":{"batch":true},"referenceSequenceNumber":10}` (example order, not a serializer mandate). (`reference/fluidframework-3.11.0/packages/common/container-definitions/src/runtime.ts:259-264`)

Loader headers literal keys: `fluid-cache` (deprecated), `fluid-client-details`, `loadMode`, `fluid-reconnect`, `fluid-sequence-number`, `version`. loadMode={opsBeforeReturn?:"cached"|"all",deltaConnection?:"none"|"delayed"}. Absent opsBeforeReturn: no trailing ops applied before return; cached: cached only; all: all storage ops (may wait unbounded on retries). Absent deltaConnection: connect and process immediately; none: neither connect nor process until connect(); delayed: process/fetch but don't open stream until connect(). Sequence header overrides opsBeforeReturn as minimum load target. Version undefined fetches latest; null or string "null" means ops only/no snapshot; other string is version SHA. ILoaderHeader's narrower string|undefined declaration does not erase null behavior described by LoaderHeader.version. ILoaderOptions={cache?:boolean(default false),client?:IClient(deprecated),provideScopeLoader?:boolean(default true, overwrites scope.ILoader),maxClientLeaveWaitTime?:number}; IContainerPolicies={maxClientLeaveWaitTime?:number}. (`reference/fluidframework-3.11.0/packages/common/container-definitions/src/loader.ts:640-773`)

### Detached serialize(): current and legacy read formats

Current emission order: attached:false; baseSnapshot:ISnapshotTree; snapshotBlobs:Record<blobID,string>; pendingRuntimeState?:unknown; hasAttachmentBlobs:boolean; attachmentBlobs?:string. snapshotBlobs stores UTF-8 decoded text, NOT base64. Detached state omits pendingRuntimeState; attaching state captures runtime state synchronously (thenables assert 0x8e3). attachmentBlobs is **nested JSON text of an array of UTF-8 strings**, e.g. `"[\"hello\"]"`, not a byte array. Empty detached storage omits it. Its IDs are decimal array indices "0","1",…; UTF-8 conversion is lossy for arbitrary binary. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:1219-1247`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/utils.ts:351-359`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/memoryBlobStorage.ts:56-74`)

Concrete outer-format fixture for snapshot tree `{blobs:{header:"b"},trees:{}}`, blob b containing `{}`, no pending runtime or detached blobs: `{"attached":false,"baseSnapshot":{"blobs":{"header":"b"},"trees":{}},"snapshotBlobs":{"b":"{}"},"hasAttachmentBlobs":false}`. This pins the outer producer and escaping; actual createSummary also supplies application/protocol content. No numeric version field. Reader first JSON.parse; if attached,baseSnapshot,snapshotBlobs,hasAttachmentBlobs are each not undefined, accept as current state without deeper validation (even attached:false is not tested). Otherwise accept legacy combined summary `{type:1,tree:{".app":<summary tree>,".protocol":<summary tree>,".hasAttachmentBlobs"?:<summary object>}}`; convert app/protocol to snapshot/blob map, set attached:false and marker-presence boolean. Otherwise UsageError `Cannot rehydrate detached container. Incorrect format`; invalid JSON throws JSON.parse error first. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:1239-1247`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/utils.ts:268-281`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/utils.ts:333-387`)

## 4. Behavior

### Attach state machine

1. New containers start Detached. Attach rejects unless lifecycle is loaded and state is not Attached; serialized attaching state is a valid retry starting point. Calls are wrapped in runSingle: concurrent calls with Object.is-equal positional arguments share the existing promise; different arguments reject UsageError `Subsequent calls cannot use different arguments.`. Completion clears the running slot in finally. Request/props objects compare by identity, not structural JSON. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:1250-1267`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/utils.ts:409-435`)
2. On first attempt with unclassified blobs: if detached storage exists and size>0, retain Detached, mark blobs outstanding and initialize redirect Map; otherwise synchronously create combined summary, then set Attaching with blobs none. Persist attachment data **before** runtime notification and host event. On any change to Attaching/Attached: runtime.setAttachState(state), then emit lowercase attaching/attached. Notification throw normalizes error, closes container, rethrows. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/attachment.ts:148-167`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:1279-1309`)
3. Await createOrGetStorageService(summary). Outstanding blobs have undefined summary, so service creates empty remote file while public state is still Detached. Loop while redirectTable.size<detachedStorage.size: get IDs absent from map, sequentially await readBlob then createBlob, then save local→remote ID; loop again to include blobs created while awaiting. Create summary with redirect table; set Attaching/blobs done. Retries retain prior map and completed uploads. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/attachment.ts:169-195`)
4. For blobs done, upload summary with context in order referenceSequenceNumber:0,ackHandle:undefined,proposalHandle:undefined; blobs none skip this because createContainer already received summary. Convert summary to snapshot, set Attached (runtime then host event), return snapshot. Caller sets initial serialized snapshot, then if not closed disposes detached storage and handles requested deltaConnection mode without fetching storage ops. Thus attached fires before connection and before final storage cleanup. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/attachment.ts:197-220`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:1348-1356`)
5. Default attach failure normalizes, closes and throws; `Fluid.Container.DisableCloseOnAttachFailure===true` leaves ordinary attach failures retriable at last durable phase. Runtime-summary/notification errors still force close. No reverse Attaching→Detached event is emitted. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:1269-1309`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:1331-1346`)

### Connection state machine and reconnect ordering

Default features: wait for catch-up unless `Fluid.Container.DisableCatchUpBeforeDeclaringConnected===true`; read clients wait for join signal unless `Fluid.Container.DisableJoinSignalWait===true`. With join wait, membership=protocol audience; without it, membership=quorum. Writes must wait for sequenced join, not merely join signal. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:106-136`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:726-754`)

1. Disconnected→EstablishingConnection when starting connection; commit state then notify. Cancellation asserts Establishing and no connection, commits Disconnected, notifies. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:562-579`)
2. Socket connected: store details, commit CatchingUp, save pendingClientId, notify. If self absent and (write mode OR read-join wait enabled), start join timer; otherwise if no old-client leave wait, request Connected. Pending ID does not replace old clientId yet. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:587-644`)
3. Matching self add stops join timer if running then requests Connected. Old-client remove while leave timer active clears leave timer then requests Connected. pendingOpsSaved clears active leave timer and requests Connected. Leave timeout also requests Connected; join timeout is diagnostic, not permission to skip join. Leave timeout defaults to 300000 ms (override maxClientLeaveWaitTime); join timeouts are 45000 ms for writes and 10000 ms for reads. Exact request predicate: pendingClientId!==clientId AND membership contains pendingClientId AND no leave timer; otherwise remain current state and log rejection. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:27-30`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:399-458`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:467-554`)
4. Base Connected commits state first; asserts previous CatchingUp; if old ID remains in quorum, marks it should-have-left; sets clientId=pendingClientId; notifies. Default catch-up wrapper intercepts that notification: remains publicly CatchingUp, allocates CatchUpMonitor using fixed target=deltaManager.lastKnownSeqNumber at construction, subscribes op, **assigns monitor before start()**. start immediately evaluates lastSequenceNumber and can synchronously call back; later op>=target also calls back once. Callback asserts base Connected/public CatchingUp, commits public Connected then notifies. Disconnect disposes/clears monitor before notifying. Catch-up target does not move with subsequent incoming ops. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:245-328`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:662-681`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/catchUpMonitor.ts:30-94`)
5. Disconnect clears connection, ignores repeated same-state request except telemetry; commits Disconnected; stops join timer; starts old-client leave timer iff old ID is in quorum AND hasPendingOps AND no leave timer already active; notifies **before** clearing pendingClientId. Retains old clientId for reconnect correlation. Stash initialization also starts leave wait whenever restored old ID remains in quorum, independently of hasPendingOps. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:557-560`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:656-723`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/connectionStateHandler.ts:763-785`)
6. Loaded container propagation: on Connected update main audience self (emits selfChanged), then signal audience self; on CatchingUp update signal audience self only. Notify runtime next: prefer optional setConnectionStatus with exact state payload above; otherwise legacy setConnectionState(Connected&&!readonly,clientId), normally only for Connected/Disconnected. Runtime notification only when loaded and runtime.disposed===false. For intermediate states return; otherwise protocolHandler.setConnectionState(connected,clientId), then host connected/disconnected event. Readonly connected container therefore can emit host connected with canSendOps=false. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:2211-2250`, `reference/fluidframework-3.11.0/packages/loader/container-loader/src/container.ts:2570-2648`)

### Audience mutations

### Delta queue scheduling and op boundaries

Queue starts pauseCount=1, no error/processing promise. push appends, emits push, then ensures processing; synchronous failure emits error. resume asserts pauseCount>0 (0x0f4), decrements, ensures processing. pause increments immediately then awaits current processing completion. Processing starts only when nonempty, pauseCount=0, no error and no processing promise; schedule a Promise microtask, never worker inline on push/resume. Each iteration shifts first, increments count, calls worker synchronously, emits queue op; repeat until paused/empty/error. If empty emit idle(count,duration) before returning result. Clear processingPromise synchronously at end of that reaction, **not finally microtask**. On exception cache error, clear promise, emit error, resolve run with zeros if error listener returns; cached error permanently suppresses future processing. clear() empties the deque but does not clear the cached error or pause count. Worker exception loses already-shifted item, with no queue op for it. idle getter requires empty AND no processing promise, so an idle-event listener still sees idle=false. Concrete dispose() throws `Not implemented.` before setting disposed; do not infer functional cleanup from IDisposable declaration. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/deltaQueue.ts:23-176`)

Delta manager submit: build partial in order contents,metadata,referenceSequenceNumber(explicit or last processed),type,compression; unbatched flushes prior buffer; prepare message (undefined→return -1); assert client message; count contents.length (UTF-16 units); append buffer; increment noop count if applicable; emit submitOp; unbatched flush again; return client sequence. flush empty does nothing; otherwise detach buffer into local batch and replace with [] **before** prepareSend(batch), so reentrant submissions initially enter a new buffer. After prepareSend require a single message to have metadata.batch===undefined (0x3c9), or a multi-message batch to start with true (0x3ca) and end with false (0x3cb). Then sendMessages(batch), then assert new buffer empty (0x3cc): reentrancy is not unconditionally supported. (`reference/fluidframework-3.11.0/packages/loader/container-loader/src/deltaManager.ts:306-381`)

Inbound op processing: assert not processing, mark processing, store lastMessage; require clientId null|string and client messages except noop have string clientId. For own client, decrement noop accounting for noop and client sequence gap; negative count throws, else update last client sequence. Call connectionManager.beforeProcessingIncomingOp; reject decreasing MSN; reject sequence<MSN or sequence===MSN with nonnull clientId. Set MSN, require sequence=lastProcessed+1, then set lastProcessed; assert <=lastObserved. Require handler, call handler.process synchronously, clear processing flag, emit delta-manager op(message,Date.now elapsed). The handler computes local=(container.clientId===message.clientId), processes protocol first, runtime.process second, then stores processed op; active connections update noop heuristic and may submit an immediate Accept; emit container op last. Therefore container op precedes delta-manager op, which precedes queue op. No rollback of fields already assigned when processing throws.
