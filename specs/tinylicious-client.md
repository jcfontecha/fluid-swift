# tinylicious-client

## 1. Role

Development-service client combining Routerlicious driver, Tinylicious URL/token providers and directory-root fluid-static runtime. Returns `{container,services:{audience}}`; it does not introduce a DDS or snapshot codec. (reference/fluidframework-3.11.0/packages/service-clients/tinylicious-client/src/TinyliciousClient.ts:57-63, reference/fluidframework-3.11.0/packages/service-clients/tinylicious-client/src/TinyliciousClient.ts:160-208.)

## 2. Surface used by other packages

`new TinyliciousClient(properties?)`; props `{connection?:{port?:number,domain?:string,tokenProvider?:ITokenProvider},logger?:ITelemetryBaseLogger}`. `createContainer(schema,oldestSupportedClient)` and `getContainer(id,schema,oldestSupportedClient)` return Promise of `{container:IFluidContainer<schema>,services:TinyliciousContainerServices}`. Tinylicious user/member has string `id,name`; member also has `connections:{id:string,mode:"read"|"write"}[]`. (reference/fluidframework-3.11.0/packages/service-clients/tinylicious-client/src/interfaces.ts:16-109, reference/fluidframework-3.11.0/packages/service-clients/tinylicious-client/src/TinyliciousClient.ts:74-156.)

**Actual option mismatch:** public connection declares `domain`, but constructor forwards connection object directly to InsecureTinyliciousUrlResolver, which reads `endpoint`, not `domain`. Faithful behavior of the declared `domain` option is therefore no endpoint effect; don't silently interpret it as endpoint. Port's intentional API correction would be a separate decision. (reference/fluidframework-3.11.0/packages/service-clients/tinylicious-client/src/interfaces.ts:34-56, reference/fluidframework-3.11.0/packages/service-clients/tinylicious-client/src/TinyliciousClient.ts:59-63, reference/fluidframework-3.11.0/packages/drivers/tinylicious-driver/src/insecureTinyliciousUrlResolver.ts:44-56.)

## 3. Wire and persisted formats

Code details emitted on creation and code-loader results: `{"package":"no-dynamic-package","config":{}}`. Factory always `createDOProviderContainerRuntimeFactory`, so writes `rootDO` package / `rootDOId` alias / `root` directory / `initial-objects-key` entries, even for a tree-only schema. Loader client literal in construction order: `{"details":{"capabilities":{"interactive":true}},"permission":[],"scopes":[],"user":{"id":""},"mode":"write"}`. This empty local user is not token identity. Config default `Fluid.Container.ForceWriteConnection=true`. (reference/fluidframework-3.11.0/packages/service-clients/tinylicious-client/src/TinyliciousClient.ts:93-99, reference/fluidframework-3.11.0/packages/service-clients/tinylicious-client/src/TinyliciousClient.ts:169-205, reference/fluidframework-3.11.0/packages/framework/fluid-static/src/rootDataObject.ts:76-112, reference/fluidframework-3.11.0/packages/framework/fluid-static/src/rootDataObject.ts:158-159.)

Resolver defaults endpoint `http://localhost`, port 7070; parses URL then if explicit port or URL has no port sets port to explicit value or 7070; keeps only origin. `resolve`: replace first `${origin}/` occurrence in request.url with empty string; first slash-separated segment is document ID. Create header `createNew===true`: empty ID becomes `new`, no URI-encoding of chosen ID. Existing: encodeURIComponent(document ID), retain remaining relative path on document URL only. Return object in order `endpoints,id,tokens,type,url`, with endpoints in order `deltaStorageUrl,ordererUrl,storageUrl`. (reference/fluidframework-3.11.0/packages/drivers/tinylicious-driver/src/insecureTinyliciousUrlResolver.ts:19-96, reference/fluidframework-3.11.0/packages/common/driver-definitions/src/urlResolver.ts:76-82.)

Example default create request `{"url":"","headers":{"createNew":true}}` resolves to `{"endpoints":{"deltaStorageUrl":"http://localhost:7070/deltas/tinylicious/new","ordererUrl":"http://localhost:7070","storageUrl":"http://localhost:7070/repos/tinylicious"},"id":"new","tokens":{},"type":"fluid","url":"http://localhost:7070/tinylicious/new"}`. Existing `doc/a` yields same storage/orderer endpoints, delta `.../deltas/tinylicious/doc`, id `doc`, URL `.../tinylicious/doc/a`. getAbsoluteUrl strips `${origin}/tinylicious/` from resolvedUrl.url, decodes it, and returns `${documentId}/${relativeUrl}`; it does not produce an HTTP URL. (reference/fluidframework-3.11.0/packages/drivers/tinylicious-driver/src/insecureTinyliciousUrlResolver.ts:59-112, reference/fluidframework-3.11.0/packages/drivers/tinylicious-driver/src/insecureTinyliciousUrlResolver.ts:155-160.)

### Tokens

Provider interface: `fetchOrdererToken(tenantId,documentId?,refresh?)`, `fetchStorageToken(tenantId,documentId,refresh?)` → `{jwt:string,fromCache?:boolean}`; optional `documentPostCreateCallback(documentId,creationToken):Promise<void>` may fail creation if it throws. Default insecure provider always returns `{fromCache:true,jwt:newlySignedToken}` for either request and ignores refresh. Every token call creates a fresh UUID user ID; name is first two UUID segments. Claims insertion order: `documentId,scopes,tenantId,user,iat,exp,ver`; omitted document becomes `""`; default scopes `['doc:read','doc:write','summary:write']`, `iat=Math.round(Date.now()/1000)`, `exp=iat+3600`, `ver='1.0'`. Header JSON `{"alg":"HS256","typ":"JWT"}` signed HS256 with UTF-8 key `12345`; JWT is base64url(header).base64url(payload).signature. (reference/fluidframework-3.11.0/packages/drivers/tinylicious-driver/src/insecureTinyliciousTokenProvider.ts:29-81, reference/fluidframework-3.11.0/packages/drivers/routerlicious-driver/src/tokens.ts:23-97.)

Concrete payload at epoch second 1700000000 for chosen UUID `01234567-89ab-4def-8123-0123456789ab`: `{"documentId":"doc","scopes":["doc:read","doc:write","summary:write"],"tenantId":"tinylicious","user":{"id":"01234567-89ab-4def-8123-0123456789ab","name":"01234567-89ab"},"iat":1700000000,"exp":1700003600,"ver":"1.0"}`. This is the insecure local-service provider, not an Azure credential scheme. (reference/fluidframework-3.11.0/packages/drivers/tinylicious-driver/src/insecureTinyliciousTokenProvider.ts:49-81.)

## 4. Behavior

New: construct loader props → await createDetachedContainer(codeDetails above) → define attach closure → await createFluidContainer → replace wrapper.attach → construct service audience → return. Attach closure: require Detached or throw `Cannot attach container. Container is not in detached state.`; create empty create-new request; await container.attach; require resolvedUrl or throw `Resolved Url not available on attached container`; return resolvedUrl.id. It does not wait for connected or saved events after attach. Existing: loadExistingContainer with `{url:id}` → await createFluidContainer → service audience → return; no attach override is installed. (reference/fluidframework-3.11.0/packages/service-clients/tinylicious-client/src/TinyliciousClient.ts:88-156.)

Audience projection validates user exists and id/name are strings (`0x313`), constructs `{id,name,connections:[]}`. fluid-static groups interactive connections by user ID and appends connection records; memberAdded then membersChanged; memberRemoved then membersChanged uses last cached projection. Reconnect can change connection ID without changing user aggregation when a custom token provider maintains user ID. Default provider does **not** maintain user ID across token fetches. (reference/fluidframework-3.11.0/packages/service-clients/tinylicious-client/src/TinyliciousAudience.ts:18-32, reference/fluidframework-3.11.0/packages/framework/fluid-static/src/serviceAudience.ts:82-165, reference/fluidframework-3.11.0/packages/drivers/tinylicious-driver/src/insecureTinyliciousTokenProvider.ts:55-61.)

## 5. Invariants and asserts

Token-provider errors propagate from driver without this client wrapping them. ## 6. JS-semantics hazards

URL origin drops supplied path/query; URL port normalization and encodeURIComponent differ from generic percent encoding. `Math.round` differs from flooring Unix seconds. Preserve Promise completion vs later connection events; no synthetic connected event at API return. Token `fromCache=true` does not mean user/token reuse. (reference/fluidframework-3.11.0/packages/drivers/tinylicious-driver/src/insecureTinyliciousUrlResolver.ts:48-56, reference/fluidframework-3.11.0/packages/drivers/tinylicious-driver/src/insecureTinyliciousTokenProvider.ts:29-69, reference/fluidframework-3.11.0/packages/service-clients/tinylicious-client/src/TinyliciousClient.ts:104-122.)
