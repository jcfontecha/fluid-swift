# container-runtime-definitions — 3.11.0

## 1. Role

Type-only contract shared by container runtime consumers, summarization observers and container extensions. It extends runtime-definitions rather than implementing a second runtime. The entry point exclusively exports types; Swift should model protocols/value types without manufacturing runtime enum values or schema-validation behavior here. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/index.ts:9-43`

- Extension contracts: `ContainerExtensionStore`, factory, instance/result, host/events, runtime properties, inbound/outbound signal message types and JoinedStatus. `ContainerExtensionId` and `ExtensionCompatibilityDetails` are reexports from runtime-definitions. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/index.ts:9-32`

### Complete extension boundary

These are in-process protocols; they have no independent field serialization order. `ExtensionCompatibilityDetails` has required `generation:number`, `version:string` (semver), `capabilities:ReadonlySet<string>`. Instantiation is a mutable record `{compatibility,interface,extension}`; mutation allows custom version adapters. Factory expectations require `hostRequirements:{minSupportedGeneration:number,requiredFeatures:string[]}`, `instanceExpectations:ExtensionCompatibilityDetails`, and `resolvePriorInstantiation(prior)->Readonly<InstantiationResult>`. A typed factory also implements `instantiateExtension(host,...context)->InstantiationResult` and custom identity predicate `Symbol.hasInstance(unknown)->boolean`. `reference/fluidframework-3.11.0/packages/runtime/runtime-definitions/src/containerExtensionProvider.ts:13-66` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:199-206` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:389-417`

`ContainerExtension` requires `handleVersionOrCapabilitiesMismatch(existing,requestedCompatibility)->Readonly<InstantiationResult>` and `onNewUse(...context)->void`; optional `processSignal(addressChain:string[],message:InboundExtensionMessage,local:boolean)->void`. `ContainerExtensionStore.acquireExtension(id,factory,...context)->interface` acquires/injects, while inherited provider `getExtension(id,expectations,...context)` does not permit injection. ContainerExtensionId is a template string `${string}:${string}`; documented no-slash rule has no extra wire brand. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:213-259` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:424-441` `reference/fluidframework-3.11.0/packages/runtime/runtime-definitions/src/containerExtensionProvider.ts:69-104`

Host protocol has `getJoinedStatus()->JoinedStatus`, `getClientId()->string|undefined`, `events`, `logger`, `supportedFeatures:ReadonlySet<string>`, `submitAddressedSignal(addressChain:string[],message)->void`, `getQuorum()->IQuorumClients`, `getAudience()->IAudience`. Events are exactly `disconnected()`; `joined({clientId:string,canWrite:boolean})`; `operabilityChanged(canWrite:boolean)`. Quorum is write membership at processed sequence; audience is faster service membership and may diverge when signals lost. Joined statuses are logical connection states, not persisted document fields. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:262-374`

## 3. Wire and persisted formats

No independent codec, persistence implementation or JSON writer is in this type-only package. Extension signal *payload* shape is typed `{type:string,content:<JSON-serializable>,targetClientId?:string}`; raw inbound adds `clientId:string|null` and uses opaque deserialized content; verified inbound narrows type/content. Container runtime supplies outer `/ext/...` address envelope and transport target; do not serialize TypeScript brands. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:42-67` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:120-173` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1850-1860`

JoinedStatus has exactly three string literals `disconnected`, `joinedForReading`, `joinedForWriting`; they are type aliases, not JS enums. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:262-294`

Summarizer observable records (callback payloads, not persisted summary blobs):

- Common counters: `numUnsummarizedRuntimeOps`, `numUnsummarizedNonRuntimeOps` (numbers). `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerRuntime.ts:116-119`
- `summarize`: `{result:"success"|"failure"|"canceled",currentAttempt,maxAttempts,error?,failureMessage?,isLastSummary?,numUnsummarizedRuntimeOps:number,numUnsummarizedNonRuntimeOps:number}`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerRuntime.ts:96-110` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerRuntime.ts:125-129`
- `summarizeAllAttemptsFailed`: same except omit result. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerRuntime.ts:131-135`
- `summarizerStop`: `{stopReason,error?,numUnsummarizedRuntimeOps:number,numUnsummarizedNonRuntimeOps:number}`; `summarizerStart`: `{onBehalfOf,numUnsummarizedRuntimeOps:number,numUnsummarizedNonRuntimeOps:number}`; `summarizerStartupFailed`: `{reason,numUnsummarizedRuntimeOps:number,numUnsummarizedNonRuntimeOps:number}`; `summarizeTimeout`: `{timeoutCount,currentSummarizeStep,numUnsummarizedRuntimeOps:number,numUnsummarizedNonRuntimeOps:number}`. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerRuntime.ts:137-161`

Stop reason literals are `failToSummarize`, `parentNotConnected`, `notElectedParent`, `notElectedClient`, `summarizerClientDisconnected`, `summarizerException`, `latestSummaryStateStale`. These strings are cross-component observations, not new wire op types. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerRuntime.ts:58-90`

### Concrete observable payloads

A successful summarize callback can receive `{"result":"success","currentAttempt":1,"maxAttempts":2,"numUnsummarizedRuntimeOps":0,"numUnsummarizedNonRuntimeOps":1}`. A failure can additionally carry opaque `error` and `failureMessage`; do not serialize Error as though it were the protocol error JSON. A host joined callback example is `{"clientId":"c","canWrite":false}` followed later by `operabilityChanged(true)`. These examples describe legal callback values, not wire ops or promise rejection shapes. All observer fields/case literals above retain their required/optional distinction. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerRuntime.ts:96-161` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:304-315`

Extension targetClientId is allowed only with loader supported feature `submit_signals_v2`; its support is a transport capability, not document-schema `opGroupingEnabled` or ID-compressor mode. Incoming unknown content stays unverified until extension narrows it; the type brand itself is erased. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:42-67` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:109-173`

## 4. Behavior

This package has no executable implementations. The following are the concrete runtime behaviors a conforming Swift implementation must expose (citations deliberately point to executable consumer, not comments):

1. `getAbsoluteUrl` throws if driver callback missing, returns undefined unless Attached, otherwise delegates supplied relative URL unchanged. Blob lookup returns undefined while detached, else redirect-map entry. Aggregate dirty includes blob work; successful BlobAttach publishes redirect mappings before clearing aggregate work. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1871-1878` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:500-505` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/blobManager/blobManager.ts:923-931`
2. Extension acquisition is keyed by ID. Check factory hostRequirements against runtime compat before using store. Missing instance invokes instantiateExtension only if injection permitted; stores returned result. Existing instance checks factory-defined instanceof or version/capabilities, delegates mismatch/adaptation, calls onNewUse, returns result.interface. Factory has custom Symbol.hasInstance, not a language constructor test. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5986-6063` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:389-417`
3. Host exposes getJoinedStatus/getClientId, events/logger/supportedFeatures, submitAddressedSignal, quorum and audience getters. Runtime may supply signal audience in preference to quorum-derived audience. Host events adapt newer connection-state notifications; older loader fallback reports joined with canWrite true on connected. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:6010-6025` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5898-5913`
4. Addressed extension signals arrive with address-chain suffix and local flag, invoking optional extension processSignal. General signal messages do not become reliable pending ops. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:1835-1860` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:3860-3865`
5. Summary success observability follows actual proposal broadcast and ack. Generator marks heuristic success and awaits ack refresh before settling final result; callbacks may observe settled submitted/broadcast stages before ack. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summaryGenerator.ts:243-244` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summaryGenerator.ts:292-297` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/summary/summaryDelayLoadedModule/summaryGenerator.ts:339-361`

For an existing extension, a mismatch resolver's returned record is used for this acquisition and its onNewUse/returned interface. The runtime does **not** call `extensions.set` on this path; only first instantiate writes the map. If adaptation must affect future acquisitions, the extension/factory must achieve that through the shared mutable instantiation record. Do not silently add a map replacement in Swift. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:6026-6063`

## 5. Invariants and asserts

No executable asserts exist in this package (exports are type-only). Do not confuse compile-time UnverifiedBrand with runtime validation: inbound data must remain potentially unknown until consumer verifies it. Runtime host incompatibility throws UsageError; missing extension in non-injection acquisition throws Error. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/index.ts:9-43` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:109-137` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:5986-6007`

`ExtensionInstantiationResult` contains both the interface delivered to caller and extension hooks used by runtime, in addition to compatibility from UnknownExtensionInstantiation. Maintain both; a single interface pointer loses the migration/hook contract. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:199-206` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:6026-6063`

## 6. JS-semantics hazards

- `undefined` means unavailable client/storage ID/URL and is distinct from explicit null server signal clientId. Model these separately at JSON boundaries. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerRuntime.ts:181-209` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerRuntime.ts:229` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:129-133`
- `UnverifiedBrand` and conditional/distributive message types have no wire representation; Swift should retain unknown JSON values until extension validates type-specific content. Do not decode arbitrary unknown/future signal types into a closed enum that drops them. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:109-173`
- Factory's custom `Symbol.hasInstance` can express identity across duplicated JS packages; use an explicit equivalent compatibility/identity predicate in Swift, not Swift class inheritance alone. `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:6030-6059` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:415-417`
- `error?:any` need not be a JSON object/string; errors are observer values, not automatically persistable JSON. Optional processSignal is absent behavior, not empty signal handler result. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerRuntime.ts:96-110` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:255-259`
- Factory context is variadic tuple (`...useContext`) and onNewUse receives same spread shape. Preserve argument order and existing-instance callback timing. `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:245` `reference/fluidframework-3.11.0/packages/runtime/container-runtime-definitions/src/containerExtension.ts:406-409` `reference/fluidframework-3.11.0/packages/runtime/container-runtime/src/containerRuntime.ts:6026-6063`
